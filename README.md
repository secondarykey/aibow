# aibow

ローカル LLM を**自分のプログラムの中で直接動かす**、学習用のチャットアプリです。
LLM サーバーに頼らず、モデルの読み込みから1トークンずつの生成、会話の管理、ツール呼び出しまでを Go で自作しながら、
「チャット AI の中で何が起きているか」を1段ずつ確かめていきます。
最終的には「ローカル LLM でバイブコーディングできるエージェント」と「MCP(クライアントとサーバー)」まで進む予定です。

## できること(ステップ 2-3 まで)

- **llama.cpp をプロセスの中で直接動かす**: 外部の LLM サーバー(Ollama など)は使いません。Ollama で `ollama pull` したモデルは、そのファイルを直接読んで使えます
- **思考(reasoning)の表示**: Qwen3.5 の思考を畳んで表示し、思考の ON/OFF も切り替えられます
- **会話の保存**: 会話は SQLite に保存され、複数の会話を切り替えられます。会話ごとにシステムプロンプトや temperature を設定できます
- **長い会話の compact**: 会話の上限を超えたら、古い発言を捨てる(truncate)か、モデル自身に要約させる(summary)かで収めます
- **ツール呼び出し(エージェントループ)**: モデルが `<tool_call>` を書いたら aibow が実行し、結果を渡して続きを書かせます。今は現在時刻・計算と、作業フォルダのファイルを並べる・読むツールがあります
- **中身が見える**: モデルに実際に渡した文字列、トークン数、KV キャッシュの再利用数、生成速度などを画面とログで確かめられます

## しくみ

```
ウィンドウ(React)⇄ Wails v3 ⇄ aibow(Go)⇄ yzma ⇄ llama.cpp(DLL)⇄ GPU
                                  ⇅                    ↑
                          会話の保存(SQLite)   GGUF のモデル / Ollama が保存したモデル
```

- **言語**: Go(C コンパイラ不要。`CGO_ENABLED=0` でビルドできる)
- **LLM**: [llama.cpp](https://github.com/ggml-org/llama.cpp) を [yzma](https://github.com/hybridgroup/yzma) で Go から直接呼ぶ。主に使うモデルは Qwen3.5(4B / 9B)
- **画面**: [Wails v3](https://v3.wails.io/) のデスクトップアプリ(React + TypeScript)
- **保存**: SQLite([modernc.org/sqlite](https://pkg.go.dev/modernc.org/sqlite))
- チャットテンプレートやエージェントループなど、学習の対象になる仕組みはライブラリに任せず自分で書いています

## 動かしてみる

Windows + NVIDIA GPU を前提にしています。Go 1.27 以上・Node.js 20.19 以上・Wails の CLI(`wails3`)が必要です。

```bash
cd _cmd/aibow
go run github.com/hybridgroup/yzma@v1.29.1 install --lib lib --processor cuda
```
llama.cpp の DLL を `lib\` にダウンロードします(最初の1回だけ)。モデルは `ollama pull qwen3.5:4b` で用意するか、GGUF を `models\` に置きます。

```bash
wails3 dev
```
アプリを開発モードで起動します。詳しい手順・うまく動かないとき・実行ファイルの作り方は [_docs/setup.md](_docs/setup.md) にあります。

## ロードマップ

| ステップ | 作るもの | 学べること |
|---|---|---|
| 1. チャット ✅ | llama.cpp を直接動かすチャット | トークン化、生成ループ、サンプリング、チャットテンプレート、思考の仕組み |
| 2-1. 会話の保存 ✅ | 会話を SQLite に保存。会話は複数 | モデルは何も覚えておらず、「記憶」はアプリが管理していること |
| 2-2. compact | 長い会話を、古い発言を捨てる・要約するで収める | コンテキスト長の限界との付き合い方 |
| 2-3. ツール呼び出し ✅ | 現在時刻・計算のツールと、エージェントループ | ツール呼び出しの正体が「決まった書式の文字列」であること |
| 3. ミニコーディングエージェント | ファイル読み書き・コマンド実行のツール(実行前に確認) | バイブコーディングツールの中身。安全策の必要性 |
| 4. MCP クライアント | ステップ3のツールを MCP サーバー経由に置き換える | MCP が「ツールの差し込み口の共通規格」であること |
| 5. MCP サーバー自作 | Go で MCP サーバーを作る | 同じサーバーを aibow と Claude Desktop の両方から使える |
| 6. 既製ツールとの比較 | OpenAI 互換 API の口を作り、Cline などからつなぐ | 既製ツールが裏でやっていること |

2-2 は作ってあり、実際のモデルで2つの方式を比べる作業が残っています。進み具合の詳細は [TODO.md](TODO.md) にあります。
