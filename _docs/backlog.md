## KV キャッシュの使い回しを良くする

関係する資料:`_docs/tuning.md` の「Cline からつないで比べる」「ファイルを読むツール」

KV キャッシュの使い回しを良くする(2026-10-19、6-3 で見つけた。ユーザーと「記録だけして後で」と決めた):ツールのループの途中で前回の分を使い回せず、全部を読み直すことがある。原因は2つ。(1) **Cline が arguments の JSON を書き直して空白を詰める**(`["a", "b"]` → `["a","b"]`)ので、aibow-api が書式に戻した文字がモデルの書いた文字と変わる。案:aibow-api が返した呼び出しを id ごとに覚えておき(最近の数百件)、履歴で戻ってきたら値が同じかを確かめて、モデルが書いた元の文字を使う(ステートレスの API に、速さのためだけの小さな状態を持つことになる)。(2) **トークンの分け方**:同じ文字列でも、生成したトークンの並びとトークンにし直した並びが違う(画面のアプリでも起きる)。案:前回のトークン列を文字列に戻し、新しいプロンプトがその文字列で始まるなら、その部分は前回のトークンをそのまま使う(エンジンの変更)。今は読み直しが 6,000 トークンで 2〜3 秒なので困ってはいない

## 会話の作業フォルダを PC ごとにする(aibow-server につないで、ほかの PC から同じ会話を開いたとき)

会話の作業フォルダを PC ごとにする(2026-10-29、ユーザーが気づいた。0019 の A14 を Linux の端末で試したとき):aibow-server につないでいると、会話の設定(作業フォルダの `work_dir` も)は server.db に置かれる。
そのため、PC A で作業フォルダを決めた会話を、同じ人が PC B から開くと、PC A のパスがそのまま残っている。作業フォルダは「その PC のパス」なので、ほかの PC では意味が無い。
**困ること**:PC B に同じパスが無ければツールが失敗するだけだが、たまたま同じパスがあると、PC B の別のフォルダを読み書きしてしまう(ツールはアプリの PC で動くため)。
**今ある手当て**:ほかの人に共有した会話を読む・写すときは、作業フォルダを渡さない(0018。持ち主の PC のパスなので)。プロファイルにも作業フォルダは入れない(0014 の決定事項)。同じ人がほかの PC から開くときだけ手当てが無い。
**案**(決めていない):(1) 作業フォルダを会話の DB に置かず、その PC の手元のファイル(`tools.json` と同じ「画面で変えるが、その PC の人が決めること」。会話の ID → パス)に置く。
(2) 会話の DB に、どの PC で決めたか(0019 のトークンと同じ PC の名前)も置き、ほかの PC では作業フォルダが無いものとして扱う(決め直すまで作業フォルダのツールは出さない)。
(3) ほかの PC で開いたら、そのことを出して、その PC の作業フォルダを決め直すよう促す。(1) は aibow-server につながない形(手元の aibow.db)でも同じ置き場所になる。どれも、作業フォルダごとに起動する MCP のサーバー(0006)の扱いも合わせて考える
