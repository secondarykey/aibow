## KV キャッシュの使い回しを良くする

2026-10-19、6-3 で見つけた(ユーザーと「記録だけして後で」と決めた)。関係する資料:`_docs/tuning.md` の「Cline からつないで比べる」「ファイルを読むツール」。

ツールのループの途中で前回の分を使い回せず、全部を読み直すことがある。原因は2つ。

1. **Cline が arguments の JSON を書き直して空白を詰める**(`["a", "b"]` → `["a","b"]`)ので、aibow-server が書式に戻した文字がモデルの書いた文字と変わる。
   案:返した呼び出しを id ごとに覚えておき(最近の数百件)、履歴で戻ってきたら値が同じかを確かめて、モデルが書いた元の文字を使う(ステートレスの API に、速さのためだけの小さな状態を持つことになる)
2. **トークンの分け方**:同じ文字列でも、生成したトークンの並びとトークンにし直した並びが違う(画面のアプリでも起きる。Granite 4.1 で日本語の引数でも見えた)。
   案:前回のトークン列を文字列に戻し、新しいプロンプトがその文字列で始まるなら、その部分は前回のトークンをそのまま使う(エンジンの変更)

今は読み直しが 6,000 トークンで 2〜3 秒なので困ってはいない

## aibow-server の起動のときのモデル(指定が無いとき・見つからないとき)

2026-11-21、0051 の作業のあとにユーザーが気づいた。指定(`-model`・`server.json` の `model`・`AIBOW_MODEL`)が無いとき、
aibow-server は「一覧の先頭のうち、書式に対応している最初のモデル」で起動する。一覧の並びは置き場所の順(models フォルダ → Ollama → 足した置き場所)と、
その中の名前の順(GGUF はファイル名、Ollama は名前)で、意味のある順ではない(models フォルダに gemma の GGUF を置くと、Ollama の qwen3.5:4b より先になる)。
0051 で入れた「指定したモデルが見つからないときは、使える最初のモデルで起動する」も、この並びに頼っている。

今の選ばれ方:

| | 指定が無いとき | 指定が見つからないとき |
|---|---|---|
| アプリモード | `AIBOW_MODEL` > 最後に使ったモデル(DB の `SettingLastModel`) > 一覧の先頭 | — |
| aibow-server | 手で書いた指定 > 一覧の先頭(最後に使ったモデルは覚えていない) | 一覧の先頭(0051) |

案(どちらか、または両方。まだ決めていない):

- **案 A:最後に読み込んだモデルを覚える**(Code のおすすめ):aibow-server が `server-models.json` に最後に読み込んだモデルを書き、
  「手で書いた指定 > 最後に読み込んだモデル > 一覧の先頭」の順にする(アプリモードと同じ考え方)。管理者がモデルのタブで「読み込み」を押せば、次の起動もそのモデルになる。
  新しい画面も操作も要らない。手で書いた値が強い、の決まりのまま。見つからないときの代わりも、まず最後に読み込んだモデルにする。
  弱いところ:リクエストの `model` でほかのモデルに読み替えられると(Cline などが別のモデルを頼む)、最後のモデルもそれに変わる。「いつもこれで起動したい」は表せない
- **案 B:既定の印**:モデルのタブで、管理者が1つに既定の印を付ける(`server-models.json` に書く)。指定が無いとき・見つからないときは、印のモデルで起動する。
  並べ替え(表示順を管理者が決める)より軽い。「いつもこれで起動したい」を明示できる。
  決めること:手で書いた指定(`server.json` の `model`)と画面の印のどちらを強くするか(今の決まりなら手で書いたほうが強く、画面には「server.json の model が強い」と出す)・
  印のモデルを管理者が使えないようにした・消えたときの扱い・案 A と両方入れるときの順(手で書いた指定 > 印 > 最後に読み込んだ > 一覧の先頭、など)・
  アプリモードのモデルのタブにも付けるか(アプリモードは最後に使ったモデルで足りているか)
- 並べ替え(表示順を決める):起動のモデルを決めるだけなら、案 A か B で足りる見込み。一覧を見やすくしたい要望が出たら別に考える

関係するところ:0051 の決定事項 1(見つからないときに止めない)・0018 の決定事項 13(管理者が使えないようにしたモデル)・[usage.md](usage.md) の `-model` の説明
