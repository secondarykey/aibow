# Chat での相談の進め方(新しいセッションの引き継ぎ用)

aibow は、**Chat(claude.ai)で相談して仕様を決め、Claude Code で実装する**分担で進めている。
Chat のセッションは章(ロードマップの1ステップ・1機能)ごとに新しく始める。長いセッションは、返事のたびに全文を読み直すので重くなるため。
このファイルは、新しい Chat のセッションが最初に読んで、続きから相談できるようにするためのもの。

## 最初に読むもの

1. `AGENTS.md`:目的・構成・技術方針・ユーザーとのやり取りのルール(Code 向けだが、方針はここが正)
2. `TODO.md`:全体の進み具合と、次にやること
3. `_docs/features/`:機能ごとの仕様。作業中・次に着手するものを読む
4. 必要に応じて `_docs/` の仕組みごとの説明(`engine.md`・`conversations.md`・`compact.md` など)

リポジトリはユーザーの PC の `D:\Go\Projects\aibow`(bash では `/d/Go/Projects/aibow`)。Chat からはリンクしたコンピューターのフォルダとして読む。
全部を一度に読まず、相談に必要なところだけ読む(読んだ量だけセッションが重くなる)。

## Chat の役割

- 相談・設計・仕様書き。コードの実装は Code が行う(Chat はコードを書き換えない)
- 決まったことを `_docs/features/<番号>-<名前>.md` に書く。Code はそれを「発注書」として実装する
- `TODO.md` の該当行を、仕様へのリンクに差し替える
- コミットはしない(ユーザーか Code が行う)。書いたら「未コミット」と伝える

## 仕様の書き方

- 番号は `_docs/features/` の連番(使われている最大の番号 + 1)
- 見出し:状態 / ロードマップ / 決めた日 / 前提 → 目的(学ぶこと) → 決定事項 → やらないこと → 未決事項 → 完了の条件 → 作業の順番
- **ユーザーと決めたこと**と、**話の流れから Chat が決めて書いたこと**を分け、後者は返事で列挙して確認してもらう
- 画面の見た目など、実際に見ないと決めにくいものは「未決事項」にして、Code が案を示してユーザーに確認する
- ロードマップの外の思いつきは、`TODO.md` の「ロードマップの外でやりたいこと」に書く

## 相談の進め方(ユーザーの好み)

- 日本語で。新しい概念は短く説明し、aibow で学んだこと(ステートレス・KV キャッシュ・compact など)にたとえると伝わりやすい
- 決めることは「選択肢 + おすすめ + 理由」で示す。一度に聞くのは数点まで
- コマンドは、何をするものかを必ず添える。シェルは bash(Git Bash)
- 事実(ライブラリの版・仕様・ライセンスなど)は推測で書かず、調べてから書く。調べられなかったことは「未確認」と書く
- 大事な方針(AGENTS.md より抜粋。詳しくは AGENTS.md):
  - Ollama などの LLM サーバーは使わない。aibow の中で llama.cpp(yzma 経由)を直接動かす。ただし Ollama を「モデルの管理係」として使い、保存されたファイルを直接読むのは OK
  - Go の外部パッケージは最小限(追加は確認してから)。cgo なし(`CGO_ENABLED=0`)でビルドできる状態を保つ
  - 完成を急ぐより、仕組みが読んで分かることを優先する

## 新しいセッションの始め方(ユーザー用)

新しい Chat に、たとえば次のように書く。

> aibow(`/d/Go/Projects/aibow`)の続きを相談したいです。`_docs/chat-guide.md` を読んで、そこに書いてある順に必要なファイルを読んでから、次にやること(TODO.md)を整理してください。
