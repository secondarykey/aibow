# 画面(UI)

`_cmd/aibow/frontend/src/` のチャット画面(React + TypeScript)の説明です。
Go とのやり取り(バインディング・イベント・停止)とアプリの起動は [_cmd/aibow/AGENTS.md](../_cmd/aibow/AGENTS.md) にあります。

## レイアウト

- 左: 会話の一覧。ウィンドウの上から下まで。上のハンバーガーで開閉し、閉じるとアイコンだけの細い列になる。
  「+ 新規」は一覧の一番上の行(スクロールしても隠れない)。開いているときも閉じたときも同じアイコン(`LuPlus`)を使い、開いているときだけ文字を添える(設定と同じ)。
  右の仕切り(`Splitter.tsx`)で幅を変えられ、幅は localStorage に覚える
- 右上: タイトルバー(`TitleBar.tsx`)。Frameless のため自前で作る。開いている会話の名前と、右端に最小化・最大化・閉じる。
  一覧の上の空いているところと合わせてドラッグで移動できる
- 中央: チャット
  - ユーザーの発言の下に、右寄せで「時刻 コピー」(時刻は保存した時刻。送信直後は user イベントで付く)
  - 返事の最後にコピー(アイコンだけ)・返事の時刻・「詳細」(統計行。ふだんは畳む)。
    時刻は返事を保存した時刻(= 書き終えた時刻。`created_at`)。今からどれくらい前か(「たった今」「3分前」「2時間前」「4日前」)で出し、
    5日以上前は日時(「2025/10/12 14:05」)で出す。マウスを乗せると実際の時刻を秒まで出す。開いたままでも進むよう、30 秒ごとに描き直す。
    発言の時刻も同じ決まり(`ChatView.tsx` の `MessageTime`)
  - コードブロックの右上に、そのコードだけのコピー(`CopyButton.tsx`)
  - 入力欄の下にモデルの選択、右端に「今すぐ要約」とメーター(`Meter.tsx`)
  - 停止ボタンは、生成中の返事の吹き出しの中(右下)に出す。赤い停止のアイコン(`LuCircleStop`)だけで、何を止めるか(停止 / 要約を停止)はマウスを乗せると出る
- 設定の画面(`SettingsView.tsx`): 一覧の下の「設定」で開閉する。別の画面として扱い、チャットの代わりに会話の場所に出す。
  一覧で会話を選ぶ・「+ 新規」でも閉じる。入力欄の打ちかけの文は App が持つので消えない
- ウィンドウは起動時 720×820、最小 480×480(`main.go`)

## ファイルの分け方

- `useModels.ts` / `useConversations.ts` / `useChat.ts` / `useAppSettings.ts` が Go とのやり取り
- `components/` が表示
- `stickToBottom.ts` が「一番下にいるときだけ追いかける」スクロール
- `App.tsx` が全体をまとめる

## 返事の表示(Markdown)

返事の本文と要約の文は `RenderedText.tsx` で Markdown として表示する。ユーザーの発言と思考の箱は文字のまま。

- Markdown の解析は学習の対象ではないので、marked に任せる(設定は `markdown.ts`)。`breaks: true` で1つの改行も改行にする
- 文をブロックに分け(`lexer`)、コードブロックだけは React で出す(`CodeBlock.tsx`)。残りは続いている分をまとめて marked で HTML にする
  - 箇条書きの中のコードブロックは marked がそのまま HTML にするので、コピーボタン・色付け・図は付かない
- モデルの出力は信用できない入力として扱う。`markdown.ts` で marked の出力を差し替えている
  - 文章の中の HTML はタグとして解釈させず、文字として見せる
  - リンクは http / https だけを `<a>` にする。それ以外(`javascript:`・相対パスなど)は文字にする
  - 画像は読み込まない(外のサーバーに取りに行かない)。http / https ならリンクとして出す
- リンクを押したら `Browser.OpenURL` で OS のふだんのブラウザで開く。ウィンドウの中で開くと画面がそのページに移り、チャットに戻れなくなるため
- 生成中は届くたびに全体を解析し直す。閉じていない書式(`**生成` など)は、閉じる記号が届くまで記号のまま見える
- 見た目は `style.css` の `.md`。吹き出しの中なので見出しを小さく・余白を詰め、色はテーマの変数から取る(ダークテーマでもそのまま合う)

### コードブロック(色付けと mermaid の図)

- 右上にそのコードだけをコピーするボタン(`CopyButton.tsx`)
- 言語が書かれていれば highlight.js で色を付ける(`highlight.ts`。よく使う 37 言語の `lib/common`)。
  言語が無い・知らない言語のときは色を付けない(言語の推測は遅く、よく外れるので使わない)。色は `style.css` の `--hl-*`(GitHub の配色が元)
- 言語が `mermaid` なら図にする(`mermaid.ts`)。図とコードはコードのアイコン(`LuCode`)のトグルで切り替え、押している間はアクセントの色になる。コピーは元のコード
  - 図にするのは閉じる記号(```)が届いてから(生成中は途中のコードで、描くとエラーになる)。それまでと、書き間違いのときはコードのまま見せ、エラーの文を添える
  - 配色は OS のライト / ダークに合わせる(`usePrefersDark`)。mermaid は設定を全体で1つ持つので、描く処理は1つずつ順番に行う
  - モデルが書いた図は信用できない入力として扱う。`securityLevel: "strict"`(クリックの動作を止める)と `htmlLabels: false`(ラベルを SVG の文字で描く)。
    strict だけだとラベルの `<img>` が残り、外の URL の画像を取りに行くことを確かめている。
    `htmlLabels: false` には、`npm audit` で出る katex の問題を実行させない役目もある([known-issues.md](known-issues.md))
- highlight.js と mermaid は、最初に必要になったときに読み込む(起動時の JS は増やさない)。
  2026-10-12 に測った値: mermaid は exe の中で約 5MB、アプリを起動して最初の図は約 0.6 秒、2回目からは約 0.1 秒。highlight.js は約 150KB

## 新しい会話の画面

- 起動時と「+ 新規」は新しい会話の画面(`NewChat.tsx`、入力欄が真ん中)
- 会話はそこで最初に送信したときに作る(空の会話を作らない)

## お知らせとエラー

- モデルの読み込み・設定の変更などのお知らせは、会話の表示ではなく右上のトースト(`toast.tsx`)に出す
- 時間のかかる処理は出したままにし、同じ key で置き換える
- エラーは会話の表示に出す

## フォーカス

- 入力欄へ自動でフォーカスを移すとき(会話を開いた・「+ 新規」・返事が終わった)は、ほかの入力欄で打っている最中なら移さない(`Composer.tsx` の `focusUnlessTyping`)。
  会話の名前の変更(一覧のダブルクリック)の入力欄からフォーカスを奪って、編集が閉じてしまったため

## スクロール

- 生成中に届く断片で一番下へ送るのは、一番下にいるときだけ(`useStickToBottom`。チャット・思考の箱・要約中の箱)。上にスクロールして読んでいる間は送らない
- 「一番下にいたか」は scroll イベントではなく描画のたびのスクロール位置で決める(イベントは次のフレームに届くので、数ミリ秒ごとの断片に間に合わない)
- スクロールバーは `::-webkit-scrollbar` でつまみだけのフラットな形にし、色はテーマの `--scrollbar` / `--scrollbar-hover`。
  標準の `scrollbar-color` は使わない(指定すると Chromium は `::-webkit-scrollbar` を無視する)

## ウィンドウの移動とリサイズ(Frameless)

- ドラッグできる場所は CSS の `--wails-draggable: drag`(`.titlebar`)、ボタンは `no-drag`
- `main.tsx` で `@wailsio/runtime` を import しておく(ドラッグとリサイズはランタイムがページ全体のマウス操作を見て行う)
- リサイズの判定はマウスの座標だけで行われるので、ルート要素に余白は要らない(wails3 スキルの「5px の余白が必須」は beta.26 では不要)
- ただし、ウィンドウの端に接してスクロールする要素(`.chat` / `.settings-view`)は、スクロールバーが端の数 px(Windows の SM_CXSIZEFRAME)の
  マウスを受け取ってリサイズできなくなる(ランタイムがずらすのはページ全体のスクロールバーだけ)。
  透明な枠線 `border-right: var(--edge-gap) solid transparent` でスクロールバーを内側に寄せる。**端に接してスクロールする要素を足したら同じようにする**

## IME(日本語入力)が効かなくなる問題

- Windows の WebView2 は、別のウィンドウから戻ると IME が効かなくなることがある
- Go が `events.Windows.WindowSetFocus` で `aibow:window:focus` を送り、画面の `imeFocus.tsx` が見えない input を経由して入力欄にフォーカスを付け直す(同じ要素への blur → focus では直らない)
- IME 変換中・ボタンにフォーカスがあるときは触らない
- 新しい入力欄を足しても、テキスト入力なら自動で対象になる
