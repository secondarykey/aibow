# 画面(UI)

`_cmd/aibow/frontend/src/` のチャット画面(React + TypeScript)の配置と操作の説明です。

- 返事の表示(Markdown・コードの色付け・mermaid の図と書き出し): [rendering.md](rendering.md)
- Go とのやり取り(バインディング・イベント・停止)とアプリの起動: [_cmd/aibow/AGENTS.md](../_cmd/aibow/AGENTS.md)

## ファイルの分け方

| ファイル | 役割 |
|---|---|
| `App.tsx` | 画面全体をまとめる。一覧の開閉(狭いウィンドウでは重ねて出す)、会話の場所に出すもの(チャット / 新しい会話 / 設定) |
| `useModels.ts` / `useConversations.ts` / `useChat.ts` / `useAppSettings.ts` | Go とのやり取り |
| `transcript.ts` | 会話の表示(吹き出し・ツールのカード・エラー・区切り)の持ち方。保存された発言から表示を作る |
| `components/` | 表示。`ConversationList` / `Splitter` / `TitleBar` / `ChatView` / `ToolCard` / `Composer` / `ModelBar` / `Meter` / `NewChat` / `SettingsView` / `CopyButton` など。返事の中身は [rendering.md](rendering.md) |
| `mediaQuery.ts` | 画面の幅・OS のライト / ダークを見る(`useMediaQuery`。狭いウィンドウの境目 `NARROW_QUERY`) |
| `stickToBottom.ts` | 「一番下にいるときだけ追いかける」スクロール |
| `toast.tsx` / `imeFocus.tsx` / `errors.ts` | トースト / IME の付け直し / Go のエラーの文の取り出し |

## 配置

- 左: 会話の一覧([下](#会話の一覧))
- 右上: タイトルバー(`TitleBar.tsx`)。Frameless のため自前で作る。開いている会話の名前と、右端に最小化・最大化・閉じる。
  一覧の上の空いているところと合わせてドラッグで移動できる
- 中央: チャット([下](#チャット))。入力欄の下にモデルの選択、右端に「今すぐ要約」とメーター(`Meter.tsx`)
- 設定の画面(`SettingsView.tsx`): 一覧の下の「設定」で開閉する。別の画面として扱い、チャットの代わりに会話の場所に出す。
  一覧で会話を選ぶ・「+ 新規」でも閉じる。入力欄の打ちかけの文は App が持つので消えない
- ウィンドウは起動時 720×820、最小 480×480(`main.go`)

## 会話の一覧

- ウィンドウの上から下まで。上のハンバーガーで開閉し、閉じるとアイコンだけの細い列になる
- 「+ 新規」は一覧の一番上の行(スクロールしても隠れない)。開いているときも閉じたときも同じアイコン(`LuPlus`)を使い、開いているときだけ文字を添える(設定と同じ)
- 右の仕切り(`Splitter.tsx`)で幅を変えられ、幅は localStorage に覚える
- ウィンドウが狭い(640px 以下)ときは、一覧を開くと会話を押しのけず、会話の上に重ねて出す(`App.tsx` の overlay。後ろの会話には影)
  - 影を押す・Esc・会話を選ぶ・「+ 新規」・「設定」で閉じる
  - 狭くなったときに一覧が開いていたら自動で閉じ、狭いウィンドウで起動したときは閉じた状態から始める
  - 重ねて出している間は仕切りを出さない(幅は広いときに変える)
  - 影はタイトルバーにもかかるので、重ねて出している間に右上のボタンを押すと、最初の1回は一覧が閉じるだけ

## チャット

- ユーザーの発言の下に、右寄せで「時刻 コピー」
- 返事の最後に「コピー 時刻 詳細」。「詳細」は統計行(モデル名・速さ・トークン数)で、ふだんは畳む。生成中は出さない
- 時刻(`ChatView.tsx` の `MessageTime`。発言と返事で共通)
  - 保存した時刻(`created_at`)。返事は書き終えて保存した時刻、送信した発言は保存されたときの user イベントで付く
  - 今からどれくらい前か(「たった今」「3分前」「2時間前」「4日前」)で出し、5日以上前は日時(「2025/10/12 14:05」)で出す
  - マウスを乗せると実際の時刻を秒まで出す。開いたままでも進むよう、30 秒ごとに描き直す
- 停止ボタンは、生成中の返事の吹き出しの中(右下)に出す。赤い停止のアイコン(`LuCircleStop`)だけで、何を止めるか(停止 / 要約を停止)はマウスを乗せると出る
- 返事の本文と要約の文の表示は [rendering.md](rendering.md)

### ツールのカード

- 1回の送信の返事は吹き出し1つ。ツールを使った送信は、その中に「思考 → 答え → カード → 思考 → 答え …」と生成した順に並べる(`AssistantView.steps` がツールを呼んだ回)
- 最後の答えより前(各回の思考・途中の答え・カード・最後の回の思考)は、1つの枠(`Process`)にまとめて畳む。中の表示は枠が無いときと同じ。
  見出しは「思考の過程(N秒)」で、N は送信から答えを書き始めるまでの時間(思考が無ければ「ツールの使用(N秒)」)。
  生成中は最初の回のプロンプトを渡した時刻から数え(「思考中… N秒」)、保存後は記録から足し直す(`processLabel`。回の間のわずかな時間は入らない)。
  1回目の生成の間はツールを呼ぶか分からないので、ふつうの「思考の過程」で出し、ツールを呼んだ時点で枠に変わる
- カード(`ToolCard.tsx`)は「思考の過程」と同じく畳んだ1行: レンチのアイコン・ツールの名前・状態(実行中… / ✓ 秒数 / ✕ エラー)。開くと引数と結果、読み取れなかった呼び出しはモデルが書いたまま
- ツールの名前にマウスを乗せると日本語の説明を出す(モデルに見せる説明は英語)
- モデルが書いた `<tool_call>` の生の文字列は答えの欄に出さない(設定の画面の「モデルに渡した文字列」で見える)
- 統計行は吹き出しの最後に1つで、ループ全体の合計(「N回生成」が付く)。コピーは各回の答えをつなげたもの
- 表示は保存された返事とツールの結果から作る(`turnView`)。生成中も `reply` / `tool_result` イベントで届いた保存済みの発言から作り直すので、再起動して開き直しても同じ並びになる
- 生成中にその会話を開き直したときは、生成中の送信で保存済みの発言を、保存された発言の側からは外す(生成中の吹き出しの中に出すため)

## 新しい会話の画面

- 起動時と「+ 新規」は新しい会話の画面(`NewChat.tsx`、入力欄が真ん中)
- 会話はそこで最初に送信したときに作る(空の会話を作らない)

## お知らせとエラー

- モデルの読み込み・設定の変更などのお知らせは、会話の表示ではなく右上のトースト(`toast.tsx`)に出す
- 時間のかかる処理は出したままにし、同じ key で置き換える
- エラーは会話の表示に出す

## フォーカス

- 入力欄へ自動でフォーカスを移すとき(会話を開いた・「+ 新規」・返事が終わった)は、ほかの入力欄で打っている最中なら移さない(`Composer.tsx` の `focusUnlessTyping`)。
  会話の名前の変更(一覧のダブルクリック)の入力欄からフォーカスを奪って、編集が閉じてしまったため

## スクロール

- 生成中に届く断片で一番下へ送るのは、一番下にいるときだけ(`useStickToBottom`。チャット・思考の箱・要約中の箱)。上にスクロールして読んでいる間は送らない
- 「一番下にいたか」は scroll イベントではなく描画のたびのスクロール位置で決める(イベントは次のフレームに届くので、数ミリ秒ごとの断片に間に合わない)
- スクロールバーは `::-webkit-scrollbar` でつまみだけのフラットな形にし、色はテーマの `--scrollbar` / `--scrollbar-hover`。
  標準の `scrollbar-color` は使わない(指定すると Chromium は `::-webkit-scrollbar` を無視する)

## ウィンドウの移動とリサイズ(Frameless)

- ドラッグできる場所は CSS の `--wails-draggable: drag`(`.titlebar`)、ボタンは `no-drag`
- `main.tsx` で `@wailsio/runtime` を import しておく(ドラッグとリサイズはランタイムがページ全体のマウス操作を見て行う)
- リサイズの判定はマウスの座標だけで行われるので、ルート要素に余白は要らない(wails3 スキルの「5px の余白が必須」は beta.26 では不要)
- ただし、ウィンドウの端に接してスクロールする要素(`.chat` / `.settings-view`)は、スクロールバーが端の数 px(Windows の SM_CXSIZEFRAME)の
  マウスを受け取ってリサイズできなくなる(ランタイムがずらすのはページ全体のスクロールバーだけ)。
  透明な枠線 `border-right: var(--edge-gap) solid transparent` でスクロールバーを内側に寄せる。**端に接してスクロールする要素を足したら同じようにする**

## IME(日本語入力)が効かなくなる問題

- Windows の WebView2 は、別のウィンドウから戻ると IME が効かなくなることがある
- Go が `events.Windows.WindowSetFocus` で `aibow:window:focus` を送り、画面の `imeFocus.tsx` が見えない input を経由して入力欄にフォーカスを付け直す(同じ要素への blur → focus では直らない)
- IME 変換中・ボタンにフォーカスがあるときは触らない
- 新しい入力欄を足しても、テキスト入力なら自動で対象になる
