# 画面(UI)

`_cmd/aibow/frontend/src/` のチャット画面(React + TypeScript)の配置と操作の説明です。

- 返事の表示(Markdown・コードの色付け・mermaid の図と書き出し): [rendering.md](rendering.md)
- Go とのやり取り(バインディング・イベント・停止)とアプリの起動: [_cmd/aibow/AGENTS.md](../_cmd/aibow/AGENTS.md)

## ファイルの分け方

| ファイル | 役割 |
|---|---|
| `App.tsx` | 画面全体をまとめる。一覧の開閉(狭いウィンドウでは重ねて出す)、会話の場所に出すもの(チャット / 新しい会話 / 設定) |
| `useModels.ts` / `useConversations.ts` / `useChat.ts` / `useAppSettings.ts` | Go とのやり取り |
| `transcript.ts` | 会話の表示(吹き出し・ツールのカード・エラー・区切り)の持ち方。保存された発言から表示を作る |
| `components/` | 表示。削除の形は `DeleteButton`(0050。下の「ボタンの言葉と見た目」)。`ConversationList` / `Splitter` / `TitleBar` / `ChatView` / `ToolCard` / `Composer` / `WorkspaceBar` / `WorkspaceSettings` / `ModelBar` / `Meter` / `NewChat` / `SettingsView` / `ConversationSettingsView` / `ConversationSettingsForm` / `ProfileSettings` / `ProfileTools` / `ConversationTools` / `ConfirmChip` / `CopyButton` など。返事の中身は [rendering.md](rendering.md) |
| `stored.ts` | 画面の見た目の好み(一覧の幅・一覧を開いているか・最後に開いていた会話・一覧の並べ方)を localStorage に覚える |
| `conversationGroups.ts` | 会話の一覧の並べ方(新しい順 / ワークスペースごと。0038)。まとめ方の計算と、並べ方・畳んだまとまりを一覧の部品の外に1つだけ持つ係([下](#会話の一覧)) |
| `mediaQuery.ts` | 画面の幅を見る(`useMediaQuery`。狭いウィンドウの境目 `NARROW_QUERY`) |
| `theme.ts` | 画面の明るさ(ライト / ダーク)を決めて `<html data-theme>` に書く([下](#明るさライト--ダーク)) |
| `stickToBottom.ts` | 「一番下にいるときだけ追いかける」スクロール |
| `pinnedQuestion.ts` | スクロールして上に隠れた質問を右上に出す |
| `questionsOnly.ts` | 「質問だけ」の表示(返事を隠して質問を並べ、選んだ質問へ飛ぶ) |
| `attachments.ts` | 入力欄で読み込んだファイル(0030)。読み込むたびに Go の `CheckFile` で確かめ、送るまで持つ([下](#ファイルを読み込む)) |
| `toast.tsx` / `imeFocus.tsx` / `errors.ts` | トースト / IME の付け直し / Go のエラーの文の取り出し |

## 配置

- 左: 会話の一覧([下](#会話の一覧))
- 右上: タイトルバー(`TitleBar.tsx`)。Frameless のため自前で作る。開いている会話の名前と、右端に最小化・最大化・閉じる。
  一覧の上の空いているところと合わせてドラッグで移動できる
- 中央: チャット([下](#チャット))。入力欄の上にワークスペース(`WorkspaceBar.tsx`)、入力欄の下にモデルの選択、右端にメーター(`Meter.tsx`)。
  モデルの選択は「この会話のモデル」(新しい会話の画面では、これから作る会話のモデル)。選ぶと会話のモデルを変えるだけで、読み込むのは送信(作り直す・今すぐ要約も)の前(0014 の「あとから決めたこと(2026-10-31)」。aibow-server 越しでは選んだときに読み込んでも、送信までにほかの人に入れ替えられることがあるため)。
  会話のモデルが読み込んでいるモデルと違う(送信するときに読み直す)ときは、枠を破線にし、吹き出しに書く(`ModelBar.tsx`。0014 の 3)。
  読み込んだモデルの情報(名前・パラメータ数・GPU / CPU・読み込み時間・作業領域・モデルの説明)は、いつも出しておかず、モデルの選択にマウスを乗せたときの吹き出しに出す(2026-10-15、ユーザーの指示)。
  吹き出しの「作業領域」は、開いている会話(新しい会話の画面では、これから作る会話)の大きさ。今確保している作業領域と違えば、今の大きさと「送信時に作り直し」を添える。
  aibow-server につないでいるとき(0015)は、吹き出しに「aibow-server(つなぎ先)で動かしています」を足し、作業領域はサーバーの大きさに「(aibow-server で固定)」を添える(いつも見える印は付けない。ユーザーと決めた)。
  つながらないときは、モデルの選択に「aibow-server につながりません」と出し、理由を吹き出しに出す。エラーのカードはつながらなくなったときに1回だけ出し、
  起動したときの会話と設定の読み込みが同じ理由で失敗しても、カードを重ねて出さない(3枚並んでいた。2026-10-29、ユーザーの指示。つながったら設定と会話の一覧を読み直す。`App.tsx`)。
  起動したときに会話を読めなかったら、最後の会話も開かず、新しい会話の画面の設定も無い(送信できない・プロファイルを選べない)画面のままになる。
  つながったときにまだその画面なら、起動したときと同じく最後の会話を開く(無ければ新しい会話の画面)。一覧だけを読み直すと、「+ 新規」を押すまで送信できなかった(2026-11-24、ユーザーの指摘)。
  その間に会話を開いた・新しい会話の画面に移ったなら、一覧だけを読み直す。
  一覧を取り直したとき(ウィンドウに戻ったとき・返事が終わったとき)につながれば「aibow-server につながりました」をトーストで出す(つなぎ直しのボタンは置かない。`useModels.ts`)。
  送る前に止まったとき(書式に未対応のモデル・会話の上限を超える、など。Go は発言を保存しない)は、送った吹き出しを消して文を入力欄に戻す(その間に打ち始めていたら、そちらを残す)。新しい会話の画面から送ったなら、送る直前に作った空の会話も消し、同じ下書きの新しい会話の画面に戻す(`useChat` の `send`・`useConversations` の `unadopt`)。保存されたように見えて、開き直すと消える、にしないため
  会話の上限・返事の上限の欄の説明も、つないでいるときは「aibow-server の作業領域の中で使います」にする(`ServerContext`)。summary の会話では、メーターのトークン数(「n / 上限」の n)を押すと今すぐ要約する(n を両側から矢印で挟んだボタン →| n |←。マウスを乗せると「要約」。別のボタンは置かない)
- 一覧の下: 左にアプリの名前とバージョン(「AIBow 0.3.1」。バージョンは Go の `_cmd/aibow/version` を `ChatService.Version` で受け取る。`wails3 dev` では「AIBow 0.3.2+dev」。[deploy.md](deploy.md))、右に設定の歯車のアイコン(文字は付けない)
  - デスクトップのアプリがサーバーモードのときだけ、バージョンの後ろにサーバーのアイコン(`LuServer`。0056)。マウスを乗せると「aibow-server: つなぎ先」。
    つながらないときはアイコンを `LuServerOff` にして警告の色(説明は「aibow-server(つなぎ先)につながりません」。理由の全文はエラーのカード)。
    状態は `Models()` の `server` / `server_error` をそのまま使い、ウィンドウに戻ったときなどに取り直したときに変わる。アプリモードとブラウザの画面では出さない。サーバーの版は 0054 で受け取るようになったら説明に足す
- 設定の画面(`SettingsView.tsx`): 一覧の下の歯車のアイコンで開閉する。別の画面として扱い、チャットの代わりに会話の場所に出す。
  一覧で会話を選ぶ・「+ 新規」でも閉じる。入力欄の打ちかけの文は App が持つので消えない。
  中身はタブで分ける(2026-10-19、ユーザーの指示。会話に関わらないアプリの設定と、会話の既定として使われる値を混ぜないため)。開くたびに「基本設定」から。開いている会話には関係しない(0009)
  - 基本設定: 画面(明るさ・「スクロールしたら、質問を右上に出しておく」)。ブラウザでログインしているときは「パスワード」(自分のパスワードを変える。0022)も。
    デスクトップのアプリには「ログ」(「ログのレベル」の選択と、今日のログファイルのパス(コピーのボタン付き。開くボタンは置かない)。このアプリのログだけ。レベルはすぐ効き、保存しない。`LogSettings.tsx`。0052)も
  - モデル(`ModelSettings.tsx`。0015 の 8-4。2026-10-22):下の「モデルのタブ」
  - 会話: プロファイル(名前の付いた新しい会話の既定。0014)・ツール。ツールは、使う / 使わない・確認するかが全部の会話の既定になるので、こちらに置く
  - MCP(`McpEditor.tsx`。デスクトップのアプリだけ。0034):MCP のサーバーの一覧(名前・command か url・つなぎ方・settings.json から移せなかったものは印。起動したときに mcp.json へ移すので、ふだんは出ない)。行を押すと下にフォームを開く(変える・消す・試しにつなぐ)。
    「追加」はフォーム、「JSON を貼る」は貼った JSON を読み取り、1つならフォームに入れ、いくつかなら追加するものを選んでから追加する。settings.json のものは見るだけ(接続テストはできる)。
    env・headers の値は伏せ字(`type=password`)。保存したら、会話で選べるサーバー(この会話のツール)を読み直し、お知らせ(足したものは最初から使わない・止めた)をトーストで出す
  - サーバー(`ServerSettings.tsx`。デスクトップのアプリだけ。0019):今のモード(アプリモード / サーバーモード)と、aibow-server につなぐ(「接続」:つなぎ先を確かめる → 自己署名の証明書ならフィンガープリントを信頼する → そのまま保存。ログインはここでせず、起動し直したあとのログインの画面で。0047)・アプリモードに戻す。
    見出しはアプリモードでは「aibow-server につなぐ」、サーバーモードでは「つなぎ先を変える」。今つないでいるのと同じつなぎ先なら何も変えず「今この aibow-server(…)につないでいます」
    (ログアウトはここではなく「アカウント」のタブと左下の名前のメニュー。0031 の決定事項 44)。
    どちらも保存するだけで、起動し直すと切り替わる(アプリは自分で起動し直さない)。変えたらその場で「起動し直してください」の画面になる(下の「ログイン」の節。0051)。
    信頼できたつなぎ先は、つながなくても覚える(`connection.json` の `known`)。タブを開き直したとき・ログアウトしたあとは、そのつなぎ先を入力欄に入れておき、「接続」で信頼し直さずに進める
    手で書いたつなぎ先(settings.json・環境変数)があれば表示だけ

### モデルのタブ(設定の画面の「モデル」。0015 の 8-4)

ブラウザ(aibow-server)では、設定の画面のモデルのタブはだれにも一覧だけ(`listOnly`)を出し、下の「アプリモードのとき」と同じもの(操作)は、
管理の画面の「モデル」のタブに出す(ログインした管理者と、ログインなしの形の画面。0032 の決定事項 6・0046)。
管理の画面の「モデル」のタブでは、表示だけだった作業領域の欄の代わりに「並列数と作業領域」(`ServerConfig.tsx` の `ServerRunSettings`。0061)を出す:
並列数・作業領域の入力欄と、1本あたりの作業領域(作業領域 ÷ 並列数)。確定式の保存(0053)で、aibow-server の server.json に書く。
起動し直すまで切り替わらないので、保存した値と今動いている値が違えば、今の値と「aibow-server を起動し直すと切り替わります」を出す(起動し直すボタンは無い)。
起動の引数・環境変数で決めている値は入力欄を押せなくし、錠のアイコンの吹き出しに、どこで決めているかを出す。設定ファイルの場所は見出しの横の(i)の吹き出し。
「資料のフォルダ」のタブ(`ServerFolders`。0061。「配布プロファイル」の隣。ログインした管理者だけ):行は名前・パス・使っているプロファイルの数(吹き出しに名前)・パスの変更(鉛筆。行が入力欄になり「適用」「キャンセル」)・削除(ゴミ箱。使っているプロファイルがあれば押せず、吹き出しに理由)。
下に名前とパスの欄と「+ 追加」。足す・変える・消すとすぐ効く(配布プロファイルのタブの資料のフォルダの選択肢は、タブを開いたときに取り直す)

アプリモードのときは、下の全部を出す。変えられるのは**すぐ効く操作だけ**(0015 の 21)。
aibow-server につないでいるときは、**モデルの一覧(名前・書式・大きさ・読み込み中か)と、つなぎ先・作業領域だけ**を出し、何も変えられない(`RemoteModelTable`・`RemoteSettings`)。
読み込み / アンロード・層の数・置き場所・出どころ・サーバーの PC のパスは、サーバーの PC の事情でサーバーの側で決めること(中央の制御)なので、見せも変えもしない(2026-10-22、ユーザーと決めた)。
入力欄の下のモデルの選択も、aibow-server につないでいるときは出どころでまとめない

- モデル: 表の形(名前・書式・出どころ・大きさ・GPU の層・読み込み / アンロード)。列は subgrid でそろえる。読み込み中のモデルは丸の中のチェックと太字
  - 書式は、そのモデルを動かす書式の名前(Qwen3.5・Gemma 4・Llama 3・Granite 4・Granite 4.2。`models.Entry` の `format`。0026 の決定事項 17)。種類(`arch`。GGUF の先頭から読む)と GGUF のチャットテンプレートの印から、Go の `api.FillFormat`(`format.ForModel`)が名前を入れる(0027)。書式に未対応の種類のモデルは「未対応(種類)」を薄く出す(読み込めても送信できない)
  - 出どころは models フォルダ / Ollama / 足した場所(`models.Entry` の `origin`)。足した場所の枠だけ色を付ける
  - 「読み込み」は今のモデルと入れ替える(同時に読み込むのは1つ。0015 の 23。`SwitchModel`)。「アンロード」は VRAM を空ける(`UnloadModel`)
  - GPU の層は、欄を変えてから「適用」を押す(押すまで変えない。読み込み中のモデルなら読み直しになるため)。「適用」は常に出しておき、値が変わっていない間は押せない(出たり消えたりで行の幅が変わらないように。0051)。読み込んでいないモデルは覚えるだけ(`SetModelGPULayers`)。
    以前の基本設定の「GPU に載せる層の数」(読み込み中のモデルの値だけ)はここに移した
  - 生成中・読み込み中は押せない(エンジンが1つのため)
- 置き場所: models フォルダと Ollama は錠(表示だけ。吹き出しに変え方)、足した場所は × で外せる(モデルのファイルは消さない)。見つからない場所は薄く出し、理由を添える(0015 の 28)。
  足すのは、パスを書く欄と、フォルダ / ファイルを選ぶダイアログ(`ChooseModelPlace`)。
  足せない(無い・GGUF でない・もう入っている)ときは、理由をエラーのカードで出す
- 表示だけの設定: アプリモードのときは「起動の設定」(作業領域は会話ごと・最初のモデル・llama.cpp)、aibow-server につないでいるときは「aibow-server」(つなぎ先・作業領域)。
  変え方などは見出しの横の i の吹き出しに出す
  (画面に操作の説明を書かないため)
- **aibow-server の管理者**(0018 の 11-0):ブラウザで管理者がログインしたとき・サーバーの PC の上で開いたとき(`ModelsResult.manage`)は、
  アプリモードのときと同じ一覧・置き場所を出し、表示だけの設定は「aibow-server」(つなぎ先・作業領域)。置き場所はサーバーの PC のパスを書く(選ぶダイアログは出さない)。
  一覧の先頭に「使える」のチェックの列を足す。使えないモデルの行は薄くし、「読み込む」を出さない。入力欄の下などのモデルの選択には、使えないモデルを出さない(`Models.models` と `allModels`)
- 降ろしたあとは、入力欄の下のモデルの選択に「(降ろしています)」と出し、点線の枠にする(送信するときに会話のモデルを読み込む。0015 の 29)。
  会話のモデルが無い新しい会話の画面では、最後に読み込んだモデル(`ModelsResult.last_model`)を出し、新しい会話もそのモデルで作る(`ChatService.NewConversation`)

### プロファイル(設定の画面の「会話」。0014)

画面は一旦作ってから使い方を考える(0014 の 12)。今の形:

- 一覧(`ProfileSettings.tsx`)。名前・「既定」の印・「アーカイブ済み」・このプロファイルから作った会話の数。押すと下で編集する。最後に「+ 作成」(選んでいるプロファイルの値を写して作る。名前は重ならないよう「新しいプロファイル 2」などにする。Go は重なる名前を断る)
- 既定のプロファイル(新しい会話の画面で最初に選ばれるもの)は、一覧の「既定」の印で見せ、選んだプロファイルの操作の行の「既定にする」で変える(押すとその場で `SetDefaultProfile`。
  自分のもの・配布されたもののどちらにもある。既定のもの・アーカイブ済みのものは押せない。管理の画面の配るプロファイルには出さない。0056。0050 では一覧の上のセレクトだった)
- 編集:名前・「既定にする」・「アーカイブ」/「アーカイブ解除」・「削除」(削除の形。押せないときは理由を吹き出しに出す。削除できるのは既定でなく、使っている会話が無いとき)
- 値は会話の設定と同じ入力欄(`ConversationSettingsForm`。モデルも)と会話の上限・返事の上限。名前・値・決まり・ツール(この PC の「確認しない」も)は下書きで、
  画面の下の「保存」で確定する(`ChatService.SaveProfile`。[確定式の画面](#確定式の画面と離れる前の知らせ0053))。保存できなければ理由を出して、下書きはそのまま残す。
  「既定にする」は下書きに関わらない人ごとの設定なので、押すとその場で変わる(下書きは残る)
- 決まりの「固定」は、項目の名前の横の錠(`FixMark`)で付け外しする。会話の設定の画面では、固定した項目を押せなくして「プロファイルで固定」と添える
- 「ツール」:ツールの扱いは、プロファイルの中の1つの一覧で決める([下](#プロファイルのツール))
- **配る**(0018 の 11-1):ブラウザで管理者がログインしているときだけ、編集の操作のボタンの下に「配る:配らない / 全員 / 指定した人」と、指定した人なら名前のチェック(自分と local は出さない)。
  変えたらすぐ保存(`SetProfileShare`)。一覧には「全員に配っている」「N 人に配っている」(色付きの枠。吹き出しに相手)と、ほかの人が作ったものなら作った人の名前
- **配布されたプロファイル**:受け取った人には、一覧の下に「配布されたプロファイル」の欄を分けて出す(作った人の名前)。選ぶと、値と決まりを読むだけで出し(`fieldset` ごと無効)、
  「複製」(`CopyProfile`。複製したものを選んだ状態にする)と「既定にする」を置く。編集の欄は、選んでいるプロファイルのある一覧のすぐ下に出す
- 新しい会話の画面のプロファイルの選択は、配られたものがあれば「自分のプロファイル」「配布されたプロファイル」のまとまりに分ける(`optgroup`。管理者が配っているものも「配られた」に入る)
- 会話の設定の画面(`ConversationSettingsView.tsx`): 入力欄の下、メーターの右の歯車で開く([下](#会話の設定の画面))。設定の画面と同じく会話の場所に出す
- ウィンドウは初めて起動したとき 720×820、最小 480×480(`main.go`)。次からは閉じたときの位置と大きさで開く([下](#次の起動で戻すもの))

  | 橙(点滅しない) | ツールを実行する前の確認を待っている(答えるまで送信が止まっている) | 答えたとき(生成中に戻る) |

    その送信でエラーが届いていたら赤、そうでなければ青。停止ボタンで止めたのはエラーではない

    (以前は開き直しでエラーが消え、ツールの回数の上限で止まったのに、エラーが出ずに止まったように見えた。2026-11-21)
  - 一覧を畳んでいるときは、ハンバーガーの右下に1つだけ出す(直径 9px・右と下の端から 6px。一覧の背景の色で縁取る。2026-10-16、ユーザーの指示で右上の 7px から変えた)(確認待ち → エラー → 生成中 → 終わった、の順で気にしてほしいものを選ぶ)。マウスを乗せると、どんな会話があるかを出す

  - 並べ方と畳んだまとまりは PC ごとに localStorage に覚える(ワークスペースが PC のものなので。下の「次の起動で戻すもの」)。
    狭いときは一覧の部品が2つ描かれるので、部品の外に1つだけ持ち(`useSyncExternalStore`)、両方が同じものを見る

- ウィンドウが狭い(720px 以下)ときは、一覧を開くと会話を押しのけず、会話の上に重ねて出す(`App.tsx` の overlay。後ろの会話には影)

  - 広くなったら、広いときにハンバーガーで自分で開け閉めした状態に戻す(覚えていなければ開く。2026-10-16、ユーザーの指示)。狭いときに重ねて出していたかどうかは引き継がない

## チャット

- 要約した位置の区切り(`ChatView.tsx` の `Divider`)は「― ここまでを要約しました 12,000 → 3,000 tok(25%)―」。前後の大きさは保存してある要約の記録(`Compaction.stats`)から出すので、開き直しても再起動しても出る(記録の無い古い要約は大きさを出さない)。% は要約したあとが前の何割になったか。開くと要約の文と記録の1行(前後の大きさは見出しにあるので、記録の行には入れない)(2026-10-16、ユーザーの指示)
- ユーザーの発言の下に、右寄せで「渡さない 時刻 コピー」(最後の発言は先頭に「直す」)
- 返事の最後に「コピー 時刻 渡さない 詳細」(最後の返事は「渡さない」の後ろに「再生成」)。「詳細」は統計行(モデル名・速さ・トークン数)と、返事の最初の発言の ID(コピーのボタン付き。ツールを使った返事は、この ID から後ろの発言がまとまっている)で、ふだんは畳む。生成中は出さない。
  ID はログや DB(`messages` の `id`)を調べるときの手がかり(2026-10-19、ユーザーの指示)
- 「渡さない」(`ChatView.tsx` の `ExcludeButton`。0011): 目のアイコン。押すとその吹き出しを「モデルに渡さない」にし(返事はツールの呼び出しと結果も一緒)、アイコンは斜線の入った目のまま残る。もう一度押すと戻す。
  外した吹き出しは薄く、点線の枠で出す(要約・truncate で渡していない発言の薄い表示と見分けるため)。生成中の会話では押せない。変えたらメーターを数え直す
- 「再生成」「直す」(0011。最後のやり取りだけ。生成中・読み込み中は押せない):
  - 再生成(更新のアイコン): 最後の返事を消して、今のモデル・設定でもう一度返事を作る。送信・生成のエラーのすぐ横にも「再生成」を出す(0048 の D8)
  - 直す(鉛筆のアイコン): 最後の発言の吹き出しが入力欄になり、「再送信」「キャンセル」。再送信すると、その発言と返事を消して直した文で送る
  - 押したら表示から最後のやり取りを外し、送信と同じ吹き出しで返事を流す。終わってエラーがあれば、会話を開き直して(Go は何も消していない)元の表示に戻し、エラーを出し直す(`useChat.retry`)
- 時刻(`ChatView.tsx` の `MessageTime`。発言と返事で共通)
  - 保存した時刻(`created_at`)。返事は書き終えて保存した時刻、送信した発言は保存されたときの user イベントで付く
  - 今からどれくらい前か(「たった今」「3分前」「2時間前」「4日前」)で出し、5日以上前は日時(「2025/10/12 14:05」)で出す
  - マウスを乗せると実際の時刻を秒まで出す。開いたままでも進むよう、30 秒ごとに描き直す
- 要約中の箱(`ChatView.tsx` の `Summarizing`)は、思考と同じく畳んで出し、「古い発言を要約しています…」を押したときだけ要約の文を見せる(2026-10-19、ユーザーの指示)。
  開いたら一番下(最新の文)から見せ、開いている間は続きを追いかける
- 停止ボタンは、生成中の返事の吹き出しの中(右下)に出す。赤い停止のアイコン(`LuCircleStop`)だけで、何を止めるか(停止 / 要約を停止)はマウスを乗せると出る
- 返事の本文と要約の文の表示は [rendering.md](rendering.md)

### ツールのカード

- 書き換えるツール(`write_file` / `edit_file`)の実行前の確認(0005 の 3-2):
  - 確認を待っているカードは開いたままにし(「思考の過程」の枠も開いたまま)、橙の枠と「確認待ち」を出す
  - 中身は、パスと「上書き」「新しく作る」「書き換え」の印、差分(```` ```diff ```` のコードブロック)と、答えの2行(0049):
    1行目が拒否する側(理由の欄「拒否の理由(モデルに伝えます。空でも可)」と「拒否」)、2行目が実行する側(「今後も同じ答えにする:」の3つから1つ(しない・この返事の間・この会話の間。初めは「しない」)と「実行」。0051)
  - 選んだ範囲は拒否にも実行にも効く(0051 の決定事項 11):
    - この返事の間:この返事(送信1回ぶんのツールのループ)が終わるまで、このツールは聞かずに実行する / 聞かずに断る(モデルには「ユーザーはこのツールを使わないよう求めています…」を返す)。
      会話の設定には書かない(Go が送信の中で覚え、停止・エラーで止まったときも含めて返事が終わったら忘れる。次の送信ではまた聞く)
    - この会話の間:「拒否」= 拒否して、この会話ではそのツールをモデルに見せない(off)。「実行」= 実行して、この会話では確認しない(allow)(会話の上書き。0010)。
      答える前にまだ送っていない会話の設定を送り、答えたら会話の設定を読み直す(会話の設定の画面の「ツール」にもすぐ出る)
  - 「今後も同じ」が1回押しただけで決まらないよう、範囲を選ぶのとボタンの2つの操作にした(0049 ではチェック1つで、入れて拒否すると、その会話では戻すまでツールが使えなくなっていた。0051)
  - 押し間違えないよう、「拒否」(1行目の右。控えめな見た目)と「実行」(2行目の右。主のボタンの色)は行の間を空けて隣り合わせない。カードが出てもフォーカスは「実行」に置かない(Enter だけで実行されないように)
  - 答えたらボタンを押せなくし、Go が答えを受け取ったら、結果を待たずに確認を閉じて「実行中… N秒」にする(会話の一覧の「確認待ち」も外す。0049。受け取られなかったら確認のカードのまま)。
    結果が届いたら、ほかのカードと同じ畳んだ1行に戻る。拒否したカードの状態は「拒否」(この会話の間なら「今後許可しない」、この返事の間なら「この返事の間は拒否」。
    この返事の間に聞かずに断ったカードも「この返事の間は拒否」)、範囲を選んで実行したカードには「この会話では今後聞かない」か「この返事の間は聞かない」の印を添える
    (答えと範囲は保存されるので再起動しても同じ。`Confirmation` の `remember`・`for_reply`)
  - 待っているのはユーザーなので、その間は「応答待ち…」を出さない
  - 確認を待っている間に別の会話に切り替えても、Go は待ち続ける(ユーザーと決めた)。画面は生成中の吹き出しと同じく、確認の内容を覚えておき、戻ったらボタン付きのカードを出す。
    会話の一覧のその会話の印は、橙(「確認待ち」。点滅しない)にする。待っている間はほかの会話で送信できない(生成中と同じ)

- 返事の途中の compact(0040)で、モデルには結果を省いて短い一文だけを渡しているカードは、見出しに小さな印「省略して渡した」を付ける(保存した印から作るので、開き直したときに付く。2026-11-06、ユーザーと決めた)。
  送信の途中で省いたときは、吹き出しの中(要約の知らせと同じ場所)に「会話の上限に収めるため、この返事の途中で前に使ったツールの結果 N 件を省いてモデルに渡しました(X → Y トークン)」を、注意の色ではない目立たない色で出す(保存しない。文は 0048)

- 1回の送信の返事は吹き出し1つ。ツールを使った送信は、その中に「思考 → 答え → カード → 思考 → 答え …」と生成した順に並べる(`AssistantView.steps` がツールを呼んだ回)
- 最後の答えより前(各回の思考・途中の答え・カード・最後の回の思考)は、1つの枠(`Process`)にまとめて畳む。中の表示は枠が無いときと同じ。
  見出しは「思考の過程(N秒)」で、N は送信から答えを書き始めるまでの時間(思考が無ければ「ツールの使用(N秒)」)。
  生成中は最初の回のプロンプトを渡した時刻から数え(「思考中… N秒」)、保存後は記録から足し直す(`processLabel`。回の間のわずかな時間は入らない)。
  1回目の生成の間はツールを呼ぶか分からないので、ふつうの「思考の過程」で出し、ツールを呼んだ時点で枠に変わる
- カード(`ToolCard.tsx`)は「思考の過程」と同じく畳んだ1行: レンチのアイコン・ツールの名前・状態(実行中… N秒 / ✓ 秒数 / ✕ エラー)。実行中の秒数は画面で数える(確認したツールは答えた時から、ほかはカードが実行中で出た時から。別の会話を開いて戻ると 0 から数え直す。0049)。開くと引数と結果、読み取れなかった呼び出しはモデルが書いたまま
- ツールの名前にマウスを乗せると日本語の説明を出す(モデルに見せる説明は英語)
- モデルが書いた `<tool_call>` の生の文字列は答えの欄に出さない(会話の設定の画面の「モデルに渡した文字列」で見える)
- 色: 思考(1段の「思考の過程」と2段の枠)は青みのあるグレー(`--think`。要約の表示も同じ色)。枠の中の思考は少しだけ青を濃くし、カードは吹き出しの地の色(`--panel`)にして思考と区別する
- 枠の見出しの後ろにツールを呼んだ回数(「・ツール N回」。カードの数で、エラーや実行しなかった呼び出しも数える)を付ける

- 表示は保存された返事とツールの結果から作る(`turnView`)。生成中も `reply` / `tool_result` イベントで届いた保存済みの発言から作り直すので、再起動して開き直しても同じ並びになる
- 生成中にその会話を開き直したときは、生成中の送信で保存済みの発言を、保存された発言の側からは外す(生成中の吹き出しの中に出すため)

### ファイルを読み込む

0030。仕組みは [conversations.md](conversations.md) の「読み込んだファイル」。

- 読み込み方は3つ:入力欄の枠の中の送信ボタンの左のボタン(ファイルを選ぶ)・入力欄のあたり(`footer`)にドロップ・入力欄に貼り付け
  - ドロップ:Wails のランタイムは `document` でファイルのドラッグを受け、`EnableFileDrop` を使わないので「ドロップできない」にする。
    入力欄のあたりで受けたら `stopPropagation` で上に伝えない(`preventDefault` は、ブラウザがファイルを開いて画面を移ってしまうのを止める)。
    持って入っている間は、枠を点線にする
  - 貼り付け:クリップボードにファイルだけが入っているとき(エクスプローラーでコピーしたなど)だけ読み込む。文も入っていれば(表計算の表は文と画像の両方が入る)、今までどおり文を貼る
- 読み込むたびに Go の `CheckFile` で確かめる(`attachments.ts`)。読めない・大きすぎる・会話の上限に入らない・画像を読めないモデルのときは、札を足さずにエラーを出す(理由と数字は Go が書く)。
  中身は base64 の文字列で渡す(Go の `[]byte` の JSON の形。Wails もブラウザも同じ)。もう付けているファイルは、中身ではなく数とトークン数の合計だけを渡す(画像は重いので送り直さない)。
  10 MB(画像の上限)より大きいファイルは、Go に送る前に断る
- 読み込んだものは入力欄の枠の上に札(`components/FileChips.tsx`。ファイル名・大きさ・トークン数)で並べ、× で外せる。
  会話のモデルをまだ読み込んでいないため数えなかった札(`uncounted`)は、トークン数を「? tok」にし、吹き出しで「送信するときに数えます」と出す。
  打っている文と同じく、会話を切り替えても持ったまま。送ったら札は消え、送れなかったら(発言が保存されなかったら)文と一緒に戻す
- 送った発言の吹き出しの上にも札(ファイル名・大きさ)を出す。中身は見せない。送り直すときは、元の発言の札を引き継ぐ(Go が元の発言のファイルを付け直す)
- 画像の札は、高さ 120px ほどの小さな表示(入力欄の上と吹き出しの上。0030 の決定事項 25)。押すと画面いっぱいに重ねて大きく見せ、Esc か画像の外を押すと閉じる(`FileChips.tsx` の `ImageViewer`)。
  画像は `data:` の URL で表示する(会話を開くと、発言と一緒に画像の中身も Go から届く)
- 送った発言の札と、画像を大きく見る画面(右上)には「保存」(ダウンロードのアイコン)を出す(0051 の決定事項 13・14。読むだけの会話でも出す。削除済みの札には出さない)。
  画面がもう持っている中身を、読み込んだときの名前でブラウザのダウンロードにする(`diagramExport.ts` の `downloadBlob`。`<a download>` なので WebView2 でも使える)。
  テキストは UTF-8 にした中身(BOM なし)なので、UTF-16 などで読み込んだファイルは元のファイルと同じにならない。そのときは保存のボタンの吹き出しで知らせる
- 送った発言のファイル名の表示には「削除」(ゴミ箱のアイコン)を出す(0030 の決定事項 26)。押すとその中に「削除 / キャンセル」を出し、もう一度押すと Go の `DiscardFile` で中身を消す(戻せない)。
  捨てた札は、名前と「消去済み」だけの点線の札になる(画像も小さな表示をやめる)。捨てたらメーターを取り直す。生成中の会話・読むだけで開いた会話では出さない

## 確定式の画面と離れる前の知らせ(0053)

設定の画面は、欄を変えた瞬間に保存せず、**編集して「保存」か「キャンセル」で確定する**のを基本にする([0053](features/0053-save-on-confirm.md)。
途中の値がそのまま保存され、配っているプロファイルならほかの人の会話にすぐ効いてしまい、「やっぱりやめる」もできなかったため)。

- 確定式の画面:設定の「会話」のプロファイル・管理の「配布プロファイル」・管理の「ツール」・会話の設定の画面(歯車)
- 画面で変えている値(下書き)と保存した値を分けて持ち、比べて違えば「保存していない変更がある」(`unsaved.tsx` の `sameValue`。空の値と、文字の並びの順は比べない)
- 「保存」「キャンセル」は、編集の欄のいちばん下に貼り付ける(`SaveBar`。スクロールしても画面の下に見える。変えているあいだは上の線を青くして影を付ける。欄ごとの印は付けない。2026-11-23、ユーザーと決めた)。
  変えていない間は2つとも押せない。「保存」は主のボタン(`primary`)で文字だけ
- 「キャンセル」は確かめずに保存した値に戻す。保存できても「保存しました」は出さない(ボタンが押せなくなれば分かる)。保存できなければ、下書きを残したまま画面の上にエラーを出す
- 会話の上限・返事の上限は、その画面の「保存」に入れる。変えていれば、保存のときに作業領域を作り直してみてから保存する(`App.tsx` の `tryLimits`。作り直したときだけトースト)。
  上限だけの「適用」のボタンは無くした。生成中・読み込み中に上限を変えたときは「保存」を押せない(理由は吹き出し)
- 会話の設定の画面の「プロファイルに保存」「新しいプロファイルとして保存」は、写すのが保存したこの会話の設定なので、保存していない変更があるあいだは押せない
- **離れる前の知らせ**:保存していない変更があるときに、設定や管理の画面のタブを替える・「会話に戻る」・会話の一覧で会話を選ぶ・「+ 新規」・プロファイルの一覧で別のものを選ぶ・

  「保存」は保存できたら離れ、できなければ離れない。「キャンセル」は離れずに編集に戻る
  - ブラウザのタブを閉じる・再読み込みは、ブラウザの決まった確かめ(`beforeunload`)に任せる
  - デスクトップのアプリのウィンドウを閉じる(タイトルバーの ×・Alt+F4・タスクバー)ときは、Go が閉じるのを止めて画面に知らせ、同じ知らせを出す(`_cmd/aibow/closeguard.go`。Wails の `WindowClosing` のフックで `Cancel`。
    画面は保存していない変更があるかを `SetUnsaved` で知らせておき、「保存」か「保存しない」なら `CloseWindow` で止めずに閉じる)
- 即時のままのもの:基本設定の画面(明るさ・質問を右上)・ログインの画面の明るさ・会話の一覧の並べ方と畳む・ログのレベル・既定のプロファイルの選択・入力欄の上のワークスペース・worktree・この会話のツール・モデルの選択。
  1行の名前の欄(会話・worktree・表示名・メール・グループの名前)は「Enter か欄を離れたら確定・Esc で戻す」のまま
- 管理 > モデルの「使える」は押した瞬間に効くまま。読み込み中のモデルを使えなくするときだけ「読み込み中の … を使えないようにしますか?生成中の返事は止まり、モデルはアンロードされます。」+「使えないようにする」「キャンセル」で確かめる
- 下書きは画面の中だけに持つ(閉じれば消える。手元に残さない)

- プロファイルのモデルが空のときは、選択肢を「会話を始めたときのモデル」と出し、下にヒント(作った時点で読み込んでいるモデルを使い、その会話ではそのまま使い続ける)を出す。
  空のプロファイルから作った会話は、作った時点のモデルを会話のモデルとして写して固定するため(0014 の「あとから決めたこと(2026-10-31)」)
- 会話の上限・返事の上限(`LimitsForm`)だけは「適用」で反映する。作業領域をその大きさで作り直してみて(`ChatService.TryLimits`)、確保できたら保存する。生成中・読み込み中は押せない。新しい会話の既定も同じ
- 設定は開いている会話に対して変える(`useConversations.updateSettings`)
- 「会話に戻る」・一覧で会話を選ぶ・「+ 新規」で閉じる(開いている間は入力欄ごと隠れるので、歯車では閉じない)。一覧の下の歯車を押すと設定の画面に切り替わる。開いている会話を削除したら閉じる
- 「ツール」(`ConversationTools.tsx`): この会話でのツールの状態。見た目はプロファイルの「ツール」に揃える
  - グループのチェックは「この会話で使うか」(入力欄の上の「この会話のツール」と同じ設定)。グループは畳んで出し、▶ で開ける
  - ツールの行のチェックは、この会話で使うか(会話の上書き `tool_policies` の `on` / `off`)。プロファイルで「最初は使わない」ツールも使うにできる(使えないツールは押せない)。既定と同じにしたら上書きを消す。この会話で使っていないグループのツールは押せなくし、名前を薄く出す
  - 使うツールには「確認しない」の枠。この会話だけ確認せずに実行する / 確認するにできる(会話の上書きの allow / ask。既定と同じにしたら上書きを消す)。この会話で使っていないグループでは出さない
  - 灰色の枠で、どこで決まったか・使えない理由を添える:「この会話で使う」「この会話で使わない」(既定と違う)・「この会話」(確認の扱いだけ変えた)・「既定で使わない」・「作業フォルダが要る」。既定どおりのツールには付けない
  - 扱いは Go の `ChatService.ToolStates` が決めて返す(`toolPolicy` と同じ決め方。上書きが無いときの扱い `default` も返す)。会話の上書きが変わったら読み直す。
    会話の ID も渡し、プロファイルで使えないツールは「プロファイルで使えない」と添える(0014。押せなくするのは作業の順番の 4)
- 確認する / 確認しないを選ぶのは、この画面に後から足す(0009 の2段目以降)

## 新しい会話の画面

- 起動時と「+ 新規」は新しい会話の画面(`NewChat.tsx`、入力欄が真ん中)
- 会話はそこで最初に送信したときに作る(空の会話を作らない)
- 入力欄の上の左に、新しい会話のプロファイルの選択(しまっていないプロファイルが2つ以上あるとき)。選ぶと、その値(モデルも)の写しで作り直す(`ChatService.ProfileDefaults`)。
  最初は既定のプロファイル。会話は選んだプロファイルから作る(`ChatService.NewConversation(プロファイルの ID, 設定)`)
- この画面にいる間に設定の画面でプロファイルを変えると、選んでいるプロファイルの写しで作り直す(画面で変えていた写しは戻る)
- 入力欄の上の「この会話のツール」と下のモデルの選択は、プロファイルで使えない・固定したものを押せなくする

## ボタンの言葉と見た目(0050)

画面のボタンは、作ったときごとに言葉を選んできたので、同じ操作が場所によって違う言葉・違う見た目になっていた(2026-11-21 に洗い出した)。次の決まりにそろえる。
新しいボタンを足すときも、この決まりと下の言葉の表に合わせる。

- **ボタンの文字は名詞(漢語)**。一般的なアプリの言い方にそろえる。対象が分かりにくいときだけ「〜を削除」のように目的語を付ける。
  「新規」「接続」「ログイン」「ログアウト」「拒否」「実行」「停止」「コピー」はもともと名詞なのでそのまま
- **同じ操作は、どこでも同じ言葉**。ボタンだけでなく、説明(マウスを乗せた文)・見出し・確かめる文・トースト・エラーの中の言葉もそろえる(ボタンと説明で言葉が違うと迷うため)
- **削除はどこでも同じ形**(`components/DeleteButton.tsx`):
  1. 最初のボタン:ゴミ箱のアイコン(`LuTrash2`)+「削除」、赤い枠(`danger-outline`)。一覧の行の中など狭い所は、ゴミ箱のアイコンだけ(説明に「削除」)
  2. 押すと確かめる段:「〜を削除しますか?」(消えるものがあれば一言)+ 赤く塗った「削除」(`danger`)・「キャンセル」
  3. 重い削除の追加の確認(利用者の削除の、ログインの名前を打つ欄)は `extra` で足す。worktree の「破棄」も同じ形(`label="破棄"`)
  4. 会話の一覧(行ごと確かめる段に変わる)と読み込んだファイル(ファイル名の表示の中)は置き場所が違うので、部品は使わず、言葉と見た目だけそろえている
- **「×」は「閉じる」と「一覧から外す」だけ**(物そのものは消えない。説明は「〜を外す」)。会話の一覧の削除はゴミ箱
- **赤くする CSS は1か所**(`style.css` の `button.danger`・`button.danger-outline`)。親の class で絞った書き方(`.conversation button.danger`)は、ほかの場所に置いたときに効かないので使わない。
  逆に、親で絞ったボタンの規則(`.conversation button` の枠と背景を消す規則など)は、詳細度が同じでも後に書いたほうが勝って赤を消してしまうので、`:not(.danger)` で危険のボタンを外す(0056。会話の一覧の確かめる段の「削除」が赤くならなかった)
- **主のボタンの色**(`primary`)は、その場所でいちばん押す操作だけ(1つの場所に1つ)
- **アイコン**:一覧の行の中・見出しの横など、位置で「何に効くか」が分かる所はアイコンだけ(マウスを乗せると説明)。例:会話の一覧の削除(ゴミ箱)・メンバーや共有の相手を外す「×」・ワークスペースごとの「+」。
  画面や欄の中に単独で置くボタンはアイコン + 文字(「+」だけでは作成・追加・開くのどれか分からず、ゴミ箱だけでは何を削除するか分からないため)。例:「+ 利用者を作成」・詳細の「ゴミ箱 削除」・入力欄の横の「+ 追加」(`with-icon`)。
  確かめる段の「削除」「キャンセル」と、保存・適用などは文字だけ(2026-11-21、ユーザーと決めた)

| 操作 | 言葉 |
|---|---|
| 消す | 削除(確かめる段も「〜を削除しますか?」) |
| worktree を捨てる | 破棄(取り込んでいない変更ごと捨てるので、削除と分ける) |

## お知らせとエラー

- 文は、使う人が何をすればいいかを先に、中の事情は後ろか括弧に書く(AGENTS.md の「コードの書き方」。0048)
- モデルの読み込み・設定の変更などのお知らせは、会話の表示ではなく右上のトースト(`toast.tsx`)に出す
- 時間のかかる処理は出したままにし、同じ key で置き換える
- エラーは会話の表示に出す。理由と対処を書いた断り(`ChatEvent.caution`。管理者が使えないようにしたモデルの会話に送ったとき)は、赤ではなく注意(三角のアイコン。要約できなかったお知らせと同じ見た目)
- 会話のモデルを読み込めずに送信が終わったときは、出したままの「…を読み込み中…」のトーストを消す
- 起動に失敗したとき(lib が無いなど)は、「起動できません: …」を1回だけ出す。そのあと Go のメソッドは同じ理由で断るので、その理由を含むエラーは出さない(`App.tsx` の `addError`。`useModels` の `startupError`)。
  以前は設定の画面でタブを移る・ウィンドウに戻るたびに同じエラーが積み上がり、タブが下に押し出されていた(2026-10-29、ユーザーの指摘)。「サーバー」のタブは起動に失敗しても使える(0019)
- 設定・管理・会話の設定の画面の上に出すエラーは「直前の操作の結果」として扱い、その画面で次の操作をしたら消す([0043](features/0043-clear-errors.md)。2026-11-08、ユーザーが決めた)。
  操作は、ボタンを押す・フォームを送る・入力欄で Enter・選択肢やチェックを変える(打っている途中は数えない)。外枠で拾うので、部品ごとにエラーの持ち方を変えなくてよい(`errors.ts` の `operationEvents`。`App.tsx` で画面を包む)。
  以前は足すだけで消えず、ログインを3回間違えると「名前かパスワードが違います」が3つ並んでいた。会話の表示のエラーは、どこで失敗したかの記録なので消さない
  この画面のエラーは会話の表示に入れず、別に持つ(`App.tsx` の `screenErrors`)。以前は会話の表示に溜まっていて、画面を閉じると新しい会話の画面に全部並んだ(2026-11-20、ユーザーの指摘)。
  送信・生成のエラーは、この画面を開いている間に届いても会話の表示に入れる
- 新しい会話の画面に出ているエラー(まだ会話が無いときのもの)は、そこで「+ 新規」を押したら消す
- aibow-server につながらない間は、同じ理由のエラーを会話の表示に重ねて出さない([0057](features/0057-login-expiry-and-retrust.md) の段3)。
  理由は種類で見る(「aibow-server につながりません」・「証明書が、信頼したときのものと違います」。`errors.ts` の `serverDownReason`。文そのものは呼んだ URL などで変わるので比べない)。
  最初に分かった1回だけ出し(モデルの一覧の取り直しでも、会話を選ぶ・送るなどの操作でも同じ印。`useModels` の `noteServerDown`)、あとは左下のサーバーのアイコン(0056)で分かる。
  理由が変わったら(つながらない → 証明書が違う)もう一度出す。つながったら「aibow-server につながりました」のお知らせで印を下ろす。
  設定などの画面のエラーは次の操作で消えるので、つながらないエラーも操作のたびに出す(印は立てる)。
  以前は会話を選ぶたびに「aibow-server につながりません」が積み重なっていた(H の確認で見つかった)
- 使っている途中で aibow-server に 401 で断られたら(ログインの期限が切れた)、ログインの画面に戻し、タイトルの下に「もう一度ログインしてください(ログインの期限が切れました)」を警告の形で1行出す(0057 の段1。ブラウザも同じ)。
  デスクトップのアプリは、Go(`connection.go` の `unauthorized`)がトークンを手放してから Wails のイベント `aibow:unauthorized` を出し、`backendWails.ts` の `onUnauthorized` が受ける。
  ログインしたら画面を読み直す(入力欄に打っていた文は残さない。0057 の未決事項 3 でユーザーと決めた)
- 見ていない会話の様子もトーストで知らせる(2026-10-16、ユーザーの指示。`App.tsx` の `notifyConversation`)。見ている会話は表示で分かるので出さない
  - 「「会話の名前」の返事が終わりました」(6 秒)・「…がエラーで終わりました」(赤い枠・10 秒)・「…でツールの実行の確認を待っています」(10 秒)
  - 押すとその会話を開く(マウスを乗せると説明)。会話ごとに key を分け、同じ会話の新しい様子で置き換える。その会話を開いたら消す
  - 一覧の印(会話の一覧の「名前の左の印」)と同じときに出る。トーストは消えるが、印は開くまで残る

## スクロール

- 生成中に届く断片で一番下へ送るのは、一番下にいるときだけ(`useStickToBottom`。チャット・思考の箱・要約中の箱)。上にスクロールして読んでいる間は送らない
- 「一番下にいたか」は scroll イベントではなく描画のたびのスクロール位置で決める(イベントは次のフレームに届くので、数ミリ秒ごとの断片に間に合わない)
- 長い返事を読んでいて質問が上に隠れたら、その質問の写しを右上に出しておく(`pinnedQuestion.ts` と `ChatView.tsx` の `PinnedQuestion`。2026-10-19、ユーザーの指示)。
  アプリの設定(設定の画面の「基本設定」の「画面」のチェック。DB の `pin_question`。会話ごとではない)で切り替える。初めはオン
  - 出す質問は「画面の上の端より上に、吹き出しが丸ごと隠れた最後の質問」。吹き出しの一部が見えているとき・次の質問が上の端から 80px 以内まで上がってきたとき(写しと重なる)は出さない
  - 吹き出しそのものを `position: sticky` で止めないのは、sticky は親の箱の中でしか止まらず(発言と返事は平らに並ぶので、吹き出しの親に返事が入っていない)、
    長い質問がそのまま止まると返事が読めなくなるため。写しは会話の列の右端にそろえ、3行で切る(`-webkit-line-clamp`)。押すと元の吹き出しまで戻る
  - `.chat` の一番上に高さ 0 の箱を `position: sticky` で止め、その中に写しを `position: absolute` で重ねる(中身の高さを変えないので、一番下に張り付くスクロールに影響しない)
  - 位置は scroll イベントのたびと、中身が変わったあとに、吹き出しの位置を上から順に見て決める(写しは次のフレームで十分なので、イベントで良い)
- 「質問だけ」の表示(`questionsOnly.ts`。2026-10-19、ユーザーの指示): 会話の右下に重ねた丸いボタン(`LuListFilter`。スクロールしても動かない)で切り替える。
  返事・エラー・要約の区切りと、発言の下の「直す・時刻・コピー」を隠し、自分の質問だけを並べる。質問を押すと元の表示に戻り、その質問を上の端に出す
  - 入るときは、読んでいた返事の質問(画面の真ん中より上にある最後の質問)を真ん中に出し、枠で印を付ける。ボタンか Esc で選ばずに戻ると、入る前の位置に戻る
  - 会話を切り替えた・送信したら「質問だけ」をやめる(送信と同じ描画でやめるので、一番下へ送るのと食い違わない)。会話ごとに覚えない
  - 返事は描画したまま CSS(`.questions-only`)で隠す。表示から外すと、戻ったときに Markdown・コードの色付け・mermaid の図を描き直し、開いていた思考の箱も閉じるため
  - 切り替えたときの位置は `useQuestionsOnly` が決める。`useStickToBottom` には切り替えを `layoutKey` で渡し、高さだけ覚え直させる
    (覚え直さないと、切り替える前の高さと比べて「一番下にいた」と間違え、生成中の次の断片で一番下へ引き戻してしまう)
  - 「質問だけ」の間は、右上の質問の写しは出さない
  - `.chat` の下の余白は 56px にした(右下のボタンが最後の吹き出しの下の「直す・時刻・コピー」に重ならないように)。`.chat` とボタンは `.chat-area` に入れて、ボタンを重ねる
- スクロールバーは `::-webkit-scrollbar` でつまみだけのフラットな形にし、色はテーマの `--scrollbar` / `--scrollbar-hover`。
  標準の `scrollbar-color` は使わない(指定すると Chromium は `::-webkit-scrollbar` を無視する)

## 明るさ(ライト / ダーク)

- 設定の画面の「基本設定」の「明るさ」で、システム(初め)・ライト・ダークを選ぶ(2026-10-19、ユーザーの指示)。DB の `theme`(画面の設定 `DisplaySettings`)
- 実際に使う明るさは `theme.ts` だけが決め、`<html data-theme="light|dark">` に書く。「システム」なら OS の `prefers-color-scheme` で決め、OS で切り替えたらすぐ追いかける
- CSS は `:root` がライト、`:root[data-theme="dark"]` がダークの色(`prefers-color-scheme` は直接見ない。設定で選んだ明るさと食い違わないように)。
  `color-scheme` も合わせるので、チェックボックス・選択肢の一覧などブラウザが描く部品も同じ明るさになる。mermaid の図の配色も `useDarkTheme` で合わせる
- 設定は Go から画面を描いたあとに届くので、そのままだと起動の直後に OS の明るさで描いてから切り替わる(ちらつく)。
  最後の設定の写しを localStorage に置き、最初の描画の前に `initTheme`(`main.tsx`)で決める。設定そのものは DB が正で、届いたら写しも書き直す

| 一覧の並べ方・畳んだまとまり | localStorage `aibow.listGrouping`・`aibow.listGroupsClosed`(`conversationGroups.ts`。0038) | メニューで選んだとき・見出しで開け閉めしたとき(自動で開いたときも) |

- ウィンドウの位置と大きさは、ウィンドウを作る前に Go が知る必要があるのでファイルに、ほかは画面だけの好みなので localStorage に置く。どれも会話の DB には入れない(その PC の画面の都合で、会話をサーバーに置く形にしても手元に残るもの)
- 位置と大きさは DIP(拡大率で割った値)。作るときのオプション(`X`・`Y`・`Width`・`Height` と `InitialPosition: WindowXY`)で渡す(`SetPosition` / `SetSize` は `Run` の前だと無視される。wails3 スキルの window-state.md)
- 閉じるときのウィンドウからは正しい値が取れないことがあるので(特に Frameless)、`events.Windows.WindowDidMove` / `WindowDidResize` のたびに覚えておき、その値を書く。
  最大化・最小化しているときは位置と大きさを覚えない(元に戻したときの大きさを残す)。最大化は、ウィンドウの準備ができてから(`WindowRuntimeReady`)行う(オプションの `StartState` で最大化すると、そのあと `X`・`Y` に動かされる)
- **`OnShutdown` は使わない**:Windows では最後のウィンドウを閉じる(× や Alt+F4)と、`OnShutdown` を呼ばずに終わる(beta.26。最後のウィンドウを閉じたときは終了の処理を通らず、終了のメッセージを直接送るため)。`app.Run` は返るので、その後で書く
- 覚えた位置の上の端(タイトルバーのあたり)がどの画面の作業領域にも入っていなければ、真ん中に出す(画面の情報は `Run` の後でしか取れないので、`WindowRuntimeReady` で確かめる)
- 狭いウィンドウ(720px 以下)で起動したときは、覚えた「開いている」にかかわらず一覧は閉じて始め、広げたときに覚えた状態に戻す。狭いときに重ねて出した一覧・F2 のために開いた一覧は覚えない
- 最後に開いていた会話が消えていたら、新しい会話の画面で始める

## ウィンドウの移動とリサイズ(Frameless)

- ドラッグできる場所は CSS の `--wails-draggable: drag`(`.titlebar`)、ボタンは `no-drag`
- `main.tsx` が最初の描画の前に Go を呼ぶ係の中身(`initBackend`。デスクトップでは `backendWails.ts` が `@wailsio/runtime` を読み込む)を読み込む(ドラッグとリサイズはランタイムがページ全体のマウス操作を見て行う)。タイトルバーのボタンも `backend.ts` の `appWindow` を呼ぶ
- リサイズの判定はマウスの座標だけで行われるので、ルート要素に余白は要らない(wails3 スキルの「5px の余白が必須」は beta.26 では不要)
- ただし、ウィンドウの端に接してスクロールする要素(`.chat` / `.settings-view`)は、スクロールバーが端の数 px(Windows の SM_CXSIZEFRAME)の
  マウスを受け取ってリサイズできなくなる(ランタイムがずらすのはページ全体のスクロールバーだけ)。
  透明な枠線 `border-right: var(--edge-gap) solid transparent` でスクロールバーを内側に寄せる。**端に接してスクロールする要素を足したら同じようにする**

## IME(日本語入力)が効かなくなる問題

- Windows の WebView2 は、別のウィンドウから戻ると IME が効かなくなることがある
- Go が `events.Windows.WindowSetFocus` で `aibow:window:focus` を送り、画面の `imeFocus.tsx` が見えない input を経由して入力欄にフォーカスを付け直す(同じ要素への blur → focus では直らない)
- IME 変換中・ボタンにフォーカスがあるときは触らない
- 新しい入力欄を足しても、テキスト入力なら自動で対象になる

  - 配布プロファイル(`ProfileSettings` の `mode="distributed"`。0032 の段3・0059):配っているものの一覧(印は「全員に配布」か、グループをメンバーに広げた「N 人に配布」・止めたものは「停止中」。

    配布する相手は人を選ぶ部品で、範囲に「配布しない」は無く、指定した人を全員外すと確定できない(`SharePicker` の `noneAllowed={false}`。配布をやめるのは停止か削除)。
    停止・削除は管理者自身の既定でもできる。削除は、だれかの会話が1つでもあれば押せない(停止を案内する)。
    「+ 新規」で、名前(初期値「新しいプロファイル」。配布プロファイル同士で重なれば番号)・モデル(使えるモデルから)・配布する相手を決め、配布の確定のボタンで作ってそのまま配る(Go の `ShareNew`)。作ったものを選んで編集の欄を開く
  - 設定の画面の「会話」(`mode="own"`):自分の配っていないプロファイルだけを変える。配っているものは「配布されたプロファイル」の欄に読むだけで出し、「複製」と「既定にする」ができる(停止中のものは印が「停止中」で、既定にはできない)
- **利用者のタブ**(0031 の段2〜4。0032 で管理の画面に移した。もとは中に [人 | グループ] の切り替えがあり、グループは管理の画面の「グループ」のタブになった):
  - 人:「ID・名前で探す」欄(表示名・ログインの名前・メールアドレス)・絞り込み [すべて | 招待中 | 管理者 | API キーあり | 無効 | 30日使っていない]・「+ 利用者を作る」(押すと名前の欄)。
    「API キーあり」は期限切れのキーも含む(0060)。
    一覧は ID(ログインの名前)・名前(表示名。無ければ「-」)・状態(文字の印:無効・管理者・招待中・ログインなし・キー期限切れ)・最後に使った日(今日・昨日・n 日前・日付・-)・作った日・会話の数。見出しを押すと並べ替え(ID でも名前でも。名前は表示名の順で、表示名が無い人は ID で比べる。状態は無効の人を最後に)。
    無効の人は行ごと薄くし、「キー期限切れ」の札は注意の色(0060 の未決事項 2。2026-11-24 にユーザーが選んだ)。
    表は ID と名前を別の列にする(0056)。詳細の見出し・人を選ぶ部品・チップなど狭い所は「表示名(ログインの名前)」・表示名のまま。
    「30日使っていない」は最後に使った日(一度も使っていなければ作った日)から 30 日以上
  - 行を押すと、一覧の下に詳細(決定事項 35):表示名とメール(欄を離れると保存。断られたら元に戻す)・グループ(札と「+ グループに足す」)・パスワード
    (招待中ならリンクの期限と「リンクを出し直す」、それ以外は「決め直すリンクを出す」→「今のパスワードは使えなくなります」で確かめる。無効の人には出さない)・
    API キー(期限「2027-02-21 まで」「無期限」「期限切れ(… まで)」か「なし」・「発行」/「再発行」・「削除」(削除の形)。
    「発行」/「再発行」を押すと、行の中で期限 [30 日 | 90 日 | 1 年 | 無期限](最初は 90 日)を選ぶ段になり、再発行なら「前のキーは使えなくなります」を添えて「発行」・「キャンセル」。0060 の未決事項 1)・
    状態(「有効」と「無効にする」→「ログイン中の画面とアプリは切れます。会話と API キーは残ります」で確かめる / 「無効」と「有効に戻す」。0060)・
    その人の会話・「削除」(削除の形。消えるものを出し、ログインの名前を打つまで確かめる段の「削除」を押せない。決定事項 15・36)。自分には、パスワード・状態・会話・削除を出さない
  - グループ(管理の画面の「グループ」のタブ):新しいグループの名前の欄と「+ 作成」・一覧(名前・長・人数・共有の数)。行を押すと詳細:名前(欄を離れると保存)・メンバーの札(冠を押すと長にする / 外す・× で外す)と
    足す人を名前で探す欄(足す前に「この人は、グループに共有された n 件の会話と n 件のプロファイルを読めるようになります」)・「このグループを消す」(「n 件の会話と n 件のプロファイルの共有から外れます」で確かめる)
- **グループのタブ**(長だけ):自分が長のグループごとに、メンバーの札(× で外す。自分を外すときは「長でもなくなります」で確かめる)と足す人を探す欄(確かめは管理者と同じ)
- ログインの画面(`Login.tsx`):名前とパスワード。ログインできる管理者がいなければ、作り方のコマンドを1行ずつ出す(0020)。
  URL が `#reset=<合言葉>` なら、ログインの代わりに「○○ のパスワードを決めます」の画面(決めたらそのままログインし、URL から合言葉を消す。0022)。
  利用者のタブの形は上の「利用者のタブ」。出したリンクとキーは、一覧の上の枠に一度だけ出す(コピーと閉じる)。自分と `local` は消せない。
  管理者の印は表示だけ(付け外しはコマンド)
