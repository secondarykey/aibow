# 画面(UI)

`_cmd/aibow/frontend/src/` のチャット画面(React + TypeScript)の配置と操作の説明です。

- 返事の表示(Markdown・コードの色付け・mermaid の図と書き出し): [rendering.md](rendering.md)
- Go とのやり取り(バインディング・イベント・停止)とアプリの起動: [_cmd/aibow/AGENTS.md](../_cmd/aibow/AGENTS.md)

## ファイルの分け方

| ファイル | 役割 |
|---|---|
| `App.tsx` | 画面全体をまとめる。一覧の開閉(狭いウィンドウでは重ねて出す)、会話の場所に出すもの(チャット / 新しい会話 / 設定) |
| `useModels.ts` / `useConversations.ts` / `useChat.ts` / `useAppSettings.ts` | Go とのやり取り |
| `transcript.ts` | 会話の表示(吹き出し・ツールのカード・エラー・区切り)の持ち方。保存された発言から表示を作る |
| `components/` | 表示。`ConversationList` / `Splitter` / `TitleBar` / `ChatView` / `ToolCard` / `Composer` / `WorkDirBar` / `ModelBar` / `Meter` / `NewChat` / `SettingsView` / `ConversationSettingsView` / `ConversationSettingsForm` / `CopyButton` など。返事の中身は [rendering.md](rendering.md) |
| `mediaQuery.ts` | 画面の幅・OS のライト / ダークを見る(`useMediaQuery`。狭いウィンドウの境目 `NARROW_QUERY`) |
| `stickToBottom.ts` | 「一番下にいるときだけ追いかける」スクロール |
| `toast.tsx` / `imeFocus.tsx` / `errors.ts` | トースト / IME の付け直し / Go のエラーの文の取り出し |

## 配置

- 左: 会話の一覧([下](#会話の一覧))
- 右上: タイトルバー(`TitleBar.tsx`)。Frameless のため自前で作る。開いている会話の名前と、右端に最小化・最大化・閉じる。
  一覧の上の空いているところと合わせてドラッグで移動できる
- 中央: チャット([下](#チャット))。入力欄の上に作業フォルダ(`WorkDirBar.tsx`)、入力欄の下にモデルの選択、右端にメーター(`Meter.tsx`)。summary の会話では、メーターのトークン数(「n / 上限」の n)を押すと今すぐ要約する(n を両側から矢印で挟んだボタン →| n |←。マウスを乗せると「要約」。別のボタンは置かない)
- 一覧の下: 左にアプリの名前とバージョン(「AIBow 0.3.1」。バージョンは Go の `_cmd/aibow/version` を `ChatService.Version` で受け取る。`wails3 dev` では「AIBow 0.3.2+dev」。[deploy.md](deploy.md))、右に設定の歯車のアイコン(文字は付けない)
- 設定の画面(`SettingsView.tsx`): 一覧の下の歯車のアイコンで開閉する。別の画面として扱い、チャットの代わりに会話の場所に出す。
  一覧で会話を選ぶ・「+ 新規」でも閉じる。入力欄の打ちかけの文は App が持つので消えない。
  中身は新しい会話の既定・アプリ全体の設定・ツール。開いている会話には関係しない(0009)
- 会話の設定の画面(`ConversationSettingsView.tsx`): 一覧の各行の歯車で開く([下](#会話の設定の画面))。設定の画面と同じく会話の場所に出す
- ウィンドウは起動時 720×820、最小 480×480(`main.go`)

## 会話の一覧

- ウィンドウの上から下まで。上のハンバーガーで開閉し、閉じるとアイコンだけの細い列になる
- 各行の右に、歯車(会話の設定)と削除(×)。マウスを乗せた行と開いている行にだけ出す。会話の設定の画面を開いている間は、その行の歯車に色を付けて出したままにする
- 「+ 新規」は一覧の一番上の行(スクロールしても隠れない)。開いているときも閉じたときも同じアイコン(`LuPlus`)を使い、開いているときだけ文字を添える(設定と同じ)
- 右の仕切り(`Splitter.tsx`)で幅を変えられ、幅は localStorage に覚える
- ウィンドウが狭い(640px 以下)ときは、一覧を開くと会話を押しのけず、会話の上に重ねて出す(`App.tsx` の overlay。後ろの会話には影)
  - 影を押す・Esc・会話を選ぶ・「+ 新規」・「設定」で閉じる
  - 狭くなったときに一覧が開いていたら自動で閉じ、狭いウィンドウで起動したときは閉じた状態から始める
  - 重ねて出している間は仕切りを出さない(幅は広いときに変える)
  - 影はタイトルバーにもかかるので、重ねて出している間に右上のボタンを押すと、最初の1回は一覧が閉じるだけ

## チャット

- ユーザーの発言の下に、右寄せで「時刻 コピー」
- 返事の最後に「コピー 時刻 詳細」。「詳細」は統計行(モデル名・速さ・トークン数)で、ふだんは畳む。生成中は出さない
- 時刻(`ChatView.tsx` の `MessageTime`。発言と返事で共通)
  - 保存した時刻(`created_at`)。返事は書き終えて保存した時刻、送信した発言は保存されたときの user イベントで付く
  - 今からどれくらい前か(「たった今」「3分前」「2時間前」「4日前」)で出し、5日以上前は日時(「2025/10/12 14:05」)で出す
  - マウスを乗せると実際の時刻を秒まで出す。開いたままでも進むよう、30 秒ごとに描き直す
- 停止ボタンは、生成中の返事の吹き出しの中(右下)に出す。赤い停止のアイコン(`LuCircleStop`)だけで、何を止めるか(停止 / 要約を停止)はマウスを乗せると出る
- 返事の本文と要約の文の表示は [rendering.md](rendering.md)

### ツールのカード

- 書き換えるツール(`write_file` / `edit_file`)の実行前の確認(0005 の 3-2):
  - 確認を待っているカードは開いたままにし(「思考の過程」の枠も開いたまま)、橙の枠と「確認待ち」を出す
  - 中身は、パスと「上書き」「新しく作る」「書き換え」の印、差分(```` ```diff ```` のコードブロック)、理由の欄、「拒否」「実行する」
  - 答えたらボタンを押せなくし、結果が届いたら、ほかのカードと同じ畳んだ1行に戻る。拒否したカードの状態は「拒否」(保存されるので再起動しても同じ)
  - 待っているのはユーザーなので、その間は「応答待ち…」を出さない
  - 確認を待っている間に別の会話に切り替えても、Go は待ち続ける(ユーザーと決めた)。画面は生成中の吹き出しと同じく、確認の内容を覚えておき、戻ったらボタン付きのカードを出す。
    会話の一覧のその会話の印は、橙の点滅(「確認待ち」)にする。待っている間はほかの会話で送信できない(生成中と同じ)

- 1回の送信の返事は吹き出し1つ。ツールを使った送信は、その中に「思考 → 答え → カード → 思考 → 答え …」と生成した順に並べる(`AssistantView.steps` がツールを呼んだ回)
- 最後の答えより前(各回の思考・途中の答え・カード・最後の回の思考)は、1つの枠(`Process`)にまとめて畳む。中の表示は枠が無いときと同じ。
  見出しは「思考の過程(N秒)」で、N は送信から答えを書き始めるまでの時間(思考が無ければ「ツールの使用(N秒)」)。
  生成中は最初の回のプロンプトを渡した時刻から数え(「思考中… N秒」)、保存後は記録から足し直す(`processLabel`。回の間のわずかな時間は入らない)。
  1回目の生成の間はツールを呼ぶか分からないので、ふつうの「思考の過程」で出し、ツールを呼んだ時点で枠に変わる
- カード(`ToolCard.tsx`)は「思考の過程」と同じく畳んだ1行: レンチのアイコン・ツールの名前・状態(実行中… / ✓ 秒数 / ✕ エラー)。開くと引数と結果、読み取れなかった呼び出しはモデルが書いたまま
- ツールの名前にマウスを乗せると日本語の説明を出す(モデルに見せる説明は英語)
- モデルが書いた `<tool_call>` の生の文字列は答えの欄に出さない(会話の設定の画面の「モデルに渡した文字列」で見える)
- 色: 思考(1段の「思考の過程」と2段の枠)は青みのあるグレー(`--think`。要約の表示も同じ色)。枠の中の思考は少しだけ青を濃くし、カードは吹き出しの地の色(`--panel`)にして思考と区別する
- 枠の見出しの後ろにツールを呼んだ回数(「・ツール N回」。カードの数で、エラーや実行しなかった呼び出しも数える)を付ける
- 統計行は吹き出しの最後に1つで、ループ全体の合計(「N回生成」と、ツールを呼んだときは「ツール N回」が付く)。コピーは各回の答えをつなげたもの
- 表示は保存された返事とツールの結果から作る(`turnView`)。生成中も `reply` / `tool_result` イベントで届いた保存済みの発言から作り直すので、再起動して開き直しても同じ並びになる
- 生成中にその会話を開き直したときは、生成中の送信で保存済みの発言を、保存された発言の側からは外す(生成中の吹き出しの中に出すため)

### 作業フォルダ

- 入力欄の枠の上に左寄せで出す(`WorkDirBar.tsx`。`Composer` の `top`)。チャットの画面と新しい会話の画面の両方
- 決めていないときはフォルダのアイコンだけ。押すとフォルダを選ぶダイアログ(Go の `ChatService.ChooseWorkDir`。Wails のダイアログ)
- 決めたらフォルダの名前を枠付きで出し、右に外す × を出す。名前にマウスを乗せると絶対パス
- 設定の画面ではなくここに置くのは、どのフォルダを触らせているかがいつも見えるように、また新しい会話の画面から設定を開かずに選べるようにするため
  (作業フォルダは新しい会話の既定に入らないので、会話ごとに選ぶ)

### この会話のツール

- 作業フォルダの隣に出す(`ToolBar.tsx`。`Composer` の `top` の中で、`.composer-top` に並べる)
- レンチのアイコン(ツールのカードと同じ)。この会話で使うものがあれば、横に名前を枠付きで出す(「組み込み, filesystem」。作業フォルダと同じ見た目)。何も使わなければアイコンだけ
- 押すと一覧が**上に**開く(入力欄の上にあるので、下に開くと入力欄に重なる)。先頭に「組み込み」、その下に MCP のサーバー。項目を押すとオン・オフ(チェックの印)。一覧の外を押すと閉じる
- 新しい会話では、設定の画面の「ツール」でチェックしているものが最初から選ばれている。チェックを外したものも、ここではいつでも選べる
- `${workdir}` を使うサーバーは、作業フォルダを決めていないと薄く出す(マウスを乗せると理由)
- 最初は MCP のサーバーだけを選ぶ「プラグ」だったが、組み込みのツールが使われているかが見えず分かりにくかったので、組み込みも並べた(ユーザーと決めた)

### 設定の画面の「ツール」

- アプリ全体の設定の下(`ToolSettings.tsx`)。「MCP のツール」ではなく「ツール」にし、その中にグループを並べる(ユーザーの希望):
  **組み込み**(aibow の中で動くツール。最初は「ローカル」と呼んでいたが、MCP のサーバーもこの PC で動くので紛らわしく、変えた)と、settings.json の **MCP のサーバーごと**
- グループの見出しにチェック。意味は「**新しい会話で最初から使う**」(使えなくするのではない。会話の「この会話のツール」からはいつでも選べる)。
  **チェックしたグループは一覧を開いて出し、外したグループは畳む**(ふだん使わないものを並べておかないため)。外したグループも会話で使うことがあるので、名前の左の ▶ で開いてツールごとに選べる
- 開いたグループは、字下げと左の線で段を付ける。ツールごとのチェック(使う)・名前・説明(ローカルは日本語の説明 `toolLabels.ts`、MCP は説明の1行目。長ければ切り、マウスを乗せると全部)
- 見出しには、使うツールの数と「すべて使う / すべて使わない」。MCP のサーバーには読み直すボタン(サーバーを一時的に起動して一覧を受け取り直す。受け取っている間は回る印)
- MCP のサーバーで一覧がまだ無ければ、開いているグループなら欄を開いたときに、畳んだグループなら ▶ で開いたときに、自動で受け取る(受け取っている間は「(ツールの一覧を読み込み中…)」。失敗したら理由をエラーの枠で出し、自動では繰り返さない)
- `tools.json` で「確認しない」にしてあるツールは、橙の小さな枠で「確認しない」と出す(画面からは選べない)
- 変えたらメーターを数え直す。新しい会話の画面なら、これから作る会話の「この会話のツール」の選択も、グループのチェックに合わせ直す

## 会話の設定の画面

- 一覧の各行の歯車で開く(`ConversationSettingsView.tsx`)。その会話だけの設定(システムプロンプト・compact・temperature・presence penalty・思考)と、
  「この設定を新しい会話の既定にする」、モデルに渡した文字列
- 入力欄は設定の画面の「新しい会話の既定」と同じもの(`ConversationSettingsForm.tsx`)。新しい会話は既定の写しから始まり、ここで会話ごとに変える(0009)
- 設定は開いている会話に対して変える(`useConversations.updateSettings`)ので、開いていない会話の歯車を押したら、その会話を開いてから出す
- 同じ歯車をもう一度・「会話に戻る」・一覧で会話を選ぶ・「+ 新規」で閉じる。一覧の下の歯車を押すと設定の画面に切り替わる。開いている会話を削除したら閉じる
- 会話ごとにツールを1つずつ選ぶ・確認しないにするのは、この画面に後から足す(0009 の2段目以降)

## 新しい会話の画面

- 起動時と「+ 新規」は新しい会話の画面(`NewChat.tsx`、入力欄が真ん中)
- 会話はそこで最初に送信したときに作る(空の会話を作らない)
- この画面にいる間に設定の画面の「新しい会話の既定」を変えると、これから作る会話の設定(既定の写し)にも入れる

## お知らせとエラー

- モデルの読み込み・設定の変更などのお知らせは、会話の表示ではなく右上のトースト(`toast.tsx`)に出す
- 時間のかかる処理は出したままにし、同じ key で置き換える
- エラーは会話の表示に出す

## フォーカス

- 入力欄へ自動でフォーカスを移すとき(会話を開いた・「+ 新規」・返事が終わった)は、ほかの入力欄で打っている最中なら移さない(`Composer.tsx` の `focusUnlessTyping`)。
  会話の名前の変更(一覧のダブルクリック)の入力欄からフォーカスを奪って、編集が閉じてしまったため

## スクロール

- 生成中に届く断片で一番下へ送るのは、一番下にいるときだけ(`useStickToBottom`。チャット・思考の箱・要約中の箱)。上にスクロールして読んでいる間は送らない
- 「一番下にいたか」は scroll イベントではなく描画のたびのスクロール位置で決める(イベントは次のフレームに届くので、数ミリ秒ごとの断片に間に合わない)
- スクロールバーは `::-webkit-scrollbar` でつまみだけのフラットな形にし、色はテーマの `--scrollbar` / `--scrollbar-hover`。
  標準の `scrollbar-color` は使わない(指定すると Chromium は `::-webkit-scrollbar` を無視する)

## ウィンドウの移動とリサイズ(Frameless)

- ドラッグできる場所は CSS の `--wails-draggable: drag`(`.titlebar`)、ボタンは `no-drag`
- `main.tsx` で `@wailsio/runtime` を import しておく(ドラッグとリサイズはランタイムがページ全体のマウス操作を見て行う)
- リサイズの判定はマウスの座標だけで行われるので、ルート要素に余白は要らない(wails3 スキルの「5px の余白が必須」は beta.26 では不要)
- ただし、ウィンドウの端に接してスクロールする要素(`.chat` / `.settings-view`)は、スクロールバーが端の数 px(Windows の SM_CXSIZEFRAME)の
  マウスを受け取ってリサイズできなくなる(ランタイムがずらすのはページ全体のスクロールバーだけ)。
  透明な枠線 `border-right: var(--edge-gap) solid transparent` でスクロールバーを内側に寄せる。**端に接してスクロールする要素を足したら同じようにする**

## IME(日本語入力)が効かなくなる問題

- Windows の WebView2 は、別のウィンドウから戻ると IME が効かなくなることがある
- Go が `events.Windows.WindowSetFocus` で `aibow:window:focus` を送り、画面の `imeFocus.tsx` が見えない input を経由して入力欄にフォーカスを付け直す(同じ要素への blur → focus では直らない)
- IME 変換中・ボタンにフォーカスがあるときは触らない
- 新しい入力欄を足しても、テキスト入力なら自動で対象になる
