## 目的

確認で見つかった3つの不具合を直す。

1. アプリを使っている途中でログインの期限(10 日)が切れても、画面に何も出ない(送っても何も起きないように見える)
2. aibow-server の証明書を作り直したあと、同じつなぎ先で「この証明書を信頼する」を押しても、新しいフィンガープリントが使われない(アプリモードに切り替えて、つなぎ直すまで直らない)
3. aibow-server につながらない間、会話を選ぶたびに「aibow-server につながりません」が会話の表示に積み重なる(ログにも同じ ERROR が何件も出る)

学ぶこと:

- **エラーの「理由」で状態を持つ**:「つながらない」の印を true / false だけで持つと、理由が「期限切れ」に変わっても「もう知らせた」と扱われて黙ってしまう。印は理由(文)ごとに持つ
- **401 は「つながらない」ではない**:サーバーには届いていて、断られている。直し方(ログインし直す)が違うので、別の扱いにする
- **覚えたもの(信頼したつなぎ先)と、今使っているもの(つなぐ先のフィンガープリント)の2つの置き場所**:片方だけ書き換えると食い違う

### 1. ログインの期限切れが画面に出ない

2. aibow-server を起動し直したあと(09:56:18)、アプリの `Models()` は `/models` が 401(`token_expired`)で断られた。`ui/models.go` は、**つながらないときと同じ** `ServerError` にこのエラーを入れる。
   画面は `serverDown` がまだ true なので、**理由が「期限切れ」に変わっても、新しいカードを出さない**。Go も `serverDown` が true のままなのでログを出さない
3. 会話の一覧・共有された会話は、取り直しのエラーを画面に出さない(`reloadShared` は `() => {}`、`reloadList().catch(() => {})`)

5. aibow-server は、期限の切れたトークンを**最初に断ったときに消す**(`auth/tokens.go` の `appTokenUser`)。そのあとの呼び出しは「API キーが無いか、違います」(`invalid_api_key`)になる(サーバーのログの 09:56:18 の2行目から)。期限切れだと分かるのは最初の1回だけ
6. アプリには、途中で 401 になったときにログインの画面へ戻る道が無い。ブラウザは `backendWeb.ts` が 401 で `onUnauthorized` を呼び、`LoginGate`(`Login.tsx`)がログインの画面にするが、`backendWails.ts` の `onUnauthorized` は何もしない(`() => () => {}`)。

7. エラーの文(`ErrTokenExpired`)は「設定の画面の「サーバー」で、もう一度ログインしてください」。0047 から「サーバー」のタブにログインの欄は無い

### 2. 証明書を作り直したあと、同じつなぎ先で信頼し直せない

## 決定事項(話の流れから Chat が決めて書き、2026-11-24 にユーザーが確認したこと)

### 段1 ログインの期限切れ(アプリ)

1. **アプリでも、使っている途中で 401 になったらログインの画面に戻す**(ブラウザと同じ。0031 の決定事項 44 の続き)
   - Go:`api/client` の `Client` に「401 で断られたら知らせる」受け口を足す(例 `OnUnauthorized(func())`)。画面でつないだとき(`serverScreen`)だけ、`connection` が受け口を付ける。
     知らせを受けたら、手元のトークンを手放し(`forgetKey`。`Account()` が `NeedLogin` を返すように)、Wails のイベント(例 `aibow:unauthorized`)を出す。続けて何本も 401 になっても、イベントはログインし直すまで1回
   - settings.json に手で書いた API キー・環境変数のときは今のまま(ログインの画面では直せないので、エラーで伝える)
   - 画面:`backendWails.ts` の `onUnauthorized` で、このイベントを受ける。`LoginGate` は今のまま(`expired` でログインの画面、ログインしたら読み直す)
2. **ログインの画面に、期限が切れて戻ったことを1行出す**(例「ログインの期限が切れました。もう一度ログインしてください」)。`expired` で戻ったときだけ。ブラウザも同じ
3. **`ErrTokenExpired` の文を今の画面に合わせる**:「アプリのログインの期限(10 日)が切れました。もう一度ログインしてください」(「設定の画面の「サーバー」で」を外す。ログインの画面に戻るので)
4. **aibow-server は期限の切れたトークンを、断るときに消さない**(何度呼ばれても `token_expired` で断る。「API キーが無いか、違います」に変わらないように)。
   同じ PC で次にログインすれば置き換わる(`SetAppToken` は利用者と PC ごとに1本の UPSERT)ので、溜まらない。ログアウト(`RevokeAppToken`)は今のまま消す
5. **401 は「つながらない」にしない**:`ui/models.go` は、つながらないエラー(`unreachableError`)・証明書の食い違いだけを `ServerError` にする。401 などそのほかは今の `ServerError` とは分ける(段1-1 でログインの画面に移るので、画面に出す先は要らない見込み。分け方は Code が決める)
6. **「つながらない」の印を理由ごとにする**:`useModels.ts` の `serverDown` と `ui/models.go` の `serverDown` は、伝えた理由の文を持ち、**理由が変わったら**もう一度カード・ログを出す(つながらない → 証明書が違う、など)

### 段2 証明書を信頼し直す(同じつなぎ先)

7. **`ConnectServer` の「同じ aibow-server なら何もしない」は、フィンガープリントも同じときだけにする**。
   今つないでいるのと同じつなぎ先でも、信頼したフィンガープリント(`pinnedFingerprint(p)`)が `connection.json` の `fingerprint` と違えば、
   つなぐ先のフィンガープリントと `known` を新しいものにして保存し、**起動し直してください**の画面にする(`pending = "server"`)
8. **トークンとログインの名前は残す**(同じ aibow-server で、証明書だけが変わったので。起動し直したらログインせずに使える)。トークンが期限切れなら、段1 のとおりログインの画面になる
9. **起動したまま新しいフィンガープリントに替えない**:`PinCert` は `http.Client` を作り直すだけで、動いている間に替えることを考えていない(`hc` を守っていない)。切り替えは起動し直して行う今の形(0019 の決定事項 1)にそろえる
10. 「起動し直してください」の画面の文は、つなぎ先を変えたときの文(0051)を使うか、「新しい証明書でつなぎます」を足すかを Code が決める(下の「未決事項」)

### 段3 つながらないときのエラーを積み重ねない

11. **つながらない間は、つながらないエラーを会話の表示に重ねて出さない**:`App.tsx` の `addError`・`addRecordError` で、`isUnreachable` のエラーは、つながらないことをすでに伝えていれば(`models.serverDown()`)出さない。
    起動のときの `report` と同じ決まりを、全部の操作に広げる。つながらないことは、最初の1回のカードと、左下のサーバーのアイコン(0056。警告の色)で分かる
12. **どの呼び出しでつながらないと分かっても、同じ印を立てる**:印をまだ立てていないときに操作でつながらないと分かったら、そのエラーを1回出して印を立てる(`useModels` に印を立てる口を足す。モデルの一覧の取り直しで同じ理由のカードを重ねて出さないように)。
    印を下ろすのは今のまま、一覧の取り直しでつながったとき(「aibow-server につながりました」のお知らせ)
13. **ログ**:Wails の `Binding call failed` のうち、aibow-server につながらない・証明書が違う・401 のエラーは Debug に落とす(理由は `ui/models.go` の Warn やサーバーのログで1回分かるので)。
    そのほかの `Binding call failed` は今のまま。やり方は、Wails に渡す `Logger` を、この行だけレベルを変える slog の Handler で包む形を Chat は考えている(エラーの中身で見分けられるか、Wails がどんな属性で書いているかは未確認。Code が確かめて決める)

## 作業中に決めたこと(Code。2026-11-24)

- 段1-1 の「続けて何本も 401 になっても、イベントは1回」は、**断られたキーが今のキーのときだけ知らせる**形にした(`connection.go` の `unauthorized`)。
  `api/client` の受け口 `OnUnauthorized(func(key string, err *APIError))` は、その呼び出しで送ったキーを渡す。最初の1本でキーを手放すので、残りは「今のキーではない」になる。
  ログインし直したあとに前のキーで送った呼び出しの返事が遅れて届いても、新しいキーを手放さない。印(フラグ)を別に持たずに済む
- 段1-1 で `connection.json` のトークンは消さない(手元のクライアントから手放すだけ)。起動し直しても断られてログインの画面になる(H3 の今の動き)。ログインすれば置き換わる
- 段1-5 の分け方:`ui.ModelsResult` に `LoginRequired`(`login_required`)を足し、401 はここで返す(`ServerError` に入れない。ログは Debug)。画面は一覧を前のままにし、何もしない(ログインの画面へは Go のイベントで移る)。
  401 でもつながらないでもないエラー(500 など)は、今までどおり `ServerError`
- 段1-6 の「理由」は、**文そのものではなく種類**で持つ(つながらない `unreachable`・証明書が違う `cert`・そのほかは文)。Go は `ui/models.go` の `serverDownReason`、画面は `errors.ts` の `serverDownReason`。
  つながらないときの文には下回りのエラー(呼んだ URL・`/_aibow/store/Conversation` など)が入り、呼び出しごとに変わるので、文で比べると同じ理由でもカードが重なるため
- 段3-12 の印を立てる口は `useModels` の `noteServerDown(text)`(まだ伝えていない理由なら印を立てて true、伝えていれば false)。印を立てるときに `serverError` も入れる(モデルの欄と、つながったら会話の一覧と設定を読み直す effect が動くように)
- 段3-11 は会話の表示に出すときだけ。設定・管理・会話の設定の画面のエラーは次の操作で消える(0043)ので、つながらないエラーも操作のたびに出す(印は立てる)。出さないと、押しても何も起きないように見えるため
- 段3-13 のログ:Wails は `Binding call failed: Bound method returned an error: <エラーの文>` を **文字列だけ**で書く(型も属性も無い。Wails v3.0.0 の `messageprocessor_call.go` と `transport_http.go` の `httpError` で確かめた)。
  そこで Wails に渡す `Logger` を包み(`_cmd/aibow/wailslog.go`)、この頭の行で、`api/client` の `ErrUnreachable`・`ErrCertChanged`、`auth` の `ErrTokenExpired`・`ErrBadKey` の文を含むものだけ Debug に落とす
- 段2 で、`ConnectServer` が保存してあるつなぐ先と同じ aibow-server のときは、トークンがあれば残す(2回「接続」してもトークンを失わない)。ログは「aibow-server(…)に新しい証明書でつなぐように決めました(ログインしたまま。…)」
