## 目的

チェックの途中で、ユーザーが次の3点で迷った(2026-11-21)。

1. 新しい会話の画面でフォルダ(ワークスペース)を選び、設定の画面を開いて戻ると、選んだものが消えていた。もう一度同じフォルダを選ぶと、前に作ったワークスペースが使われたが、新しく作ったのか既存を使ったのか分からなかった。
   また「同じフォルダなら既存を使う」なら、同じフォルダで別のワークスペースを作れないのでは、という心配
2. 確認のカードの「理由の欄・今後許可しない・拒否・この会話では今後聞かない・実行する」の並びで、理由の欄が何に効くのか分からない
3. `go test` のような時間のかかるコマンドを確認して実行したあと、画面が止まって、動いているのか分からない

学ぶこと:

- **操作の結果を見せる**:裏で「既存を使った」「実行を始めた」などの判断をしたら、それを画面に出す。出さないと、使う人は止まった・失敗したと受け取る
- **押し間違いを仕組みで防ぐ**:重い操作(今後ずっと・実行)は、隣に並べない・1回で決まらないようにする

## 今の作り(2026-11-21、Chat がコードを読んで確かめた)

### 1. ワークスペース

- 新しい会話の画面で「+ 新規」を押すと、選んでいたワークスペースを外す(`App.tsx` の `onNew`。0035 の「+ 新規はワークスペースを選ばない」)。
  設定の画面を開いている間は入力欄ごと隠れ、そこから「+ 新規」で戻ると、この外す処理が通る。歯車をもう一度押して戻ったときは残る(`toggleSettings` は draft に触らない)。
  ユーザーが見たのはこの流れと見ている(画面で再現はしていない。Code が確かめる)
- 「フォルダから新しく作る」(入力欄の上)と、設定の「ワークスペース」タブの「作る」は、どちらも `createFromFolder` → `ChatService.CreateWorkspace` → `config.Workspaces.CreateFromFolder`。
  **同じフォルダ1つだけのワークスペースがあれば、作らずにそれを返す**(同じものが一覧に並ばないように。`MigrateWorkDirs` もパスごとに1つにするために使う)。そのことは画面に出ない
- そのため、同じフォルダで2つ目のワークスペースを作る手段は、別のフォルダで作ってから設定でパスを書き換えるしかない(`Update` はほかのワークスペースとのパスの重なりを見ていない)

### 2. 確認のカード(`components/ToolCard.tsx` の `Confirm`)

- 1行に「理由の欄(placeholder「理由」)・今後許可しない・拒否・この会話では今後聞かない・実行する」
- 理由の欄は**拒否するときの理由**。「拒否」「今後許可しない」のときモデルに「ユーザーが実行を拒否しました。理由: …」として渡す。「実行する」側では捨てる。説明はマウスを乗せたときの title だけ
- 「今後許可しない」は `ToolPolicy.ToolOff`(拒否して、この会話ではそのツールをモデルに見せない)。「この会話では今後聞かない」は `ToolPolicy.ToolAllow`(実行して、この会話では確認しない)

### 3. 実行中の表示

- 答えると `ChatService.ConfirmTool` を呼ぶが、カードの確認(`l.confirm`)は **`tool_result` が届くまで外さない**(`useChat.ts`)。その間カードは「確認待ち」のまま、ボタンが押せなくなるだけ
- 会話の一覧の「確認待ち」の印(`confirmingId`)も、結果が届くまで残る
- 「実行中…」(`ToolCard` の summary)は確認の無いツールだけに出る
- `run_command` の出力は、終わってからまとめて結果になる(`tool/command.go`。上限 120 秒)。途中の様子は届かない

## 決定事項(ユーザーと決めたこと)

### 1. ワークスペース

1. **設定の画面・管理の画面から「+ 新規」で新しい会話の画面に戻ったときは、選んでいたワークスペースを外さない**。新しい会話の画面にいて(ほかの画面を開いていない)「+ 新規」を押したときは、今のまま外す(0035)
2. **入力欄の上の「フォルダから新しく作る」は、今のまま同じフォルダ1つのワークスペースがあればそれを選ぶ**。ただし、そのことをトーストで知らせる(例:「既にあるワークスペース「aibow」を選びました」)。新しく作ったときは知らせなくてよい(名前が出るので分かる)
3. **設定の「ワークスペース」タブの「作る」は、同じフォルダでも毎回新しく作る**(同じフォルダを別のワークスペースにしたいときの入口)。名前が重なるときは「aibow (2)」のように番号を付ける(モデルが呼ぶフォルダの名前はワークスペースの中で重ならなければよいので、そのままフォルダ名)

### 2. 確認のカード

4. **ボタンを2つにし、「今後」はチェックボックス1つにまとめる**。2行に分け、**1行目が拒否する側、2行目が実行する側**(ユーザーの指定)

```
[ 拒否の理由(モデルに伝えます。空でも可)      ] [拒否]
□ この会話では、このツールを今後も同じ答えにする        [実行する]
```

   - チェックを入れて「実行する」= 今の「この会話では今後聞かない」(`ToolAllow`)。チェックを入れて「拒否」= 今の「今後許可しない」(`ToolOff`)
   - 1回押しただけでは「今後ずっと」にならないので、押し間違えても被害が小さい
5. **押し間違いを防ぐ配置**:「拒否」は1行目の右、「実行する」は2行目の右の端に置き、2つを縦・横に隣り合わせない(行の間を空ける)。「実行する」だけを主のボタンの色にし、「拒否」は控えめにする
6. **カードが出たときのフォーカスを「実行する」に置かない**(Enter だけで実行されないように)
7. 文言は 0048 の決まりに沿う。チェックボックスの説明(title)には、実行なら確認せずに実行・拒否ならモデルに見せない、を書く

### 3. 実行中の表示

8. **答えたらすぐに、カードの確認の中身を閉じて「実行中… 12秒」のように経過の秒数を出す**(結果が届くまで。拒否したときは結果がすぐ届くので、今と同じ)
9. **会話の一覧の「確認待ち」の印も、答えた時点で外す**(生成中の印に戻す)
10. 実行中のコマンドを止める手段は、今の停止のボタンのまま(この仕様では変えない。止まることを Code が確かめる)
