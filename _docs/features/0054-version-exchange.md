# 0054: 画面のアプリと aibow-server でバージョンを受け渡す

- 状態: ⬜ 未着手
- ロードマップ: ロードマップの外(サーバーモードの土台)
- 決めた日: 2026-11-22(Chat でユーザーと相談した。下の「決定事項(ユーザーと決めたこと)」の外は、話の流れと今のコードを読んで Chat が決めて書いた)
- 前提: 0015(画面のアプリから aibow-server につなぐ `api/client`)、0019(アプリのログイン・`ProbeServer`)、0051(ログインするまで aibow-server を呼ばない)、[_docs/deploy.md](../deploy.md)(バージョンの決め方・`internal/appversion`)

## 目的

サーバーモードでは、画面のアプリと aibow-server が別々に更新される。今はお互いのバージョンを知らないので、
古いアプリが新しいサーバーにつないでおかしくなっても、どちらの版の組み合わせで起きたのかが分からない
(`ProbeServer` の「aibow-server が古いなら、アプリと同じ版にしてください」は、404 から推し量っているだけ)。

そこで、**アプリが自分のバージョンを送り、サーバーが自分のバージョンと「対応できるアプリの最低バージョン」を返す**ようにする。
今は**受け渡しと記録だけ**で、何も止めない。合わないときにアプリに知らせる・アプリの更新を促す、は将来この上に作る。

学ぶこと:

- **HTTP にはハンドシェイクが無い**:MCP は最初の `initialize` で `clientInfo` / `serverInfo` のバージョンを1回だけ交換する(つながりがずっと続くので)。
  HTTP はリクエストが1つずつ独立していて(ステートレス。会話の履歴を毎回全部送るのと同じ)、「つないだ瞬間」が無い。
  そのため、ブラウザの `User-Agent` やサーバーの `Server` と同じく、**毎回のリクエストと返事の見出し(ヘッダー)に載せる**のが HTTP の流儀
- **SemVer の比べ方**:`0.9.2+dev` の `+` の後ろはビルドの情報で、大小の比べ方に入らない(deploy.md)。将来の判定はこれを外して比べる

## 決定事項(ユーザーと決めたこと。2026-11-22)

1. アプリが aibow-server につなぐとき、**アプリが自分のバージョンを送る**
2. aibow-server は**自分のバージョン**と、**対応できるアプリの最低バージョン**を返す
3. **今は何も止めない**。受け渡しと記録だけにする。合わないときにどうするか(知らせる・更新を促す・断る)の判定のルールは将来決める
4. 将来、合わないときにアプリへ知らせる・アプリの更新を促すための土台にする
5. (別の UI の仕様で)サーバーモードのとき、アプリの左下のバージョンの後ろにサーバーのアイコンを出し、マウスを乗せるとサーバー名を出す。
   **その説明に、サーバーのバージョンも出せるようにする**(アイコンと説明の見た目はその UI の仕様で扱う。ここは値を画面に渡すところまで)

## 決定事項(話の流れから Chat が決めて書いたこと。作る前にユーザーに確かめる)

### どこに載せるか

6. **専用の口(`/_aibow/version` など)は作らず、HTTP の見出しに載せる**。理由:
   - アプリが aibow-server を呼ぶ入口が1つではない(起動のときは `remote` の保存の口・`/_aibow/auth/key`、ログインを待つときは `/_aibow/auth/me`(0051)、設定の画面では `ProbeServer`)。
     どこか1か所に「最初に呼ぶ口」を足すと、通らない道が残る
   - アプリはサーバーが起動していなくても起動し、あとでつながる(0015 の 13)。毎回載せておけば、あとからつながったときも、サーバーを入れ替えて版が変わったときも、次の返事で分かる
   - ログインの要らない口(`/_aibow/auth/me`)の返事にも付くので、ログインする前から分かる(将来「アプリを更新してください」をログインの画面でも出せる)
7. 見出しの名前(今ある `X-Aibow-User` にそろえる):

   | 向き | 見出し | 値 |
   |---|---|---|
   | アプリ → サーバー(全部のリクエスト) | `X-Aibow-App-Version` | アプリのバージョン(`_cmd/aibow` の `appVersion()`。`0.9.3+dev` もそのまま) |
   | サーバー → (全部の返事) | `X-Aibow-Server-Version` | aibow-server のバージョン(`appversion.Version()`) |
   | サーバー → (全部の返事) | `X-Aibow-Min-App-Version` | 対応できるアプリの最低バージョン(決定事項 10) |

8. **サーバーは全部の返事に2つの見出しを付ける**(`/v1/` の OpenAI 互換の口・ブラウザの画面・404 も)。Cline などは知らない見出しを読み捨てるので害が無く、
   道ごとに付ける・付けないを分けるより分かりやすい。付けるのは aibow-server の一番外側の部品(信頼するプロキシの書き換え(0044)のあと、`mount` の外)の1か所
9. Cline やブラウザは `X-Aibow-App-Version` を送らない。**送ってこないリクエストは「画面のアプリではない」として何もしない**(記録もしない)。
   この機能より古いアプリも送らないので、同じ扱いになる

### 最低バージョン

10. 最低バージョンは `internal/appversion` に**手で書く定数**(`MinApp`)として置く。`_cmd/aibow/version` の写しとは別で、`go run _cmd/version.go` は書き換えない。
    **アプリとサーバーのあいだのやり取り(`api/client` と aibow-server の口)を、古いアプリが使えない形に変えたときに、手で上げる**(そのときの決め方を deploy.md に書く)
11. 初めの値は、**この機能が入る版**(作る時点の `_cmd/aibow/version`。そのタグがもう打たれているなら patch を1つ上げた版。deploy の版の決め方と同じ)。
    それより古いアプリはそもそも版を送ってこないので、知らせる相手にならないため
12. `+dev` の付いた値は返さない(最低バージョンは手で書いた値のまま。`go run` で patch +1 しない)

### サーバーの記録

13. aibow-server は、`X-Aibow-App-Version` の付いたリクエストを受けたら、**(相手のアドレス, アプリのバージョン)の組を、起動してから初めて見たときだけ** Notice のログを出す
    (「つながった MCP のサーバー」を Notice で残すのと同じ扱い。毎回出すと、生成のたびに行が増えるため)。覚えるのはメモリの中だけで、起動し直したら忘れる。
    文の例:「画面のアプリ(0.9.2)が 192.168.1.5 からつながりました(この aibow-server は 0.9.3、対応するアプリは 0.9.3 から)」
    - 相手のアドレスは、信頼するプロキシの書き換えのあとの `r.RemoteAddr` のホストの部分
    - 誰がつないだか(利用者の名前)は、見出しを付ける部品ではまだ分からないので出さない
14. 今は**版を比べない**。最低バージョンより古いアプリからつながっても、ログの文は同じ(判定のルールを決めるまで、「古い」とも書かない)

### アプリの受け取り(`api/client`)

15. アプリのバージョンは、`api/client` のパッケージで1回だけ決める(`client.SetAppVersion(v)`。`_cmd/aibow` の `main` で、クライアントを作る前に呼ぶ)。
    `Client` はあちこちで作られる(`newServerClient`・`ProbeServer` の中・ログインの `login`・`DisconnectServer`)ので、作るたびに渡すと漏れが出るため。
    `do`(全部のリクエストが通るところ)で見出しを付ける。決めていなければ付けない(テストや、ほかの人がライブラリとして使うとき)
16. `Client` は、返事の見出しから**最後に知ったサーバーのバージョンと最低バージョン**を覚える(`do` で毎回取り直す。`Info` と同じく、聞きに行かずに覚えた値を返す)。
    読む口は `ServerVersion() (server, minApp string)`。まだ1回も返事を受けていない・古い aibow-server で見出しが無いなら空
17. アプリは、サーバーのバージョンを**初めて知ったときと、変わったときだけ** Notice のログを出す。
    文の例:「aibow-server(http://192.168.1.10:8089)のバージョンは 0.9.3 です(このアプリは 0.9.2、サーバーが対応するアプリは 0.9.3 から)」
18. `Probe`(`ProbeServer` の結果)にも `ServerVersion`・`MinAppVersion` を足す(`/_aibow/auth/me` の返事の見出しから。`Trusted` のときだけ入る)。
    設定の画面の「サーバー」で確かめたときに、ログにも残す(画面に出すかは決定事項 20 と同じく UI の仕様で)

### 画面に渡す

19. デスクトップのアプリの `ServerConnection`(`_cmd/aibow/connection.go`)に `ServerVersion`・`MinAppVersion` を足す(今動いているクライアントの `ServerVersion()`。アプリモード・まだ知らないなら空)。
    ブラウザの画面はサーバーが配っているので同じ版で、渡さない
20. 画面にどう出すか(アイコンの説明に「サーバー名 ・ 0.9.3」のように出すか、知らないときに何も出さないか)は、**サーバーのアイコンの UI の仕様で決める**。ここは値を渡すところまで

## やらないこと

- server.db に残す(管理の画面で「どの PC がどの版でつないでいるか」を見る、は将来の案。今はログだけ)
- 専用の口(`/_aibow/version`)を作る(決定事項 6)
- aibow-mcp(MCP は `initialize` で既に版を交換している)・Cline などの OpenAI 互換のクライアントの版を見る
- ブラウザの画面とサーバーの版を受け渡す(同じものを配っているので)

## 完了の条件

1. アプリ(サーバーモード)から aibow-server を呼ぶと、全部のリクエストに `X-Aibow-App-Version` が付く(`api/client` のテスト)
2. aibow-server の返事に、`/v1/`・`/_aibow/`・画面・404 のどれでも `X-Aibow-Server-Version` と `X-Aibow-Min-App-Version` が付く(テスト)
3. aibow-server のログに、つないだアプリの版が、(相手, 版)ごとに1回だけ Notice で出る。Cline(見出し無し)では出ない
4. アプリのログに、サーバーの版が初めて知ったとき・変わったときだけ Notice で出る。古い aibow-server(見出し無し)でも、エラーにならずに空のまま動く
5. `ServerConnection` に `ServerVersion`・`MinAppVersion` が入る(サーバーモードでつながったあと)
6. 最低バージョンより古いアプリでも、今までどおりに使える(何も止めない)
7. [_docs/api.md](../api.md) に見出しの表を、[_docs/deploy.md](../deploy.md) に `MinApp` の役目と上げる時を書く
