# 0022: パスワードは本人が決める(招待・再設定のリンクと、パスワードを変える画面)

- 状態: ✅ 完了(2026-10-26。確かめたことは下の「確かめたこと」)
- ロードマップ: ロードマップの外(0017 の「パスワードは aibow-server が作って一度だけ表示する」を決め直す)
- 決めた日: 2026-10-26(Code でユーザーと決めた)
- 前提: 0017(利用者・ログイン・セッション)、0018(管理者の「利用者」のタブ)、0019(アプリ用のトークン)、0020(既定でログイン必須)

## 目的

**パスワードを本人が決め、本人が変えられるようにする**。
今は、パスワードはいつも aibow-server がでたらめに作って一度だけ見せるもので、本人が決める手段が無い。
管理者が「利用者」のタブで自分のパスワードを作り直したら、表示を読む前にログインの画面に戻り、入れなくなった(2026-10-26)。
セッションを残しても、ログアウトしたら同じことになる。作りの根本が「渡されたパスワードをずっと使う」になっているのを直す。

## 決定事項(ユーザーと決めたこと。2026-10-26)

1. **管理者(画面とコマンド)はパスワードを作らない。代わりに、本人がパスワードを決めるリンクを出す**(招待・再設定)。
   リンクは URL に合言葉(でたらめな値)を入れたもので、開いた人がその利用者のパスワードを決める
2. **リンクの期限は 1 時間**。一度使ったら使えない。出し直すと前のリンクは使えない
3. **今パスワードがある人に再設定のリンクを出したら、その時点で今のパスワードは使えなくする**(ログイン中の画面とアプリ用のトークンも切れる)。画面では出す前に確かめる
4. **本人が自分のパスワードを変える画面を作る**(今のパスワードと、新しいパスワードを2回)。管理者も、自分のパスワードはここで変える
5. **本人が決めるパスワードは 12 文字以上**(文字の種類は問わない)。名前と同じものは断る
6. **「利用者」のタブの自分の行には、再設定のボタンを出さない**(自分を締め出さないように)

## 決定事項(Code が決めたこと)

7. **合言葉は URL の `#` の後ろに置く**(`http://…:8089/#reset=<合言葉>`)。`#` の後ろはサーバーに送られないので、アクセスのログに残らない。画面が読んで、本文で送る。開いたら URL から消す
8. 保存するのは合言葉の SHA-256・持ち主・期限だけ(DB の版 14 `password_links`。1人1本。利用者を消すと一緒に消える)
9. **リンクでパスワードを決めたら、そのままログインする**(セッションを作る)。決めたときに、その人のほかのセッションとアプリ用のトークンは消す
10. **自分のパスワードを変えたら**、ほかのセッションとアプリ用のトークンは消し、今の画面には新しいセッションを渡す(ログインし直さなくてよい)。今のパスワードを間違えた回数は、ログインと一緒に数える
11. **リンクのアドレス**:画面で出したときは、管理者が開いている画面のアドレス(`location.origin`)。コマンド(`user add`・`user passwd`)は、aibow-server の待ち受け(`server.json`・引数)から作る。全部のネットワークで待ち受けるとき(`0.0.0.0`)は 127.0.0.1 で出し、ほかの PC からはアドレスを置き換えるよう添える
12. コマンドの `user add` は、パスワードの無い利用者を作って招待のリンクを出す。`user passwd` は、今のパスワードを使えなくして再設定のリンクを出す(入れなくなったときに戻る道)
13. ログインなし(`login: false`)の aibow-server では、リンクでパスワードを決める口は断る(パスワードを使わないので)。コマンドではリンクを出せる(あとでログインありにしたときのため)
14. 管理者がいない知らせ(0020 の `setup`)は、「パスワードを決めた管理者」がいないときに出す(招待のリンクをまだ使っていない管理者は、まだログインできないので)

## 確かめたこと(2026-10-26)

- 一時フォルダの aibow-server(`go run ./_cmd/dev build` で作った exe。port 18090・ログインあり・CPU)で、`user add boss` が `http://127.0.0.1:18090/#reset=…`(1 時間後の時刻)を表示。
  `user admin boss` のあとに起動すると、boss はまだパスワードを決めていないので「管理者がいません」が出る
- Chrome でリンクを開くと「boss のパスワードを決めます」の画面。決めるとそのままログインし、URL から `#reset=…` が消え、管理者の画面になる。合言葉はサーバーのログに出ていない
- 「利用者」のタブ:自分(boss)の行に再設定のボタンが無い・carol を作ると招待のリンク(期限と「一度だけ」)・carol の再設定は「今のパスワードは使えなくなります」で確かめてからリンク
- 「基本設定」の「パスワード」:今のパスワードを間違えると「今のパスワードが違います」・正しければ「パスワードを変えました」で、画面はログインしたまま。前のパスワードのログインは 401、新しいパスワードは 200
- テスト:`TestPasswordLinks`(期限・一度だけ・出し直し・決まり・ほかのセッションが切れる)・`TestChangePassword`・`TestAdminUsers`(自分の再設定を断る・再設定で前のパスワードとログインが使えない)・`TestUserCommands`・`TestLinkBase`
- 見ていないこと:期限切れのリンクを画面で開いたときの見え方(テストだけ)・HTTPS とほかの PC から開いたとき

## やらないこと

- メールでリンクを送る(管理者がチャットなどで渡す)
- 本人が「パスワードを忘れた」から自分でリンクを頼む口(管理者かコマンドが出す)
- デスクトップのアプリでパスワードを決める・変える(ブラウザで行う)
