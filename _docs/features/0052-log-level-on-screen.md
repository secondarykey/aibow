- 前提: 0008(ログの仕組み。`aibow/log`・`Init` の `Root`)、0032・0046(管理の画面・`Caller.ManagesPC`)

## 目的

ログのレベルは、起動したときに決まって変えられない(アプリの dev は Info・exe は Notice、aibow-server は `-debug` > `server.json` の `logLevel` > 既定、aibow-mcp は Info で固定)。
困ったことが起きたときに詳しいログを見たくても、起動し直すしかなく、起動し直すと起きていたことが消える。
**起動したあとに画面からレベルを変えられる**ようにする。起動したときのレベルの決め方は変えない。

学ぶこと:

- **slog のレベルをあとから変える**:`slog.Handler` はレベルを決まった値ではなく `slog.Leveler` で受け取れる。`slog.LevelVar`(あとから値を変えられるレベル)を渡せば、出口を組み直さずにレベルだけを変えられる(wenteasy/log の `NewSimpleHandler` も `slog.Leveler` を受け取る)
- **どのプロセスのログか**:サーバーモードでも、アプリ自身のログはアプリのプロセスのもの、生成と会話のログは aibow-server のプロセスのもの。変える人と変えられる人もプロセスで分かれる

## 決定事項(ユーザーと決めたこと。2026-11-21)

1. **起動したあとに画面から変える**。起動したときのレベルの決め方(dev / exe の既定・`-debug`・`server.json` の `logLevel`)は変えない
2. **変えたレベルは保存しない**。再起動すると、起動したときのレベルに戻る
3. **アプリのログは、サーバーモードのときも画面で選んだレベルで動く**(アプリのプロセスのログ。aibow-server のログには効かない)
4. **aibow-server のログのレベルは管理者だけが変えられる**
5. **選べるのは trace・debug・info・notice・warn・error の6つ**。Trace は今使っているところが無いが、使うかもしれないので出す
6. **aibow-mcp は起動の引数でレベルを決める**(Info で固定にしない)。aibow-mcp を起動するのは MCP のクライアント(Claude Code・mcp.json に足した aibow など)で、アプリの組み込みのツールは exe を使わずメモリの中の MCP で動くので、画面から起動中の aibow-mcp は変えられない
7. **Debug・Trace にしても、画面に断りは出さない**(サーバーで管理者が Debug にすると、ほかの人の MCP のやり取りの中身(ツールの引数と結果)が aibow-server のログに残るが、それでも出さない)
8. **aibow-server のレベルは、ブラウザの管理の画面で変える**。サーバーモードのデスクトップのアプリには出さない(管理の画面は今ブラウザだけにあり、サーバーの管理の作業は管理の画面に集める。0032・0046 の形のまま。もとの未決事項 1)
9. **Info にしたときの Wails の `[AssetFileServerFS] Handling request` の行は、今回は絞らない**(exe で Info にすると、画面のファイルを読むたびに十数行がファイルに入る。0008 のやり残しの 5 のまま。困ったら別に絞る。もとの未決事項 2)

## 決定事項(話の流れから Code が決めて書いたこと。作る前にユーザーに確かめる)

### レベルを変える仕組み(`aibow/log`)

10. `Init` で、`Options.Root` を初めの値にした `slog.LevelVar` を作り、出口(ファイル・標準エラー出力)の両方に渡す。
   `log.SetLevel(slog.Level)` と `log.Level() slog.Level` を足す。`SetLevel` は、標準の log から来る行(WebView2 の行など)のレベル(`slog.SetLogLoggerLevel`)も同じ値に合わせる(0008 の決定事項のとおり、exe でもその行を捨てないため)
11. `Init` を呼んでいないとき(ライブラリとして使う人)は、`SetLevel` は何もしない(出口を決めるのは使う人。`SetLogger` の出し先のレベルは使う人が決める)
12. **変えたことは Notice で残す**(「利用者が変えた設定」は Notice、の決まりのとおり)。文は「ログのレベルを Notice から Debug に変えました」。aibow-server では誰が変えたかも添える。
    出るほうのレベルのときに書く:詳しくするとき(Notice → Debug など)は変えたあと、絞るとき(Debug → Warn など)は変える前に書く(Warn にしたあとに Notice で書くと捨てられるため)。Warn → Error のように両方とも Notice より上なら、残らない
13. 名前とレベルの対応(`trace`〜`error`)は1か所に置き、aibow-server の `server.json`・aibow-mcp の引数・画面で同じものを使う。
    `server.json` の `logLevel` にも `trace` を書けるようにする(書ける値を1つ足すだけで、今の値の意味は変えない)

### アプリのログ(デスクトップのアプリ)

14. 設定の画面の「基本設定」のタブに「ログのレベル」の選択を置く(デスクトップのアプリだけ。アプリモード・サーバーモードのどちらでも出す)。開いたときは今のレベルを選んだ状態にする。
    6つの段階の意味はマウスを乗せた説明に出す(画面に説明文は書かない)
15. 画面から呼ぶメソッドは `ui.Service` ではなく `_cmd/aibow` の `ChatService` に置く。
    `ui.Service` のメソッドはブラウザからも `/_aibow/ui/call/{メソッド}` で呼べるので、そこに置くとブラウザから aibow-server のプロセスのレベルを変えられてしまう
16. ブラウザの画面には「アプリのログ」を出さない(ブラウザにはアプリのプロセスが無い)

### aibow-server のログ

17. 管理の画面に「ログ」のタブを足し、「ログのレベル」の選択を置く。出す人は管理の画面の「モデル」のタブと同じ(ログインした管理者と、ログインなしで使うときの画面。`Caller.ManagesPC`)。
    後で「画面からログを見る」(0008 のやり残しの 6)を作るなら、このタブに置ける
18. メソッドは `ui.Service` に置き(aibow-server の中で動き、aibow-server のプロセスのレベルを変える)、Go の側でも `ManagesPC` を確かめる(画面で隠すだけにしない)。デスクトップのアプリからは使わない(決定事項 8)

### aibow-mcp

19. `-log-level <名前>` の引数を足す(`aibow-mcp -log-level debug [作業フォルダ]`)。書かなければ今と同じ Info。知らない名前なら、書ける値を添えて起動を止める
20. 環境変数(`AIBOW_LOG_LEVEL` のようなもの)は足さない。`AIBOW_` の環境変数はアプリと aibow-server も同じ名前を読むので、同じターミナルから起動するとほかにも効いてしまう
