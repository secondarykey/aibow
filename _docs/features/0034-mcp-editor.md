## 目的

今は MCP のサーバーを足すのに `settings.json` を手で書き、アプリを起動し直す必要がある(2026-11-01、ユーザーの要望)。
**アプリの設定の画面から、MCP のサーバーを足す・変える・消す・試しにつなげるようにする**。
aibow-server(`server.json`)の分は、あとで同じ部品で作る(今回は作らない)。

学ぶこと:

- **設定の置き場所を1つにする**:画面から変えるものは、aibow が書くファイル(`mcp.json`)に置く。`tools.json`・`connection.json` と同じ考え方。
  手で settings.json に書いたサーバーも、起動したときに mcp.json へ移す(決定事項 13。2026-11-03 に改めた)
- **動いている仕組みに設定の変更を流す**:今は起動したときだけ読んで `Manager` の名前の一覧を固定で持っている。変えたら、そのサーバーだけ止めて、次の送信で起動し直す(KV キャッシュの話と同じで、「何が変わったら作り直すか」を決める練習)
- **既製の形に合わせる利点**:`mcpServers` の形は Claude Desktop などと同じなので、MCP サーバーの説明にある JSON をそのまま貼れる

## 今の作り(2026-11-02、Chat がコードを読んで確かめた)

- `settings.json`(`%APPDATA%\aibow\settings.json`・`AIBOW_SETTINGS`)の `mcpServers` を、起動したときに `aibow.LoadSettingsFile` で読む。`serverUrl`・`serverKey`・`serverCert` と同居している
- 確かめるのは `aibow.CheckMCPServers`(名前の重なり・`ServerConfig.Validate`)。アプリと aibow-server(`server.json`)で共有している
- `_cmd/aibow/main.go` の `startMCP` が `client.New(configs)` で `Manager` を作る。**サーバーが1つも無ければ `Manager` を作らない(nil)**。`Manager` は名前の一覧 `names` を作ったときに固定で持つ
- 会話の仕組みは `RemoteTools`(`Servers`・`Start`・`Tools`・`ListTools`)だけを見る。`ListTools` は「一時的に起動して一覧だけ受け取り、すぐ止める」(設定の画面で使っている)
- 足したばかりのサーバーは、`tools.json` の `seen` に無ければ `notDefault` に入れる(`ToolPrefs.NoteServers`。起動したときだけ呼ばれる)
- 設定の画面のタブは「基本設定・モデル・会話・サーバー・グループ・アカウント」(`SettingsView.tsx`)。MCP のサーバーの一覧は、会話の「ツール」(`ProfileTools.tsx`)に出る

## 決定事項

ユーザーと決めたこと(2026-11-01・02):

1. **アプリ側(settings.json の分)から作る**。aibow-server(server.json)の分は、あとで同じ部品を使って作る(今回はやらない)

話の流れから Chat が決めて書いたこと(2026-11-03 にユーザーが確かめた):

2. **権限の仕組みは作らない**。アプリを使う人 = その PC で決める人で、command はその人が自分の PC で動かすだけ(手で書くのと同じ)。
   アプリが aibow-server につないでいる(`serverUrl`)ときも、MCP のサーバーは手元で動くので同じように使える。ブラウザ(aibow-server の画面)にはこの画面を出さない
3. **置き場所は設定の画面の新しいタブ「MCP」**(アプリだけ)。会話の「ツール」は扱い(使う・確認する)を決める場所、「MCP」はサーバーそのものを足す場所、と分ける。
   「MCP」で変えたら、会話の「ツール」と入力欄の上の「この会話のツール」の一覧にもすぐ出る(今の `onToolsChanged` の流れ)
4. **部品は aibow-server でも使える形にする**:
   - Go:`mcpServers` だけのファイルを読む・書く係を、アプリに縛らない形で作る(パスを受け取る。aibow-server では `server-mcp.json` に使う見込み)。確かめるのは今の `CheckMCPServers` をそのまま使う
   - 画面:一覧・フォーム・JSON を貼る欄・試しにつなぐ、を1つの部品にし、呼ぶ口(一覧・保存・消す・試す)を外から渡す形にする(`ServerTools.tsx` と `ProfileTools.tsx` のように、アプリとブラウザで中身を分けない)

ユーザーと決めたこと(2026-11-02。Chat のおすすめをユーザーが選んだ):

5. **書く先は、aibow が書く新しいファイル `mcp.json`**(`%APPDATA%\aibow\mcp.json`・環境変数 `AIBOW_MCP`)。
   形は `{"mcpServers": {...}}`(settings.json と同じ形。そのまま写し合える)。書き方は `tools.json` と同じ(一時ファイルに書いてから名前を変える)。
   `settings.json` の `mcpServers` も今までどおり読む。両方を合わせたものを `Manager` に渡す(2026-11-03 に、読んだら mcp.json へ移すに改めた。決定事項 13)
6. **反映は、保存したらすぐ**(起動し直さない)。
   - 足した:次にそのサーバーを使う送信で起動する(今までと同じ)
   - 変えた・消した:動いていればすぐ止める。止めたサーバーのツールを実行中だった送信には、ツールのエラーとして返る(落ちたときと同じ扱い。0006)
   - 名前の順は毎回同じに保つ(ツールの並びが変わると KV キャッシュが効かなくなるため。足したり消したりで並びが変わるのは仕方ない)
7. **JSON を貼る欄を作る**。受け付ける形は3つ:
   `{"mcpServers": {"名前": {...}}}`(説明によくある形)/ `{"名前": {...}}` / `{"command": ...}` か `{"url": ...}` だけ(この形は名前を打つ)。
   貼ったら読み取って、フォームに入れる(1つのとき)か、足すサーバーの一覧を出して確かめてから足す(いくつかのとき)。
   今ある名前と同じなら、そのサーバーは足さずに理由を出す(上書きはしない。変えるときはフォームで)
8. **「試しにつなぐ」ボタンを作る**。保存する前のフォームの中身で、一時的に起動して一覧だけ受け取って止める(今の `ListTools` と同じ動き。保存していない設定を受け取れる形にする)。
   成功ならツールの数と名前、失敗ならエラーの最後の行(今の起動の失敗のお知らせと同じ文)を出す。`${workdir}` を使うサーバーは空の一時フォルダで試す(今の `ListTools` と同じ)。
   試しただけでは何も書かない。保存したときに、そのとき受け取った一覧を `tools.json` の `known` に覚えてよい(Code が決めてよい)

それ以外に Chat が決めて書いたこと:

9. **フォームの項目**:名前・種類(command / url)・command・args(1行に1つ)・env(キーと値の組)・url・headers(キーと値の組)・startupTimeout・callTimeout(秒。空なら 60)。
   `type` はフォームに出さない(種類で決まる。貼った JSON に書いてあれば `Validate` で確かめる)
10. **秘密の値は伏せ字で出す**:headers の値と env の値は、一覧とフォームで伏せ字にする。変えるときだけ打つ(空のまま保存したら前の値のまま)。
    `mcp.json` には settings.json と同じく平文で書かれることを、画面に一言添える
11. **名前は変えられない**(変えるときは消して足し直す)。名前は会話の設定(`mcp_servers`)と `tools.json` の扱いのキーになっているため。
    消しても `tools.json` の扱いと `seen` は残す(今の「settings.json から消しても残す」と同じ)
12. **画面から足したサーバーも、新しい会話で最初から使わない**(今の `NoteServers` の決まり。2026-10-15、ユーザーの指示)。保存したときに `NoteServers` を呼び、お知らせを出す
13. **settings.json に手で書いたサーバーは、起動したときに mcp.json へ移し、settings.json からは `mcpServers` を消す**(2026-11-03、ユーザーが決めた)。
    移したあとは、画面から足したものと同じく変える・消すができる。settings.json のほかの項目(`serverUrl` など)は、並びも値もそのまま残す。
    あとで settings.json に手で書いても、次の起動で同じように移る(説明にある JSON を settings.json に貼る、今までの足し方も使える)。

    改めた理由:もとは「settings.json の分は一覧に印を付けて出し、画面からは変えも消しもしない(手で書いた JSON を書き戻すと、並びや書き方を壊すため)」としていた。
    これはユーザーが決めたことではなく、0032 の決定事項 10(server.json の項目を**今回は**画面に出さない)を Chat が原則にしたもので、確かめずに作った。
    書き戻して失うのは並びと字下げくらいで、知らない項目も残せる。一方、置き場所が2つあると、画面から消せないサーバーや「使われていない」サーバーができて分かりにくい。
    mcp.json で管理するなら、settings.json に MCP のサーバーを置き続ける理由は無い、とユーザーと確かめた
14. **保存の前に確かめる**:今の `CheckMCPServers` を、settings.json の分と合わせた全体にかける(名前がツールの名前で重なる・`${workdir}` を url に書いた、など)。エラーなら保存しない
15. **`Manager` はサーバーが無くても作る**(画面から最初の1つを足せるように)。会話の仕組みの `remote == nil` の分かれ道は、空の `Manager` で同じ動きになるなら消してよい(Code が決めてよい)
16. **`mcp.json` が壊れていたら**、お知らせで伝えて `mcp.json` の分を使わずに起動し、画面からは保存させない(壊れたファイルを上書きしない。`tools.json` と同じ)
