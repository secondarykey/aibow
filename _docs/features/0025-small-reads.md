# 0025: 読む資料を小さくし、長い結果で詰まらないようにする(TODO.md を短い入口に・ツールの結果の立て直し)

- 状態: ✅ 完了(2026-10-26)
- 決めた日: 2026-10-26(Code でユーザーと決めた。0024 の 12-2 の前に済ませる、とユーザーが決めた)
- きっかけ:0024 を作る前の試し(`_docs/tuning.md` の「仕様の相談を試す」)。会話の上限 8,192 で、ローカルのモデルがリポジトリの資料を読んで仕様の相談をすると詰まった
- 前提:0005(作業フォルダのツール・`read_file`)、0002(会話の上限・compact)、0024(サーバーの資料のフォルダを読む会話)

## 目的

ローカルのモデル(と新しい Chat のセッション)が、会話の上限の中でリポジトリの資料を読み進められるようにする。
12-2(サーバーの資料のフォルダをブラウザの会話で読む)の前に済ませておくと、その試しがそのまま楽になる。

学ぶこと:

- **入口の資料の大きさも、会話の上限の一部**:人が読む前提で書き足してきた文書は、モデルにとっては毎回読み直す重い入力になる
- **断るより、渡せる分を渡して続きの取り方を教える**:小さいモデルは「範囲を絞って」のような曖昧な指示では、呼び出しをどう変えればよいか決められない

## 決定事項(ユーザーと決めたこと。2026-10-26)

### TODO.md を短い入口にする

1. **TODO.md の行は「状態・一言・仕様へのリンク」だけにする**
2. **長い中身は消さずに移す**。段ごとの経過と決めたことは、その行が指していた仕様のファイルの末尾の「経過(TODO.md から移した)」へそのまま移す。
   仕様の無い行(ロードマップの外の検討メモ)の中身は、新しい `_docs/backlog.md` へ移し、TODO.md からはそこへリンクする
3. **末尾の「2-3 以降のために決まっていること」(全部が仕様に反映済み)と、2-2 の注記は消す**(git の履歴に残る)

### ツールの結果が会話の上限に入らないとき

4. **断らずに、残りに入る長さで結果を切って渡し、どこで切ったかと続きの取り方を添える**(今は結果を捨てて「範囲を絞って呼び直して」とだけ返している)。
   MCP の結果も同じ仕組みで切る。ツールの引数は増やさない
   - `read_file` の結果は行の切れ目で切り、「続きは offset=N で読めます」と具体的な数で伝える
   - 残りがほとんど無く、何も渡せないときは、今と同じく渡さずに、残りのトークン数を具体的に書いて伝える
5. **`read_file` は長い行を分けて数える**。1行が長いとき(TODO.md の行のように数千文字)は、決まった文字数ごとに分けて別の行として番号を付ける。
   切った行の続きも、次の呼び出しの offset で読めるようにするため(今は 8,000 文字を超える行は途中で切り、その続きを読む手段が無い)
6. **同じ呼び出しが同じエラーで2回続いたら、1回の送信のツールの上限(20 回)を待たずに止め、理由と対処を画面に出す**(会話の上限を上げる・読む範囲を指定して頼み直す)

## 決定事項(Code が決めたこと。2026-10-26)

7. `read_file` が行を分ける幅は 1,000 文字(会話の上限 8,192 で、残りが 2,000 トークンほどでも1つの行が入る大きさ)。分けた行には、続きの行であることが分かる印を付けず、ただ番号を進める(説明に書く)
8. 切ったことはログ(Info)にも出す(結果のトークン数・残りのトークン数・渡した文字数)
9. 切るのは残りの 3/4 まで。残りを全部使うと、モデルが次に書く呼び出しや答えが入らず、次の回の確かめ(`checkFits`)で止まるため(テストで、答えを足すと上限を超えた)
10. 何も渡せないときの文は「ここまでに分かったことで答えてください」にする(残りが無いので、呼び直しても読めない)
11. **何も渡せなかったら、その送信の次の生成ではツールを見せない**(設定は保存しない。プロンプトからツールの説明も外れる)。それでもツールを呼んだら、実行せずに理由を出して止める。
    試しで、4B が「答えてください」を読んでもツールを呼び、会話の上限を超えて答えが出ないまま終わったため(`_docs/tuning.md` の「0025 のあとで試す」)

## やらないこと(先回りしない)

- ツールに文字数で絞る引数(`max_chars` など)を足す
- 今の組の中の compact(古いツールの結果を「(省略)」に置き換えて続ける。`_docs/backlog.md` の「今の組の中の compact」)
- 返事のたびに読み直す遅さ(0024 の未決事項。0023 と KV キャッシュの使い回しで扱う)
