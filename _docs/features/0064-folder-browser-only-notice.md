## 目的

サーバーモードのアプリとブラウザは、同じ aibow-server の `server.db` に会話を置くので、ブラウザで作った会話もアプリの一覧に出る。
ところが、ツールが動く場所は「どの画面で開いたか」で決まる(ブラウザならサーバーの資料のフォルダ、アプリなら手元のワークスペース)。
アプリで開いても、その会話がサーバーのフォルダを使う会話だったと分からず、**サーバーのフォルダのつもりで手元のファイルを読み書きしてしまう**おそれがある(2026-11-25、ユーザーの指摘)。

仕様(アプリはツールを手元で動かす)は今のままにし、開いたその場で「ここでは資料のフォルダは使えない」と分かるようにする。

学ぶこと:

- **同じデータでも、開いた側で意味が変わることがある**:会話は共有でも、ツール(手)は開いた側の PC にある。KV キャッシュがサーバーにあっても、ファイルを開くのは手元、というのと同じ分け方
- **困る瞬間に知らせる**:一覧の印より、そのフォルダを使おうとする入力欄の上で知らせるほうが、取り違えを防げる

## 今の作り(2026-11-25、Chat がコードを読んで確かめた)

- 資料のフォルダを作業フォルダにする処理(`IgnoreWorkDir`・`SetFolders`)は、aibow-server の中のブラウザの会話(`ui.Options.Browser`)だけで動く。アプリでは配布プロファイルの `Rules.Folder` を誰も引かない
- 画面では、ブラウザのときだけ `folder`(開いている会話は Go の `ConversationDetail.Folder`、新しい会話の画面は `grantedFolder(profile)`)を作り、入力欄の上に `FolderBar`(押せない名前)を出す。アプリでは `folder` をいつも空にし、`WorkspaceBar` を出す(`App.tsx` の `composer-top`)
- 会話のプロファイル(`convs.current.profile`、新しい会話の画面では選んだプロファイル)は、サーバーモードのアプリでも aibow-server から届く。配布プロファイルなら `share`・`withdrawn`・`rules.folder` も入っている

   文の形は「資料のフォルダ『名前』はブラウザでだけ使えます(ここでは手元のフォルダ)」

   開いている会話にも、新しい会話の画面(選んだプロファイル)にも出す。配布をやめた(`withdrawn`)プロファイルの会話には出さない(ブラウザでも使えないため)

5. **ワークスペースのバー(`WorkspaceBar`)はそのまま出し、その右に知らせを並べる**。アプリではツールが手元のワークスペースで動くので、選ぶ手段は残す。知らせは押せない(`FolderBar` と同じく選べるものではない)

   「この会話のツールはこの PC で動くので、aibow-server の資料のフォルダは読み書きできません。資料のフォルダを使うときは、ブラウザで aibow-server を開いてこの会話を続けてください」

7. **アプリのモデルに渡すプロンプトは変えない**(環境の説明に資料のフォルダのことを足さない)。手元のワークスペースで動くことはモデルには今までどおり。知らせるのは使う人だけ
8. ログは出さない(開くたびに出る見た目の知らせなので。0053 の「ログは後から追いたい出来事」)
