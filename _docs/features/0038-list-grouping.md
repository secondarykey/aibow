# 0038: 会話の一覧の並べ方(新しい順 / ワークスペースごと)

- 状態: 🔧 作業中(2026-11-03。作った。ユーザーが画面で確かめるのを待っている)
- 決めた日: 2026-11-03(ユーザーの要望。Code のセッションで、backlog の検討メモから実装に入った。決めたことの多くは Code が仮に決めたもので、下に分けて書く)
- 前提: 0035(ワークスペース。会話は ID だけを持ち、名前とフォルダは PC の `workspaces.json`)、0024(ブラウザの会話は資料のフォルダでワークスペースを使わない)

## 目的

会話の一覧を、今のフラットな表示(新しい順)と、ワークスペースごとにまとめた表示とで切り替えられるようにする。

学ぶこと:

- **見せ方と持ち方を分ける**:会話の保存の形(会話がワークスペースの ID を持つ)は変えず、画面の側でまとめ直すだけで別の見せ方が作れる
- **PC のものと人のものを分ける**:ワークスペースは PC のもの、会話は人のもの。まとまりの中身は PC によって変わる

## 決定事項(ユーザーと決めたこと)

1. **表示の仕方の1つとして扱う**。プロジェクト(backlog の「共有の再検討」で出た、まだ無い概念)との関係はここでは考えない。
   プロジェクトができたら、同じ切り替えに「プロジェクトごと」の表示を足せる、というイメージ(2026-11-03)

## 決定事項(Code が仮に決めたこと。ユーザーの確認待ち)

2. **並べ方は、一覧の上の右端(ハンバーガーの反対側)のメニューで選ぶ**。ボタンは今の並べ方のアイコン(新しい順 `LuList`・ワークスペースごと `LuFolderTree`)。
   2つでも切り替えのボタンにせずメニューにしたのは、決定事項 1 の「プロジェクトごと」を足せるようにするため(`conversationGroups.ts` の `LIST_GROUPINGS` に並べる)
3. **並べ方は PC ごとに localStorage に覚える**(`aibow.listGrouping`。一覧の幅・開いているかと同じ「見た目の好み」)。
   backlog では「画面で変える設定なので DB(人ごと)」と書いていたが、ワークスペースは PC のものなので、人ごとにすると、ワークスペースの無いほかの PC でも
   「ワークスペースごと」になってしまう。PC ごとのほうが中身と合う。DB に置かないので、Go とバインディングは変えていない
4. **まとまりの並び**:この PC のワークスペース(中のいちばん新しい会話の順)→ 会話の無いワークスペース(名前の順。「+」で始められるように出す)→
   「ワークスペースなし」→「この PC に無いワークスペース」。後ろの2つは会話があるときだけ出す。まとまりの中は今と同じ新しい順
5. **「この PC に無いワークスペース」は1つにまとめる**:別の PC で選んだワークスペースと、消したワークスペース(0035 では会話は消さず ID が残る)は、
   この PC では名前が分からない(名前はその PC の `workspaces.json` にしか無い)ので見分けない
6. **まとまりの見出しを押すと開け閉めする**。畳んだまとまりも PC ごとに覚える(`aibow.listGroupsClosed`)。畳んだ見出しには、中の会話のいちばん気にしてほしい印
   (確認待ち → エラー → 生成中 → 終わった。畳んだ一覧のハンバーガーと同じ)を出す
7. **開いた会話・生成を始めた会話のまとまりは自動で開く**。開くのは、会話を開いた・生成を始めた・F2 で名前を変え始めた・開いている会話のワークスペースを変えたときの1回だけで、
   そのあと畳めば畳んだまま(読み直すたびに開き直すと、畳めなくなるため)
8. **見出しの「+」で、そのワークスペースを選んだ新しい会話の画面に移る**(ワークスペースのまとまりだけ)。0035 の「前回のワークスペースを最初から選ばない」とは別
   (利用者がワークスペースを選んで押しているので)。上の「+ 新規」は今までどおり選ばず、新しい会話の画面で押したときも、選んでいたワークスペースを外す
9. **新しい会話の画面でプロファイルを選び直しても、選んだワークスペースを残す**(ワークスペースはプロファイルに入らない。0035)。
   前は選び直すと外れていた。「+」で選んでからプロファイルを変えたときに外れないように直した
10. **開いている会話のワークスペースを入力欄の上で変えたら、一覧を読み直す前にすぐ移す**(設定の保存は少し待ってまとめるので、一覧の読み直しを待つと遅れる)
11. **ブラウザ(aibow-server)ではメニューを出さず、いつも新しい順**(ブラウザの会話はワークスペースを使わない。0024)。
    画面のアプリを aibow-server につないだときは出す(ワークスペースはアプリの PC のもの)
12. **一覧を畳んだ細い列は、並べ方によらず今のまま**
13. **共有された会話の欄は今のまま、一覧の下に別に置く**(ほかの人の会話は、自分の PC のワークスペースに関係しない)

## やらないこと(先回りしない)

- プロジェクトごとの表示(プロジェクトを作るとき)
- まとまりの中の並び替え・まとまりの並びを手で変える
- 会話の検索・絞り込み(0003)
- 「この PC に無いワークスペース」の会話を、この PC のワークスペースへまとめて付け替える操作

## 完了の条件

1. 一覧の上のメニューで「新しい順」と「ワークスペースごと」を切り替えられ、次の起動でも同じ並べ方で開く
2. ワークスペースごとのとき、決定事項 4・5 の順にまとまり、見出しで開け閉めでき、開け閉めが次の起動でも残る
3. 畳んだまとまりの会話を開く・生成を始めると、そのまとまりが開く。開いている会話のワークスペースを変えると、すぐそのまとまりへ移る
4. 見出しの「+」で、そのワークスペースを選んだ新しい会話の画面になり、上の「+ 新規」では選ばない
5. ブラウザでは今までどおり(メニューが出ない)
6. `_docs/ui.md`・`TODO.md`・`_docs/backlog.md` を更新している
7. ユーザーが画面で確かめる
