# 0066: MCP のサーバーの説明(instructions)をモデルに渡す

- 状態: 🔧 作業中
- ロードマップ: ロードマップの外(MCP のクライアントの続き。0006・0034)
- 決めた日: 2026-11-26(ほかのセッションからの依頼を受けて、Claude Code が今のコードを読んで案を出し、迷うところをユーザーに確かめた)
- 前提: 0006(MCP のクライアント)、0007・0045(自作の MCP サーバー。`mcp/server` の `Options.Instructions`)、0041(システムプロンプトの環境の説明と作業の決まり)、0024(aibow-server の `server.json` の `mcpServers`)

## 目的

MCP のサーバーは、つないだときの返事(`initialize` の結果。2026-07-28 版からは `server/discover` の結果)に、
サーバーの使い方の説明 `instructions` を入れて渡せる。ツールの説明だけでは伝えきれない前提
(扱うデータの形・本文に書ける記法・ツールを呼ぶ順番・作業の終わりに記録するツールを呼ぶ・消すのは頼まれたときだけ、など)を書いておく場所。

aibow は今、これを受け取っても使っていない(`mcp/client` に `Instructions` を読む箇所が無い)。
そのため、説明に前提を書いているサーバーでは、ユーザーがその文を会話かプロファイルのシステムプロンプトに手で貼っている。
**会話で選んだサーバーの説明を、aibow がシステムプロンプトに足す**ことで、この手間を無くす。

特定のサーバーに合わせた扱いはせず、MCP の `instructions` 一般の扱いとして作る。

学ぶこと:

- **MCP のサーバーは、ツールのほかに「使い方の説明」も渡せる**:クライアント(Claude Code など)はこれをモデルに見せる。ツールの説明はツールごと、サーバーの説明はサーバー全体の前提
- **説明も会話の上限を使う**:ツールの定義と同じく毎回プロンプトに入るので、選んでいないサーバーの説明は入れない。長すぎる説明は切る

## 今の作り(2026-11-26、コードを読んで確かめた)

- `mcp/client` の `Manager.connect` は、つないだあと `session.InitializeResult()` から版とサーバーの名前だけを読んでログに出す。`Instructions` は読まない。
  SDK(v1.8.0)は、古い版の `initialize` でも新しい版の `server/discover` でも、`InitializeResult().Instructions` に説明を入れる
- システムプロンプトは `prompt.go` の `systemPrompt` が組み立てる:会話の設定の `System` → `# Environment`(作業フォルダがあり、時刻・計算のほかにツールがあるとき)→ `# Working rules`(書き換えるツールがあるとき。0041)
- 会話で使う MCP のツールは `toolsFor` が決める(会話で選んだサーバー・起動済み・「使わない」にしていないツール)。サーバーは送信の前に起動する(`startRemote`)
- aibow-server のブラウザの会話も、同じ `Conversations` と `client.Manager`(`server.json` の `mcpServers`)を使う
- 組み込みのツール(aibow の中の自作サーバー。`client.Local`)は `RemoteTools` を通らない。自作サーバーの説明(作業フォルダとシェル)は、aibow では `# Environment` が同じことを書いている

## 決定事項(ユーザーと決めたこと。2026-11-26)

1. **長さの上限は 4,096 文字**(Claude Code と同じ)。超えたら先頭の 4,096 文字だけを渡し、ログに Warn を出す
2. **置き場所はシステムプロンプトのいちばん後ろ**(`# Working rules` の後ろ)。サーバーを足し引きしても、前の部分の KV キャッシュが崩れにくいため
3. **見出しは `# MCP server instructions` の下に、サーバーごとに `## <サーバーの名前>`**。名前は `mcp.json`(`server.json`)のサーバーの名前で、モデルに見せるツールの名前の頭(`<名前>__<ツール>`)と同じ
4. **サーバーごとに「説明を渡さない」を選ぶ設定は、今回は作らない**(要ると分かったら backlog に)

## 決定事項(話の流れから Claude Code が決めて書いたこと。2026-11-26)

5. **入れる条件は「この会話で、そのサーバーのツールを1つ以上モデルに渡しているとき」**(`toolsFor` の結果に、そのサーバーのツールがある)。
   会話で選んでいない・まだ起動していない・ツールを全部「使わない」にした・プロファイルで使えないサーバーの説明は入れない。
   aibow はサーバーのツールしか使わない(resources・prompts は使わない)ので、ツールを渡さないサーバーの説明は役に立たず、会話の上限を使うだけのため
6. **並びはサーバーの名前の順**(ツールの並びと同じ。毎回同じ順にして KV キャッシュを効かせる)。説明が空のサーバーは見出しも出さない
7. **節の頭に1行の前置きを英語で書く**(環境の説明・作業の決まりと同じく英語):
   `The following MCP servers have provided instructions for how to use their tools (each tool name starts with the server name and "__"):`。
   説明はサーバーが書いたまま(前後の空白だけ落とす)。小さいモデルが、見出しの名前とツールの名前の頭を結び付けられるように、名前の付け方を添える
8. **`${workdir}` ごとに起動するサーバー・url のサーバー・aibow-server のブラウザから使う会話でも同じ**(同じ `Manager` と `Conversations` を通るので、分けない)。
   `${workdir}` ごとのサーバーは、その会話の作業フォルダで起動したものの説明を使う(フォルダごとに説明が違ってもよい)
9. **「モデルに渡した文字列」にもそのまま出る**(システムプロンプトの一部なので、特別なことはしない)。メーター(会話の上限)にも入る
10. **説明はつないだときに1回受け取り、サーバーを止めるまで同じものを使う**(ツールの一覧と同じ)。サーバーが落ちてつなぎ直したら、そのとき受け取り直す
11. **ログ**:つながったときの Notice の行に説明の文字数を添える(説明があるときだけ)。送信ごとのシステムプロンプトのトークン数のログ(0041 の `logSystemParts`)に、サーバーの説明の分も足す(Info。学習用)
12. **組み込みのツール(`client.Local`)の説明は入れない**。`# Environment` と同じことを書いているため(今までどおり `RemoteTools` を通らない)

## やらないこと(先回りしない)

- サーバーごとに説明を渡さない設定(決定事項 4)
- 設定の画面の MCP のタブ・「接続テスト」に説明を出すこと
- サーバーが説明を途中で変えたことに追従すること(MCP には説明の変更の知らせが無い。つなぎ直したときだけ受け取り直す)
- resources・prompts など、ツールのほかの MCP の機能
