# 0001: 会話を Go 側に移し、SQLite に保存する

- 状態: ✅ 完了
- ロードマップ: ステップ 2-1
- 決めた日: 2026-10-12(Chat でユーザーと相談して決定)

> **0002(compact)で変わったこと**: 返事の上限トークン数は会話ごとの設定からアプリ全体の設定に移った。
> アプリ全体の「コンテキスト長」は「会話の上限 + 返事の上限」から計算するようになり、`AIBOW_CTX` は廃止(`AIBOW_HISTORY_TOKENS` を追加)。
> この仕様の本文は、決めた当時のまま残している。今の決まりは [0002-compact.md](0002-compact.md) と [conversations.md](../conversations.md) を見る。

## 目的

今は会話の履歴を画面(React の `useChat.ts`)が持ち、送信のたびに全部を Go に送っている。
これを Go 側の「会話」に持たせ、SQLite に保存して、アプリを閉じても会話が残るようにする。会話は複数持てるようにする。

学ぶこと:

- モデルは何も覚えていない。「記憶」はアプリ側が管理している、という構造(Claude などのアプリと同じ)
- 2-2(compact)と 2-3(ツール呼び出し)の土台。どちらも Go 側に履歴がないと作れない

## 決定事項

### 会話(セッション)

- 「会話」= ID・タイトル・発言の列・設定をひとまとめにしたもの。複数持てる。Claude の画面の左に並ぶ会話と同じ考え方
- 画面でできること: 会話の一覧、新規作成、切り替え、削除(確認つき)
- タイトルは、最初のユーザー発言の先頭(30 文字程度)を自動で付ける。モデルにタイトルを考えさせることはしない
- 会話の仕組み(履歴の管理、生成の呼び出し、打ち切り時の扱い)はルートの `aibow` パッケージに置く。Wails に依存させない(ステップ6の API からも同じものを使うため)
- `ChatService`(`_cmd/aibow`)は画面と会話の仕組みを中継するだけにする。画面は表示と入力に専念する

### 保存(SQLite)

- ドライバーは `modernc.org/sqlite`(cgo 不要)。標準の `database/sql` 経由で使う。
  今の aibow は C コンパイラなし(`CGO_ENABLED=0`)でビルドできるので、それを保つ。ユーザー承認済みの追加パッケージ
- DB ファイルは `%APPDATA%\aibow\aibow.db`(`os.UserConfigDir()` + `aibow\aibow.db`)。フォルダが無ければ作る
- 環境変数 `AIBOW_DB` で DB ファイルの場所を変えられるようにする(テストや worktree 用)
- 保存の約束(interface)はルートの `aibow` パッケージに置き、SQLite の実装は別パッケージ(例: `store`)に分ける。
  会話の仕組みのテストは、メモリ上の保存先で書けるようにする
- テーブルの作り変えは `PRAGMA user_version` で版を管理する(マイグレーション)。2-2 / 2-3 で必要な列や表は、そのときにマイグレーションで足す。**今は先回りして作らない**

### ID

- Go を **1.27** に上げ、標準の `uuid` パッケージの `uuid.NewV7()` で ID を作る(会話も発言も)。ルートと `_cmd/aibow` の両方の `go.mod`
- v7 は作成順に並ぶので、発言の順番は ID の並びで決める(順番用の列は持たない)
- DB には TEXT(`id.String()`)で保存する。DB を直接のぞいて読めるように。読み出すときは `uuid.Parse()`(`uuid.UUID` は `Scan` / `Value` を持たない)

### テーブル(案。列名や型は実装時に調整してよい)

```
conversations
  id          TEXT PRIMARY KEY   -- UUIDv7
  title       TEXT
  settings    TEXT               -- この会話の設定(JSON)
  created_at  TEXT / updated_at TEXT

messages
  id               TEXT PRIMARY KEY   -- UUIDv7。並び順もこれで決まる
  conversation_id  TEXT REFERENCES conversations(id) ON DELETE CASCADE
  role             TEXT               -- system / user / assistant
  content          TEXT               -- 答え(モデルに渡すのはこれだけ)
  thinking         TEXT               -- 思考。画面で開いて見る用。モデルには渡さない
  model            TEXT               -- どのモデルの返事か(assistant のみ)
  stats            TEXT               -- トークン数・速度・終了理由(JSON。assistant のみ)
  created_at       TEXT

app_settings
  key TEXT PRIMARY KEY, value TEXT    -- アプリ全体の設定(下の「設定」を参照)
```

- 過去の返事の思考は保存し、画面で開いて見られるようにする。モデルに渡す文字列には今どおり入れない(公式テンプレートと同じ)
- 答えが空のまま終わった回(思考の途中で打ち切り・停止)は、今の画面と同じく理由の文を assistant の発言として保存する。この処理を画面から Go に移す

### モデル

- モデルはアプリ全体で1つ(VRAM 8GB に1つしか載らないため)。会話を切り替えてもモデルは読み直さない
- どの返事をどのモデルが書いたかは、発言ごとに `model` に記録する(比べられるように)
- 最後に使ったモデルを `app_settings` に保存し、次の起動時にそれを読み込む(`AIBOW_MODEL` が設定されていればそちらを優先)

### 設定を画面から変えられるようにする

| 設定 | 持ち主 | 変えたときに必要なこと |
|---|---|---|
| システムプロンプト / 返事の上限トークン数 / temperature / 思考 ON/OFF / presence penalty | 会話ごと | なし。次の送信から反映 |
| コンテキスト長 | アプリ全体 | コンテキスト(KV キャッシュ)だけ作り直す。モデル本体は読み直さない。エンジンにそのための関数を足す |
| GPU に載せる層の数 | アプリ全体 | モデルの読み込み直し(モデル切り替えの仕組みを流用) |
| lib / モデルの置き場所 | 環境変数のまま | 再起動が必要 |

- アプリ全体に「新しい会話の既定の設定」を持つ。新しい会話はそれをコピーして始まり、会話の中で変えてもその会話だけに効く
- 環境変数(`AIBOW_CTX` など)は「DB にまだ値が無いときの初期値」として使う。画面で変えたら DB の値が優先
- 打ち切り時のヒント文(今は「AIBOW_MAX_TOKENS / AIBOW_CTX を増やす」)を、画面の設定を案内する文に変える

### 生成

- 生成は同時に1つだけ(エンジンが1つのため)。生成中に別の会話を開いて読むことはできるが、送信はできない(画面で分かるようにする)
- 画面へのイベントには会話の ID を付け、表示中の会話のものだけを画面に出す
- 停止の仕組み(`Call` の `cancel()` → Go の `ctx` のキャンセル)は今のまま

## やらないこと(先回りしない)

- モデルによるタイトルの自動生成、会話の検索・エクスポート・並べ替え
- 複数の会話での同時生成

Code の判断(ユーザーに計画を見せて了承済み):

- 送信がエラーになっても、ユーザーの発言は保存したまま残す(今の画面と同じ)
- ~~「+ 新規」を押した時点で空の会話を DB に作る~~ / ~~起動時は一番新しく更新された会話を開く~~
  → 2026-10-12 にユーザーの依頼で変更: 新しい会話の画面(入力欄が真ん中)を設け、起動時と「+ 新規」はこの画面にする。
  会話はこの画面で最初に送信したときに作る(空の会話を作らない)。この画面で設定パネルを変えると、これから作る会話の設定
  (新しい会話の既定の写し)が変わり、作るときにその設定を渡す。開いていた会話を削除したら、この画面に戻る
- 一覧は更新の新しい順
- 返事の stats(JSON)には GenerateStats に加えて、初回応答の秒数・思考の秒数・答えが出なかった印を入れる(再起動後も表示を作り直すため)
- 「モデルに渡した文字列」は DB に保存せず、画面が会話ごとにメモリに持つ(再起動後は次の送信まで空)
- 削除の確認は WebView の `confirm()` ではなく、一覧の行の中に「削除 / やめる」を出す
- `chat` イベントの `stats` は無くし、`done` に Go が保存した返事(統計つき)を入れる。画面はそれで吹き出しを置き換える
- `ChatEvent` は会話の仕組みが出すものなので、ルートの `aibow` パッケージに置く
- 発言を保存したときは、会話を丸ごと書き戻さず、更新日時と「空のときだけ自動のタイトル」だけを書く(`Store.TouchConversation`)。
  生成中に画面で変えた名前や設定を、生成を始めたときの古い値で上書きしないため

## 完了の条件

1. アプリを再起動しても、会話の一覧と中身(思考を含む)が残っている
2. 会話の新規作成・切り替え・削除ができる。削除は確認してから行う
3. 生成中は、別の会話を読めるが送信はできない
4. 「モデルに渡した文字列」を見ると、過去の思考が入っていない
5. 思考の途中で打ち切られた回は、理由の文が返事として残り、次の送信にも含まれる
6. 返事の上限などは画面で変えると次の送信から効く。コンテキスト長はモデルを読み直さずに変わる。GPU の層数は読み直して変わる
