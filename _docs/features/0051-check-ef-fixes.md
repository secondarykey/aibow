## 目的

チェック E・F で、ユーザーが次の7点に引っかかった(2026-11-21)。

1. aibow-server の `server.json` の `model` に無いモデルを書くと、起動できない
2. 一覧をワークスペースごとに並べたとき、「ワークスペースなし」のまとまりにだけ「+」が無い
3. モードを切り替えたあと、起動し直すまで前のモードのまま動くのが分かりにくく、危ない
4. API キーを使っていないのに、aibow-server のログに「API キーが無いか違うので断りました」がたびたび出る
5. モデルのタブで GPU の層数を変えると「適用」が現れて、行がガタガタする
6. 確認のカードで「同じ答え」にチェックを入れて拒否すると、この会話ではツールが使えなくなり、戻さないといけない
7. 読み込んだ(添付した)ファイルを、あとで保存(ダウンロード)する手段が無い

学ぶこと:

- **止めるより、知らせて続ける**:設定の間違い(無いモデル)は、管理者が直せるように Warn で知らせて動き続けるほうが、何度も起動に失敗するより直しやすい
- **状態が変わったら、古い状態のまま動かない**:トークンを消したのに前の画面のまま動くと、サーバーに断られる呼び出しが出続ける(4 の正体)
- **範囲を選ばせる**:「今後も同じ」は、どこまで続くか(この返事・この会話)を使う人が選べると、押したあとに困らない

## 今の作り(2026-11-21、Chat がコード・ログ・DB を読んで確かめた)

### 1. 起動のときのモデル(`_cmd/aibow-server/main.go` の `firstModel`)

- 指定(`-model`・`server.json` の `model`・`AIBOW_MODEL`)があれば `findArg` で探し、見つからなければエラーで起動を止める
- 管理者が使えないようにしたモデル(`DisabledError`)のときだけは、Warn を出して `firstModel(mm, "")`(使える最初のモデル)に移る
- 2026-11-20 のログでは、`"qwen3.5:4b" が見つかりません。使えるモデル: ` で約2秒おきに起動に失敗し続けていた(置き場所にモデルが無かった時間と、gemma だけがあった時間がある)

### 2. 一覧のまとまりの「+」(`ConversationList.tsx` の `groupHead`)

- 「+」は `g.workspace` があるまとまりだけに出る。「ワークスペースなし」(`key: "none"`・`workspace: ""`)と「見つからない」(`missing`)には出ない
- 「+」は `App.tsx` の `onNewIn(workspace)` で、新しい会話の画面に移ってそのワークスペースを選ぶ

### 3. モードの切り替え(`_cmd/aibow/connection.go`)

- 「アプリモードに戻す」(`DisconnectServer`)は、トークンを aibow-server で消し(`revoke`)、`connection.json` を書き換えて pending にする。**画面はサーバーモードのまま動き続け**、手元の client には消したトークンが残る
- 「接続」(`ConnectServer`)・つなぎ先を変えるときも、起動し直すまで前のモードのまま動く(違うつなぎ先なら前のトークンを消す)
- ログインの画面(`Login.tsx`)は、pending の間はお知らせを出してログインを押せなくする(0047 の決定事項 14)

### 4. 謎のログ(`auth/keys.go` の `RequireKey`)

**デスクトップのアプリ自身の呼び出しだった**。アプリのログインのトークンも API キーと同じ `Authorization: Bearer` で送るので、断ったときのログは「API キー」になる。出ていたのは次の2つの場面(2026-11-21 の両方のログを突き合わせた)。

- サーバーモードでトークンが無いまま起動したとき:ログインの画面を出す前に、設定(`AppSetting`)・プロファイル(`ListProfiles`)・一覧(`ListConversations` × 2。1つは作業フォルダをワークスペースに移す処理)・`/_aibow/auth/key` の5本を呼んで断られる(05:04・08:03・09:13)
- 3 の「アプリモードに戻す」のあと、起動し直すまでの間:画面が一覧・モデル・共有の一覧を読みに行き、消したトークンで断られる(08:25 に戻す → 08:26:20 に8本。ユーザーが見たのはこれ)

### 5. GPU の層数(`ModelSettings.tsx` の `ModelRow`)

- 層数の欄の値が覚えた値と違うときだけ「適用」のボタンを出す(`{n !== layers && <button>適用</button>}`)。出たり消えたりで行の幅が変わる

### 6. 確認のカードの「同じ答え」(0049 で2行にしたカード。`ToolCard.tsx` の `Confirm`・`agent.go` の `Answer`)

- チェック「この会話では、このツールを今後も同じ答えにする」を入れて拒否すると `ToolOff`(この会話ではそのツールをモデルに見せない)。実行すると `ToolAllow`(この会話では聞かない)
- F のチェックの会話では、モデル(9B)が URL を変えながら `fetch_url` を5回呼び、ユーザーは5回目にチェックを入れて拒否した。そのあとは、会話の設定で戻さないと `fetch_url` が使えない

### 7. 読み込んだファイル(`FileChips.tsx`)

- 吹き出しの上の札は、名前・大きさ・(画像は)小さな表示と大きく見る・削除だけ。保存のボタンは無い
- 中身(`File.Data`)は画面がもう持っている(会話を開くと発言と一緒に届く)。テキストは UTF-8 にしたもの(BOM を外す)、画像は読み込んだファイルのまま

### 4. 謎のログ

6. **サーバーモードでトークンが無いまま起動したときは、起動のときの aibow-server への呼び出し(設定・プロファイル・一覧・作業フォルダの移し)をせず、そのままログインの画面にする**。それらはログインしたあとに行う

### 5. GPU の層数

9. **「適用」は常に出しておき、値が変わっていない間は押せなくする**(行の幅を変えない)

### 6. 確認のカードの「同じ答え」

10. **2行目のチェックボックスを、3つから1つ選ぶ形にする**。初めは「しない」

```
[ 拒否の理由(モデルに伝えます。空でも可) ] [拒否]
今後も同じ答えにする:(•) しない ( ) この返事の間 ( ) この会話の間   [実行する]
```

11. 選んだ範囲は、拒否にも実行にも同じように効く

| | 実行する | 拒否 |
|---|---|---|
| しない | この1回だけ実行(今のまま) | この1回だけ拒否(今のまま) |
| この返事の間 | この返事が終わるまで、このツールは聞かずに実行する | この返事が終わるまで、このツールは聞かずに断る。モデルには「ユーザーはこのツールを使わないよう求めています。ツールを使わずに答えてください」のように伝える |
| この会話の間 | 今の「この会話では今後聞かない」(`ToolAllow`) | 今の「今後許可しない」(`ToolOff`。モデルに見せない) |

12. 「この返事の間」は会話の設定に保存しない。aibow の中(会話の仕組みの側。aibow-server でも同じく動くように)で覚え、その返事(送信1回ぶんのツールのループ)が終わったら忘れる

### 7. 添付したファイルの保存

13. **吹き出しの上の札(テキスト・画像)と、画像を大きく見る画面に「保存」を足す**。保存はブラウザのダウンロード(図の保存の `diagramExport.ts` と同じ `<a download>`。WebView2 でも使える)。ファイル名は読み込んだときの名前
14. テキストは UTF-8 にした中身を保存する(UTF-16 で読み込んだファイルは、元のファイルと同じにはならない。吹き出し(title)で知らせる)。削除済みの札には出さない
