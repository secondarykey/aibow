## 目的

今の fetch は公式の MCP のサーバー(`uvx mcp-server-fetch`)頼みで、Python と uv が要る(2026-11-02、ユーザーと話した。backlog の「組み込みの fetch」)。
**URL のページを読むツールを組み込みにし、exe だけで使えるようにする**。ブラウザの会話でも、管理者が MCP のサーバーを置かずに有効にできる。

学ぶこと:

- **ツールの結果の大きさを自分で決める**:ページは長い。本文だけを取り出し、会話の上限に入る分だけ渡して、続きは `start_index` で読ませる(read_file の offset と同じ考え方。0025)
- **HTML から本文を取り出す**:構文解析は既製の部品に任せ、「どこが本文か」(script・style・nav を落とす、main・article を優先する)は自分で書く
- **サーバーから外へ取りに行く危うさ(SSRF)**:モデルが書いた URL で、PC の中や社内のサーバー・クラウドのメタデータ(169.254.169.254)に届いてしまうこと。名前を引いたアドレスを接続の直前に確かめる理由(DNS rebinding)

## 今の作り・調べたこと(2026-11-02、Chat が確かめた)

- 組み込みのツールは `tool` パッケージ。時刻・計算は会話の仕組みの `cs.tools`、作業フォルダがあるときだけフォルダのツールと `run_command`(`agent.go` の `localTools`)。グループは「組み込み」1つ(`tools.json` の `builtin`)
- アプリでは組み込みのツールも aibow の中の MCP サーバー(`mcp/server`)越しに呼び、`tool.Confirmable` のツールはサーバーが確認を求める(MRTR)
- aibow-server のブラウザの会話は、時刻・計算と資料のフォルダのツール・管理者が `server.json` に書いた MCP のサーバー。管理者が「使わない」にしたツールは禁止(0024 の決定事項 22)
- 公式の fetch の MCP サーバー(modelcontextprotocol/servers の `src/fetch/README.md`。2026-11-02 に読んだ):
  - 引数は `url`・`max_length`(既定 5,000 文字)・`start_index`(続きから読む)・`raw`(Markdown にしない)
  - **既定で、グローバルでないアドレス(loopback・private・link-local・100.64.0.0/10・169.254.169.254 など)を断る**。リダイレクトの先も同じに確かめる。`--allow-private-ips` で外す。
    名前を引いた結果を確かめてから接続するので、その間に答えが変わる DNS rebinding は防げない、と書いてある
  - モデルが呼んだ fetch は robots.txt に従う(`--ignore-robots-txt` で外す)
  - backlog に書いていた「fetch サーバーは PC の中やイントラの URL にも届く」は、今の版では既定で断るように変わっていた
- `golang.org/x/net` の最新は v0.62.0(2026-10-27。proxy.golang.org で確かめた)

## 決定事項(ユーザーと決めたこと。2026-11-02)

1. **組み込みのツールとして fetch を作る**(`tool` パッケージ)。検索は作らない(API キーと無料の枠が絡むので MCP のまま)
2. **HTML の読み取りに `golang.org/x/net/html` を足す**(Go チームのパッケージ。cgo なし)。`tool` パッケージだけで使う。HTML の字句と木の組み立てはこれに任せ、本文の取り出しと Markdown への書き直しは自分で書く。
   AGENTS.md の外部パッケージの表に足す
3. **PC の中・社内のアドレスは既定で断る**(公式と同じ範囲)。許すかどうかは設定で決める(アプリはその PC の人、aibow-server は管理者)

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-02 にユーザーが確かめた)

### ツールの形

4. **名前は `fetch_url`、引数は `url`(必須)と `start_index`(省略可。0 から)**。返す長さ(`max_length`)はモデルに選ばせず aibow が決める(既定 5,000 文字。小さなモデルに選ばせると大きすぎる値を書くため)。
   `raw` は作らない(HTML をそのまま渡すと会話の上限をすぐ使い切る)
5. **結果の形**:1行目に最終的な URL(リダイレクトの後)・状態コード・Content-Type、空行をはさんで本文。切ったときは最後に「全体は N 文字です。続きは start_index=M で読めます」。
   英語で書くか日本語で書くかは、ほかのツールの結果に合わせる(Code が決める)
6. **中身の種類ごとの扱い**:HTML は本文を取り出して簡単な Markdown(見出し `#`・段落・リスト・リンク `[文](URL)`・コードブロック・表は行ごとに `|` で区切る)にする。
   `text/*`・JSON・XML はそのまま(UTF-8 にして)。それ以外(画像・PDF・zip など)は「この種類は読めません」のエラー
7. **本文の取り出し**:`script`・`style`・`noscript`・`template`・`svg`・`iframe`・`nav`・`header`・`footer`・`aside`・`form` を落とす。`main` か `article` があればその中だけ(複数あれば最初の `main`、無ければいちばん長い `article`)。
   無ければ `body` 全体。`<title>` は本文の頭に `# 題` で書く。読みやすさの細かい工夫(広告の除き方など)は作らず、試して困ってから足す
8. **上限**:受け取る大きさ 2MB(超えた分は読まずに切る)・時間 15 秒(ツールが自分で数える。`tool.TimeLimiter`)・リダイレクト 5 回・`http` と `https` だけ。
   文字コードは Content-Type と `<meta charset>` を見て、UTF-8 以外は `golang.org/x/net/html/charset` で直す(Shift_JIS の日本のページのため)
9. **User-Agent は `aibow/<版> (+fetch_url)`**。ほかの値にする設定は作らない
10. **robots.txt は見ない**。アプリでは1回ずつ人が確認し、aibow-server では管理者が有効にするため。見ると1回の呼び出しで2回取りに行くことになる

### 安全

11. **断るアドレス**:loopback(127.0.0.0/8・::1)・private(10/8・172.16/12・192.168/16・fc00::/7)・link-local(169.254/16・fe80::/10)・100.64.0.0/10・未指定(0.0.0.0・::)・マルチキャストなど、`netip.Addr` でグローバルでないと分かるもの。
    **接続の直前(`net.Dialer.Control`)に、実際につなぐアドレスで確かめる**。名前を引いてから確かめる形では DNS rebinding を防げないため(公式より一歩進める)。リダイレクトの先も同じ道を通るので自然に確かめられる。
    プロキシ(`HTTPS_PROXY`)は使わない(使うとプロキシのアドレスしか確かめられないため。会社のプロキシの中でしか外に出られない環境は、困ってから考える)
12. **許す設定**:アプリは `settings.json` に手で書く項目(名前は Code が決める。例:`fetchAllowPrivate: true`)、aibow-server は `server.json` の同じ名前の項目。画面からは変えない(めったに使わず、危うさを分かって書く人だけが使う)
13. **アプリでは「確認する」が既定**(`tool.Confirmable`。確認のカードに URL を出す)。書き換えるツールとコマンドと同じ決まりの既定に入れる。「この会話では今後聞かない」や `tools.json` の「確認しない」は今までどおり使える
14. **aibow-server では、管理者が「ツール」のタブで有効にするまで使えない**(既定で禁止。0024 の決定事項 22 の「使わない」と同じ扱い)。有効にしたあとの確認の既定は、アプリと同じ「確認する」
15. **aibow-mcp(MCP のサーバーの exe)では既定で出さない**。引数(例:`-fetch`)を付けたときだけ出す(Claude Code などは自分の fetch を持っているので、出すと重なる)
16. **作業フォルダが無い会話でも出す**(時刻・計算と同じ。調べ物はフォルダと関係ないため)
17. **ページの文はモデルへの指示として働きうる**。書き換え・コマンドの確認は今のまま残し、`_docs/usage.md` に危うさ(ページに書かれた指示で、モデルがファイルを書き換えようとすることがある)を書く
18. **ログ**:取りに行った URL・状態コード・受け取った大きさ・渡した文字数・秒数を Info で。断ったアドレスは Warn。aibow-server では誰の・どの会話のかも(0024 の決定事項 11・19)

## やらないこと(先回りしない)

- 検索(「Web で調べる」は検索の MCP のサーバーとして残す)
- JavaScript で作るページ(ブラウザを動かさない)・ログインが要るページ・cookie・POST
- PDF・画像を読む(0030 の「ファイルを読み込む」と一緒に、あとで)
- 取ってきたページの保存・キャッシュ
- 読みやすさの細かい工夫(Readability のような本文の当て方)
- 社内のアドレスをホストごとに許す表(許すか許さないかの1つだけ)
- プロキシ越しに取りに行く
