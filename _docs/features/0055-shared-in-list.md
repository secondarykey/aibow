## 目的

今は、ほかの人に共有された会話が、会話の一覧の下の「共有された会話」の欄(「自分に共有(n)」と「全員に共有(n)」の段)に分かれている。
自分の会話と共有された会話を行き来するたびに、一覧の上と下を往復することになる。

共有された会話を**自分の会話と同じ一覧に、更新の新しい順で混ぜ**、共有のアイコンで見分けられるようにする。
探すのは「+ 新規」の横の検索ボックス1つにまとめ、自分の会話と共有された会話の両方をタイトルと持ち主の名前で探す。
共有された会話を開いたときの上の帯には、誰から・どう共有されたか(自分あて・グループ・全員)を出す。
あわせて、作り直す会話の一覧に**非アクティブ**という会話の属性を足す。使っていない会話を非アクティブにすると、一覧の下の折りたたみにしまわれる(消さずに残しておく)。
共有の仕組みではなく、一覧の機能。共有された会話にも付けられるようにすれば、ほかの人の「全員に共有」で一覧が埋まるときの片付けにも使える(決定事項 8・16)。

学ぶこと:

- **画面の中で混ぜる**:保存の形(自分の会話 `Conversation` と、ほかの人の会話の見出し `ConversationRef`)は別のまま、画面で1つの列にして並べる。
  認可の判定(store の `conversationShared` の1か所)は変えない
- **一覧の属性**:非アクティブは会話の中身ではなく、一覧での見せ方の属性。会話の中身(発言・設定)とも共有とも関わらない
- **なぜ見えるのかを返す**:今の判定は「見えるか」だけを返している。「自分が相手だから」「グループのメンバーだから」「全員だから」を返すには、同じ条件を分けて読む

## 今の作り(2026-11-22、Chat がコードを読んで確かめた)

- 一覧の下の「共有された会話」の欄(`ConversationList.tsx` の `SharedList` / `SharedGroup`)。ログインしているときだけ(`App.tsx` の `reloadShared`。`me.login` が無ければ取らない)
  - 上に「タイトルで探す…」の欄と、**持ち主で絞る選択**(`<select aria-label="持ち主で絞る">`。先頭の「全員」は「絞らない」の意味。あとは共有された会話の持ち主の表示名)
  - 「自分に共有(n)」(`ConversationRef.Share` が `users`)と「全員に共有(n)」(`all`)の2段。それぞれ新しい 20 件から出し、「もっと見る」で 20 件ずつ足す(`SHARED_PAGE`)
  - 絞り込みと検索は**画面の中だけ**(サーバーで探す API は無い)。検索はタイトルだけ
- 自分の会話の一覧(`useConversations.ts` の `ChatService.Conversations()`)は全件を画面が持っている。検索の欄は無い。自分が共有した会話は名前の右に `LuShare2`
- 共有された会話を押すと `ReadConversation` で読むだけの画面(`ReadView.tsx`)。上の帯は「○○ が共有した会話」だけで、どう共有されたかは出していない
- サーバーは「自分あて」と「グループ経由」を区別して返していない。`ConversationRef.Share` は会話の範囲(`users` / `all`)で、`users` のときに自分が直接の相手か、メンバーのグループが相手かは分からない

## 決定事項(ユーザーと決めたこと。2026-11-22)

1. **共有された会話を通常の会話の一覧に混ぜる**。別の欄・段にしない。「共有された会話」の欄と「自分に共有(n)」「全員に共有(n)」の段は無くす
2. 混ぜた共有された会話には**共有のアイコン**を付けて見分ける
3. 「+ 新規」の横に**検索ボックス**を置き、**自分の会話と共有された会話の両方**を探す
4. 共有された会話を開いたときの上の帯(会話のヘッダー)に、**共有のされ方**(誰から・自分あて / グループ / 全員)を出す
5. **持ち主で絞る選択(「全員」の選択欄)は無くす**。持ち主で探したいときは、検索ボックスに名前を打つ
6. 「全員に共有」で一覧が埋まる心配は、まず混ぜて使ってみてから考える(絞り込みは今は作らない)
7. **非アクティブ**:会話の一覧での会話ごとの属性(共有の仕組みではない)。会話を「非アクティブ」にでき、一覧の折りたたみの中に入る。削除はせず、残しておく使い方
8. 非アクティブは**共有された会話にも付けられる**(付けた人の一覧だけが変わる。2026-11-22、ユーザーが選んだ)

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-22、Code が案として示し、ユーザーが A〜D とも「このままでよい」と確かめた)

### A. 一覧に混ぜる

9. 検索ボックスは**タイトルと持ち主の名前(表示名・ログインの名前)**に当てる(大文字小文字を区別しない部分一致)。自分の会話は持ち主が自分なので、タイトルだけに当たる。
   発言の中身は探さない(0003 の検索で扱う)。画面の中で絞る(今の共有の欄と同じ。サーバーで探す API は作らない)
10. 並びは**更新の新しい順で1列**。自分の会話の `updated_at` と `ConversationRef.UpdatedAt` で混ぜる
11. 共有された会話の行:
   - 名前の右に、自分が共有した会話(今の `LuShare2`)とは**別のアイコン**(受け取った側の印。何にするかは未決事項 1)
   - 名前の下か右に、持ち主の表示名を薄く(今の `shared-owner` と同じ)
   - マウスを乗せた説明は今と同じ「(○○ の会話。読むだけ)」に、共有のされ方を足す(例「佐藤 花子 の会話。営業 グループに共有。読むだけ」)
   - 名前の変更・削除・生成中などの印は出さない(自分の会話ではないので。今の共有の欄と同じ)
   - 押すと今と同じ読むだけの画面(`ReadView`)。開いている間は、その行を選んでいる見た目にする(今の `readingId`)
12. 「もっと見る」(20 件ずつ)は無くす。自分の会話の一覧と同じく全件を出す(1列にしたので、共有されたものだけを途中で切ると並びが崩れる)。
   共有された会話が多くて困るかは、使ってから決める(やらないこと 3)
13. **ワークスペースごとの並べ方**(0038。アプリだけ)では、共有された会話は**「ワークスペースなし」のまとまり**に入れる(ワークスペースは自分の PC のもので、ほかの人の会話には無い)
14. ログインしていないとき(1人の形)は、今と同じく共有された会話を取らない。検索ボックスは出す(自分の会話を探すため)
15. 一覧を畳んでいるとき(細い列)は検索ボックスを出さない(今の「+」だけのまま)

### B. 会話の一覧の非アクティブ(決定事項 7)

16. 非アクティブは**会話の一覧での属性**で、付けた人の一覧にだけ効く。自分の会話に付けられる。
    共有された会話にも付けられる(決定事項 8。その人の一覧だけで、持ち主やほかの相手の一覧は変わらない)。
    保存は、一覧を見る人 + 会話の表 `conversation_inactive`(会話か利用者を消すと一緒に消える。DB の版を上げる)。
    会話の列(`conversations.inactive`)にしないのは、共有された会話にも付けるため(持ち主の列にすると、相手全員の一覧が変わってしまう)。
17. 付ける・外す:一覧の行にマウスを乗せたときに、削除(ゴミ箱)の左に「非アクティブにする」のアイコン(未決事項 4)。折りたたみの中の行は「アクティブに戻す」。
    共有された会話の行は削除を出さないので、このアイコンだけ。確かめは出さない(すぐ戻せるので)
18. 一覧の一番下(「管理者が読めます」の上)に「非アクティブ(n)」の折りたたみ。**最初は閉じている**。開け閉めは PC ごとに覚える(0038 のまとまりと同じ localStorage)。
    中は更新の新しい順。ワークスペースごとの並べ方でも、非アクティブはまとまりから抜いてこの折りたたみに入れる。件数が 0 なら出さない
19. 非アクティブの会話も開ける(自分の会話なら送信もできる)。**送信しても非アクティブのまま**(勝手に戻すと、残しておいたつもりの会話が上に戻ってくるため。戻すのは自分で)。
    開いている間は、折りたたみを開いてその行を選んでいる見た目にする(0038 の「開いた会話のまとまりは自動で開く」と同じ)
20. 検索ボックスは非アクティブの会話にも当てる。当たったものがあれば折りたたみを開いて出す(探して見つからない、をなくす)
21. 共有をやめられた・持ち主が消した会話は一覧から消える(印は表ごと消えるので残らない)。共有し直されたら、前の印が残っていれば非アクティブのまま出る
22. ブラウザ(aibow-server の会話)もアプリモード(手元の SQLite)も同じ。アプリモードの利用者は今の `local`

### C. 共有のされ方を返す

23. `ConversationRef` と `SharedRead` に、**自分に見えている理由**を足す:
    - `ToMe bool`(自分が直接の相手)
    - `Groups []string`(自分がメンバーで、相手に入っているグループの名前。名前順)
    - 範囲が `all` なら今の `Share` で分かるので、足さない
    両方あてはまるときは両方を返す。store の `conversationShared` の判定(見えるか)はそのまま使い、理由は別の副問い合わせで読む(判定の1か所を崩さない)
24. 管理者が読むとき(`ByAdmin`)は理由を返さない(共有されていないので)。今の帯のまま

### D. 読むだけの画面の帯

25. 帯の文(0048 の読む人から見た文):
    - 自分あて:「佐藤 花子 があなたに共有した会話」
    - グループ:「佐藤 花子 が 営業 グループに共有した会話」(複数なら「営業・開発 グループに」、3つ以上は「営業・開発 ほか1グループに」)
    - 自分あてとグループの両方:自分あてを先に出す(「佐藤 花子 があなたと 営業 グループに共有した会話」)
    - 全員:「佐藤 花子 が全員に共有した会話」
    - 管理者として読む:今のまま「管理者として ○○ の会話を読んでいます(記録が残ります)」
26. 一覧の行の説明(決定事項 11)と帯の文は、同じ関数で作る(`directory.ts` の近くに置く)
