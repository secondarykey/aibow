## 目的

設定の画面には、**自分のための設定**と**サーバー管理者の作業**が混ざっている(2026-11-01、ユーザーの指摘)。
利用者の管理はサーバー管理者だけが行う作業で、自分の設定の続きにあるのはおかしい。
サーバー管理者のための「管理」の画面を設定とは別に作り、サーバー全体に関わる作業をそこに集める。

学ぶこと:

- **画面を「だれの作業か」で分ける**:今は同じタブの中で、管理者かどうかで出すものを変えている(モデルのタブ・会話のタブの「配る」)。
  作業する人で画面を分けると、出し分けの条件が画面の入口の1か所にまとまる
- **画面の出し分けと、口の断り**:画面を分けても、断るのは今までどおり Go の口(`onlyAdmin`・`pcMethods`・`adminToolMethods`・store の条件)。画面は出し分けるだけ

## 今の設定の画面にある、サーバー管理者の作業(2026-11-01 の時点)

| 今の場所 | 中身 | 今の出し分け |
|---|---|---|
| 「利用者」のタブ(`UserSettings.tsx`・`GroupSettings.tsx`) | 利用者(作る・リンク・API キー・表示名・メール・消す・その人の会話)・グループ・グループの長 | ブラウザの管理者だけ(`/aibow/admin/` とグループのメソッド) |
| 「モデル」のタブ(`ModelSettings.tsx`) | 読み込む / 降ろす・GPU の層数・置き場所・「使える」のスイッチ | 管理者とサーバーの PC から開いた画面(`models.manage`・`Caller.ManagesPC`)には操作も、ほかの人には一覧だけ。1つのタブに混ざっている |
| 「ツール」のタブ(`ServerTools.tsx`。ブラウザだけ) | ブラウザの会話のツールの扱いの、aibow-server 全体の既定(`server-tools.json`) | 管理者とサーバーの PC から開いた画面が変える。ほかの人は見るだけ |
| 「会話」のタブの「配る」(`ProfileSettings.tsx` の `ShareForm`・資料のフォルダ) | プロファイルを組織に配る・配ったプロファイルを変える・資料のフォルダを選ぶ | 自分のプロファイルの編集の中に、管理者の操作として混ざっている |

## 決定事項(2026-11-01、ユーザーと決めた)

1. **設定とは別に、サーバー管理者のための「管理」の画面を作る**。設定の画面と同じく、会話の場所に出す別の画面(「会話に戻る」で閉じる)
2. **利用者の設定(今の「利用者」のタブ)は、管理の画面に移す**
3. **サーバー全体の設定になりうるものは、管理の画面に移す**。今回移すのは下の 6〜8
4. **管理の画面を出すのは、管理者と、サーバーの PC から開いた画面**(今のモデル・ツールのタブと同じ線。0018 の決定事項 8。`Caller.ManagesPC`)。
   ただし「利用者」と「グループ」は、ログインした管理者にだけ出す(ログインの要らない形では利用者がおらず、利用者の管理はコマンドで行うため)
5. **入口は、左下の設定の歯車の隣の管理のアイコン**(盾)。管理できる人にだけ出す。ログインした管理者も、サーバーの PC から開いたログインなしの画面も同じ入口。
   会話の一覧を畳んだときも、歯車と並べて出す
6. **モデルのタブを分ける**:aibow-server(ブラウザ)では、設定のモデルのタブは一覧を見るだけにし、読み込む / 降ろす・層の数・置き場所・「使える」は管理の画面の「モデル」に移す。
   アプリの中で動かすとき(1人で使う)は管理の画面が無いので、今と同じく設定のモデルのタブで操作する。aibow-server につないだアプリは今と同じく一覧だけ
7. **ツールの扱いの既定(今の「ツール」のタブ)を、管理の画面の「ツール」に移す**(ほかの人に見るだけの表を設定に残すかは未決事項)
8. **プロファイルを配る作業を、管理の画面の「配るプロファイル」に移す**:配っているものの一覧・配る相手・値と決まり・資料のフォルダをそこで扱う。
   設定の「会話」は、自分のプロファイルと、配られたもの(読むだけ)だけにする。自分のプロファイルを組織に配るときは、管理の画面で「写して配る」(元の自分のプロファイルは残す)
9. **アプリ(serverUrl でつないだもの)からは、管理の画面を開かない**(今までどおりブラウザだけ)。管理の口の権限の線は変えない
10. **server.json に手で書いている項目(資料のフォルダ・MCP のサーバー・待ち受け・ログインなど)は、今回は画面に出さない**。
    画面で変えるのは、起動し直しの扱いも含めて別の仕様にする(`_docs/backlog.md` の「aibow-server の中央の制御」に書き足した)
11. **3段に分けて進める**。段ごとにコミットし、どの段で止めても使える形にする(下の「作業の順番」)

```
設定(自分のため)                          管理(サーバー管理者のため。歯車の隣の盾から)
  基本設定                                    利用者          … ログインした管理者だけ
  モデル        … aibow-server では一覧だけ   グループ        … ログインした管理者だけ
  会話          … 自分のプロファイル・配られたもの   モデル    … サーバーの PC の事情
  アカウント                                  ツール          … 全体の既定
  サーバー      … アプリだけ                  配るプロファイル
  グループ      … グループの長だけ(長の作業はサーバー管理ではないので、設定に残す)
```

## やらないこと(先回りしない)

- Go の口の権限の線を変える(画面の出し分けだけを変える。決定事項 9)
- 管理者を画面から決める(今までどおりコマンドだけ。0018 の決定事項 6)
- server.json の項目を画面で見る・変える(決定事項 10)
- アプリから管理の画面を開く(決定事項 9)
