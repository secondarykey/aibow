## 目的

設定の画面には、**自分のための設定**と**サーバー管理者の作業**が混ざっている(2026-11-01、ユーザーの指摘)。
利用者の管理はサーバー管理者だけが行う作業で、自分の設定の続きにあるのはおかしい。
サーバー管理者のための「管理」の画面を設定とは別に作り、利用者の設定をそこで行う。サーバー全体の設定になりうるものも、そこに移す見込みが高い。

学ぶこと:

- **画面を「だれの作業か」で分ける**:今は同じタブの中で、管理者かどうかで出すものを変えている(モデルのタブ・会話のタブの「配る」)。
  作業する人で画面を分けると、出し分けの条件が画面の入口の1か所にまとまる
- **画面の出し分けと、口の断り**:画面を分けても、断るのは今までどおり Go の口(`onlyAdmin`・`pcMethods`・`adminToolMethods`・store の条件)。画面は出し分けるだけ

## 今の設定の画面にある、サーバー管理者の作業(2026-11-01 の時点)

| 今の場所 | 中身 | 今の出し分け |
|---|---|---|
| 「利用者」のタブ(`UserSettings.tsx`・`GroupSettings.tsx`) | 利用者(作る・リンク・API キー・表示名・メール・消す・その人の会話)・グループ・グループの長 | ブラウザの管理者だけ(`/aibow/admin/` とグループのメソッド) |
| 「モデル」のタブ(`ModelSettings.tsx`) | 読み込む / 降ろす・GPU の層数・置き場所・「使える」のスイッチ | 管理者とサーバーの PC から開いた画面(`models.manage`・`Caller.ManagesPC`)には操作も、ほかの人には一覧だけ。1つのタブに混ざっている |
| 「ツール」のタブ(`ServerTools.tsx`。ブラウザだけ) | ブラウザの会話のツールの扱いの、aibow-server 全体の既定(`server-tools.json`) | 管理者とサーバーの PC から開いた画面が変える。ほかの人は見るだけ |
| 「会話」のタブの「配る」(`ProfileSettings.tsx` の `ShareForm`・資料のフォルダ) | プロファイルを組織に配る・配ったプロファイルを変える・資料のフォルダを選ぶ | 自分のプロファイルの編集の中に、管理者の操作として混ざっている |

手で書くしかない aibow-server の設定(`server.json`:資料のフォルダ・MCP のサーバー・待ち受け・ログイン)も、将来は管理の画面に出す候補
(`_docs/backlog.md` の「aibow-server の中央の制御」と重なる)。

## 決定事項(2026-11-01、ユーザーと決めた)

1. **設定とは別に、サーバー管理者のための「管理」の画面を作る**
2. **利用者の設定(今の「利用者」のタブ)は、管理の画面に移す**
3. **サーバー全体の設定になりうるものは、管理の画面に移す方向で考える**(どれを移すかは未決事項)

## 案(Code が出したもの。まだ決めていない)

```
設定(自分のため)                          管理(サーバー管理者のため)
  基本設定                                    利用者
  モデル        … 一覧を見るだけ              グループ
  会話          … 自分のプロファイル          モデル        … サーバーの PC の事情(読み込む / 降ろす・層の数・置き場所・使える)
  アカウント                                  ツール        … 全体の既定
  サーバー      … アプリだけ                  配るプロファイル
  グループ      … グループの長だけ(長の作業はサーバー管理ではないので、設定に残す)
```

- 入口は左下の名前のメニュー。管理者にだけ「管理」を足す(今の「アカウント」「ログアウト」と並べる)
- 管理の画面は、設定の画面と同じく会話の場所に出す別の画面(「会話に戻る」で閉じる)
- Go の口と断り方は変えない(画面を分けるだけ)。グループの長の作業(`SetGroupMember`)は今までどおり長にも開く

## 未決事項(Code は勝手に決めず、案を示してユーザーに確認する)

- **だれに管理の画面を出すか**:サーバーの PC から開いた、ログインなしの画面(127.0.0.1)にも出すか。
  今のモデルのタブとツールのタブは、その画面にも操作を出している(0018 の決定事項 8)。利用者の管理は、ログインなしの形ではコマンドだけ
- **配るプロファイルを移すか**:移すなら、プロファイルの編集の部品を「自分のもの」と「配るもの」で分けることになり、いちばん大きい作業になる。
  移さないなら、会話のタブの「配る」は今のまま残る
- **モデルのタブを分けるか**:設定には一覧だけ、管理には操作、と分けるか。アプリの中で動かすとき(1人で使う)は、今と同じく設定のモデルのタブで操作できるようにするか
- **アプリ(serverUrl)からも管理の画面を開けるか**:0031 では利用者の管理を「ブラウザの管理者だけ」にした(0018 も、サーバーの PC の事情をアプリから変えるのは作らない)
- **server.json の項目を画面に出すか・いつ出すか**(資料のフォルダ・MCP のサーバーなど。起動し直しが要るものをどう扱うか)
- **進め方**:一度に全部移すか、段に分けるか(案:段1 管理の画面と入口・利用者とグループを移す → 段2 モデルとツール → 段3 配るプロファイル)
