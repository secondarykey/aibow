## 目的

**画面のアプリから、aibow-server につなぐ・ログインする・アプリの中で動かす形に戻す、をできるようにする**。
今は `settings.json` に `serverUrl`・`serverKey`(サーバーの PC で `aibow-server user key` を打って作ったキー)・`serverCert`(サーバーの PC から写した証明書)を手で書き、アプリを起動し直している。
人が使うアプリとしては不自然なので、画面でつなぎ先を打ち、名前とパスワードでログインすれば使えるようにする。

学ぶこと:

- **トークンを発行する認証**:パスワードを毎回送らず、確かめたら期限付きの合言葉(トークン)を渡す。ブラウザの cookie のセッションと同じ考え方を、cookie の無いアプリに当てはめる
- **秘密の保存**:手元に置く合言葉を、OS の仕組み(Windows の DPAPI)で包む。ファイルを写されても、ほかの PC・ほかの Windows の利用者では戻せない
- **証明書の固定(TOFU)**:誰も保証していない自己署名の証明書を、初めてつなぐときにフィンガープリントで確かめて覚える(SSH の `known_hosts` と同じ考え方)

## 決定事項(ユーザーと決めたこと。2026-10-26)

1. **つなぎ先を画面で変えたら、保存して、起動し直すと切り替わる**
   - 切り替えると、生成の口(engine か `api/client`)も会話の保存先(`aibow.db` か `server.db`)も丸ごと替わるので、今の起動の流れをそのまま使う
   - 起動したまま切り替える形は作らない(llama.cpp の解放と読み込み・会話の仕組みの作り直し・生成中の扱いまで要るため)
   - **2026-10-26 に決め直した**:アプリは自分で起動し直さない(exe でも `wails3 dev` でも)。起動し直すまでは「起動し直すと切り替わります」を出し続ける。閉じるボタンなどの案内は付けない。
     理由:`wails3 dev` ではアプリが終わると dev ごと止まり(`build/config.yml` の `exit_policy: shutdown`)、自分で起動し直す形が作れない。
     exe だけ自分で起動し直すと、同じ操作で dev と exe の動きが違い、プロセスの入れ替えという意外なことも起きる。起動し直せと言ってその通りに動かない、は利用者として考えられない(ユーザー)
2. **ログインはアプリの画面で名前とパスワードを打つ**。aibow-server が確かめ、アプリ用のトークンを出す。アプリはトークンだけを覚え、パスワードは覚えない
3. **トークンの期限は固定の 10 日**。使っても延ばさない(ブラウザのセッションは「最後に使ってから 30 日」なので、そこが違う)。切れたら 401 で断り、アプリは設定の画面でもう一度ログインするよう伝える
4. **アプリはトークンを Windows の DPAPI で包んで保存する**。標準ライブラリの `syscall` で `crypt32.dll` を呼ぶ(外部パッケージなし・CGO なし)。
   Windows 以外では平文で保存し、そのことを画面とログに出す
5. **手で書いた値が強い**。`settings.json` の `serverUrl`(・`serverKey`・`serverCert`)か、環境変数 `AIBOW_SERVER_URL`(・`AIBOW_SERVER_KEY`・`AIBOW_SERVER_CERT`)に書いてあれば、それを使う。
   そのときは、画面ではつなぎ先を変えられず、「手で書いてあるので画面では変えられない」と、どこに書いてあるかを表示だけする(書いたのに効かない、が起きないように)
6. **自己署名の証明書は、初めてつなぐときにフィンガープリントを見て信頼する**(TOFU。Trust On First Use)。
   アプリは、つなぎ先の証明書の SHA-256 のフィンガープリントを画面に出し、aibow-server が起動のときに出すフィンガープリントと同じなら「信頼してつなぐ」。覚えたフィンガープリントと違う証明書を出すサーバーには、つながない。
   証明書のファイルを写さなくてよい

## 決定事項(Code が決めたこと。ユーザーに確かめる)

7. **画面が書くファイルは `connection.json`**(`%APPDATA%\aibow\connection.json`。環境変数 `AIBOW_CONNECTION` で変えられる)。`tools.json` と同じ「画面で変えるが、その PC の人が決めること」。
   中身はつなぎ先・覚えた証明書のフィンガープリント・ログインした名前・トークン(DPAPI で包んだもの)・トークンの期限。
   手で書いた値が無いときだけ使う(決定事項 5)
8. **つなぎ先は1つだけ覚える**(複数を覚えて選ぶ形は作らない)。つなぐ前に確かめる:つながるか・ログインが要るか・証明書(自己署名ならフィンガープリント)。
   確かめられないつなぎ先は保存しない(起動し直してから「つながりません」となるのを避ける)
9. **トークンは PC ごとに1本**(利用者 + PC の名前)。同じ PC でログインし直すと、その PC の前のトークンは消える。ほかの PC のトークンは残す(2台目でログインしても1台目が切れない)
10. **トークンが消えるとき**:アプリで「ログアウトして戻す」をしたとき(サーバーのトークンも消し、アプリの中で動かす形に戻す。サーバーにつながらなければ手元だけ消す)・
    パスワードを作り直したとき(`user passwd`・管理者の画面。ブラウザのセッションと一緒に全部消える)・利用者を消したとき
11. **トークンの形は `aibowapp_` + 32 バイトのでたらめな値**。server.db には SHA-256・持ち主・PC の名前・期限だけを置く(DB の版 13 `app_tokens`)。
    送り方は API キーと同じ `Authorization: Bearer`。使える口も API キーと同じ(保存の口・生成の口・誰としてつないでいるか)。
    期限の切れたトークンは 401 で、`code` を `token_expired` にする(アプリが「期限が切れました」と出し分けるため)
12. **`user key`(手で書く API キー)は残す**。Cline などログインの画面を持たないものと、`settings.json` の `serverKey` は今のまま
13. **口**:`POST /aibow/auth/token`(本文 `{"name", "password", "device"}` → `{"token", "name", "admin", "expiresAt"}`。ログインと同じ回数制限・JSON だけ受け付ける)と、
    `POST /aibow/auth/token/revoke`(`Authorization: Bearer <トークン>` のトークンを消す)。ログインの要らない aibow-server では、トークンの口は 400 で断る(キーも要らないので)
14. **フィンガープリントを出す場所**:aibow-server は HTTPS で起動したときと `cert` のコマンドで、証明書の SHA-256 のフィンガープリントをログ(Notice)と画面に出す。形は `AB:CD:…` の16進(32 バイト)
15. **画面**:設定の画面に「サーバー」のタブを足す(デスクトップのアプリだけ。ブラウザでは出さない)。
    今の形(アプリの中で動かす / aibow-server に誰としてつないでいる・期限)・つなぎ先の入力と確かめる・証明書のフィンガープリント・ログイン・ログアウト・アプリの中で動かす形に戻す
16. ~~**`wails3 dev` では起動し直さない**~~ → 決定事項 1 を決め直して、どちらでも起動し直さないことにした
17. **起動し直す前に、もう一度つなぎ直す・戻すことができる**(保存したものと、今動いている形を分けて持つ)。つないだのを起動し直す前に取りやめたら(「ログアウトして戻す」)、
    もらったトークンを aibow-server で消し、お知らせも消す(今もアプリの中で動いているので、起動し直さなくてよい)

## 作業中に決めたこと(Code。2026-10-26)

- **ログアウトと「戻す」は1つにした**(「ログアウトして戻す」)。ログアウトだけしてつなぎ先を残すと、起動し直したあとに全部の呼び出しが 401 になり、使える形が無いため。
  ログインし直したいとき(期限切れなど)は、同じタブで今のつなぎ先にもう一度「確かめる」→ ログインする(つなぎ先と名前は入れておく)
- **初めてつなぐときは、フィンガープリントを確かめるまで何も送らない**。TLS でつないで証明書を受け取るだけ(`api/client` の `ProbeServer`)。信頼したら、フィンガープリントを固定して `/aibow/auth/me` でログインが要るかを聞く
- **固定したフィンガープリントの証明書か、OS が信頼する証明書だけを受け付ける**(`PinCert`。名前の確かめは、固定したフィンガープリントのときはしない。フィンガープリントが中身そのものなので)。違う証明書なら「起動していない」ではなく、証明書が違う(なりすましかもしれない)と伝える
- ~~起動し直しは、後片付けのあとに同じ引数・カレントフォルダ・環境変数で自分を起動する(`relaunch`)~~ → 決定事項 1 を決め直して消した(2026-10-26)
- フィンガープリントの形は `AB:CD:…`(SHA-256 の 32 バイトを大文字の16進で `:` 区切り)。aibow-server とアプリで同じ関数(`auth.Fingerprint`)を使う

## 段 4 で確かめたこと(2026-10-26)

- 用意:一時フォルダの aibow-server(`127.0.0.1:18089`・HTTPS(自己署名)・ログインあり・CPU)、利用者 bob。アプリは一時ビルド(WebView2 のデータフォルダを分け、CDP で操作)で、DB・ログ・`connection.json` は一時フォルダ
- 直接の形から「サーバー」のタブでつなぎ先を確かめる → aibow-server が起動のときに出したフィンガープリントと同じフィンガープリントが出る → 信頼する → 名前とパスワードの欄が出る → 違うパスワードは「名前かパスワードが違います」→
  正しいパスワードでアプリが起動し直し(プロセスが替わった)、`connection.json` にはトークンが DPAPI で包まれて入る(`aibowapp_` がそのまま無い)
- 起動し直したあと:タブに名前・期限(10 日後)・フィンガープリントが出る。送信すると aibow-server(4B・CPU)が返事をした(生成と保存がトークンで通る)
- 「ログアウトして戻す」:aibow-server のログに「アプリでログアウトしました」、`connection.json` が消え、起動し直して手元の DB に戻った
- 環境変数 `AIBOW_SERVER_URL` を書いて起動:タブは表示だけで、「手で書いてあるので、画面では変えられません」と出る
- **決定事項 1 を決め直したあと**(2026-10-26。同じ用意):つなぐと「保存しました。aibow を起動し直すと、aibow-server(https://127.0.0.1:18089)につなぎます」が出て、プロセスはそのまま(PID が変わらない)・まだアプリの中で動く。
  手で起動し直すと aibow-server につながった形で始まる。そこで「ログアウトして戻す」と「起動し直すと、アプリの中で動かす形に戻ります」。
  アプリの中で動いているときに、つないでから起動し直す前に「ログアウトして戻す」と、お知らせが消え、aibow-server のログに「アプリでログアウトしました」
- 見ていないこと:期限切れ(10 日後)の画面での見え方(サーバーの 401 `token_expired` はテストだけ)・覚えたフィンガープリントと違う証明書になったとき(テストだけ)・LAN のアドレスとほかの PC から・Windows 以外(平文で保存)
