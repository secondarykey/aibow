# 0028: 同じ呼び出しが成功のまま繰り返されるのを止める

- 状態: ✅ 完了(2026-10-30。llama3.2:3b での確かめはまだ)
- 決めた日: 2026-10-30(Code が案を書き、ユーザーが未決事項を選んだ)
- きっかけ:0027 で Llama 3 の書式を足したとき、Ollama の `llama3.2:3b` がツールの結果を渡しても答えず、同じ呼び出し(`get_current_time`・`list_files` など)を何度も繰り返した。
  1回の送信の上限(20 回)で止まることもあった(`_docs/tuning.md` の「Llama 3.2 3B も並べる」)。書式はテンプレートどおりなので、エージェントループの改良として別にする、とユーザーが決めた(0027 の決定事項 23)
- 前提:0004(エージェントループ・`maxToolCalls`)、0025(同じ失敗の繰り返しで止める `repeatedFailure`・残りが無いときはツールを見せずに答えさせる `noRoom` と `noRoomNote`)

## 目的

成功した呼び出しを繰り返して終わらないモデルを、20 回の上限まで待たずに、ここまでの結果で答えさせる(または止める)。

学ぶこと:

- **エージェントループの「終わり」はモデルが決める**:モデルが呼び出しをやめない限りループは続く。アプリができるのは、繰り返しを見つけて、終わるきっかけを渡すこと
- **繰り返しの見つけ方には、取りこぼしと取り違えの両方がある**:結果まで同じかを見ると、時刻のように毎回変わる結果を取りこぼす。名前と引数だけを見ると、直したあとにもう一度テストを動かす、のような正しい繰り返しを取り違えうる

## 今の動き(2026-10-30)

- 同じ呼び出し(名前と引数)が**同じエラー**で2回続いたら止める(`repeatedFailure`。0025 の決定事項 6)
- 成功した呼び出しの繰り返しは止めない。1回の送信の上限(20 回)で止まる
- 会話の上限の残りが無くなったら、次の生成ではツールを見せず、最後に「読んだ内容で答えて」(`noRoomNote`)を足す。それでも呼んだら止める(0025 の決定事項 11・12)。
  ツールを外すだけでは小さいモデルが前の呼び出しをまねて呼ぶが、頼みを足すと答えた

## 決定事項(ユーザーが選んだこと。2026-10-30。案は下の「選ばなかった案」)

1. **同じ呼び出しは、名前と引数が同じもの。結果は見ない**。`get_current_time` は結果に秒が入り毎回変わるため、結果まで比べると llama3.2:3b の繰り返しを取りこぼす
2. **続けて(間に別の呼び出しが無い)同じときだけ数える**。1つの返事の中で並べた呼び出しも順に数える。
   「直す → テストを動かす → 直す → テストを動かす」のような、間に別の呼び出しを挟む正しい繰り返しを取り違えないため。A・B・A・B の交互の繰り返しは 20 回の上限に任せる
3. **2回目で手当てする**(同じ呼び出しが1回繰り返されたら)。手当てが「答えさせる」でやわらかいので、早めでよい
4. **手当ては、次の生成でツールを見せず、最後に「同じ呼び出しを繰り返しています。ここまでの結果で答えてください」の頼みを足す**(保存しない。0025 の決定事項 11・12 の、残りが無いときと同じ形)。
   それでもツールを呼んだら、実行せずに理由を画面に出して止める
5. **別の引数で同じツールを呼び続ける場合は、今回は扱わない**(20 回の上限に任せる。引数を変えて呼び直すのは、立て直している途中のことが多い)

## 決定事項(Code が決めたこと。2026-10-30)

6. 2回目の呼び出しも実行して結果を渡す(結果は変わりうるので、実行せずに「前と同じ」とは返さない。どの呼び出しにも結果がある形も保てる)
7. 同じ失敗の繰り返し(`repeatedFailure`)を先に見る。同じ呼び出しが同じエラーで続いたら、今までどおり止める(答えさせる手当てには回さない)
8. 読み取れない呼び出し(書式の崩れ)は、間に挟まると「別の呼び出し」として数え直す
9. 残りが無いとき(0025)と同じ回に繰り返しも見つけたら、残りが無いほうの頼みを使う(もう読めない、のほうが答えに要ることなので)
10. 手当てをしたことはログ(Info)に出す。画面にはお知らせを出さない(続けてモデルの答えが出るため。ツールのカードで繰り返しは見える)
11. 頼みの文は、残りが無いときと同じく、日本語と英語の両方で書く(何語で頼まれたかに、モデルが合わせられるように)
12. ツールを見せない回は、MCP のツールも外す(以前は、組み込みのツールを外している会話では MCP のツールを残していた。残りが無いときも同じに直す)

## 選ばなかった案

- 同じ呼び出しの見方:名前と引数と結果が同じ(時刻の繰り返しを取りこぼす)・その送信の中のどこかで同じ(正しい繰り返しを取り違えやすい)
- 回数:3回目(生成が2回分多くかかる)
- 手当て:止めて理由を出す(答えが出ない)・結果の文に一言添えるだけ(ツールは見せたまま。効くか分からない)
- 別の引数:同じ名前のツールが N 回続いたら手当てする

## やらないこと(先回りしない)

- 同じ失敗の繰り返し(`repeatedFailure`)の扱いを変える(0025 で決めたとおり、2回で止める)
- 1回の送信の上限(20 回)を変える
- 書式・モデルごとの手当て(繰り返しやすいモデルを名前で見分ける、など)
