## 目的

デスクトップのアプリでサーバーモードにしてログアウトし、起動し直すと、ログインの画面になる。ここから**アプリモードに戻る道が無い**。
設定の画面はログインしないと開けず、戻すには `%APPDATA%\aibow\connection.json` を手で消すしかない(2026-11-20、ユーザーが見つけた)。

あわせて、「サーバー」のタブで「確かめる」のあとにその場でログインする今の流れを、**つなぐ(サーバーがあるかを確かめて覚える)とログイン(ログインの画面で行う)に分ける**。
ログインの入口をブラウザと同じログインの画面の1つにそろえ、ログインの画面からはその PC の設定(つなぎ先・アプリモードに戻す)を開けるようにする。

学ぶこと:

- **設定の置き場所と「誰のものか」**:その PC の人が決めること(つなぎ先・ツールを聞かずに動かすか)は PC に、ログインした人のもの(会話・プロファイル・表示)はサーバーに置く(AGENTS.md の技術方針・0017 の 6)。
  ログインの前に触れるのは PC に置いたものだけ、という線がそのまま画面の線になる
- **認証の前に使える操作を絞る**:ログインの画面は、まだ誰か分からない人が触る画面。サーバーに何かを頼む操作は置かず、手元のファイルを変えるだけの操作に限る

## 決定事項(ユーザーと決めたこと。2026-11-20)

1. **「サーバー」のタブの「確かめる」ボタンを「接続」に改名する**。「接続」でサーバーがあるか(つなぎ先の URL が正しいか)を確かめた時点で保存し、起動し直すよう促すお知らせを出す。
   **起動し直したら、ログインの画面にする。ログインはログインの画面で行う**(「サーバー」のタブには名前とパスワードの欄を置かない)
2. **ログインの画面から設定を開けるようにする**(デスクトップのアプリだけ。ブラウザには付けない)。
   出すのは**その PC に保存される設定**だけ(つなぎ先と「接続」・「アプリモードに戻す」など)。aibow-server に利用者ごとに保存される設定は出さない。
   どの設定がどちらに保存されているかを洗い出して仕様に書く(下の「設定の置き場所」)。言語のような基本設定がサーバーの側にあるなら、PC の側に置くべきかを未決事項にして案を示す(下の未決事項 1)
3. **ログインの前の「アプリモードに戻す」は、手元のつなぎ先を消して、起動し直すよう促すだけ**。トークンが無いので、aibow-server には何も送らない

## 設定の置き場所(2026-11-20 のコードを洗い出した)

デスクトップのアプリがサーバーモードのとき、どの設定がどこにあるか。「ログインの前」は、ログインの画面で読めるか・変えられるか。

| 設定の画面のタブ | 中身 | 置き場所(サーバーモード) | ログインの前 |
|---|---|---|---|
| 基本設定 | 明るさ(`theme`)・質問を右上に出す(`pin_question`) | aibow-server の `server.db` の `user_settings`(**人ごと**。`appsettings.go` の `LoadDisplay`)。アプリモードなら手元の `aibow.db` | 読めない(401)。明るさだけは、画面が最後の値の写しを `localStorage` に持っていて、ログインの画面もそれで描く(`theme.ts`) |
| モデル | 読み込む / 降ろす・GPU の層数・置き場所 | aibow-server の PC(`server.db` の `app_settings`・`server-models.json`。0046 で管理者だけ)。アプリモードなら `aibow.db`・`model-places.json` | 読めない |
| 会話 | プロファイル・新しい会話で最初に選ばれるプロファイル | `server.db`(人ごと) | 読めない |
| 会話(ツールの「確認しない」) | ツールを聞かずに動かすか(PC の既定) | **PC** の `tools.json`(0014。プロファイルの一覧の中に混ぜて出している) | ファイルは読めるが、出す場所(プロファイルの一覧)がサーバーのもの |
| ワークスペース | 名前を付けたフォルダの組・会話の worktree の結び付け | **PC** の `workspaces.json`(0035・0039) | 読める |
| MCP | MCP のサーバー | **PC** の `mcp.json`(0034) | 読める |
| サーバー | つなぎ先・信頼したフィンガープリント・トークン・`known` | **PC** の `connection.json`(0019) | 読める・変えられる |
| アカウント | 表示名・メールアドレス・パスワード・使用量・ログアウト | `server.db`(人ごと) | 読めない |
| (画面に無い) | aibow-server のつなぎ先を手で書く・`fetchAllowPrivate` | **PC** の `settings.json`(手で書く) | — |
| (画面に無い) | ウィンドウの位置と大きさ | **PC** の `window.json` | — |

- **言語の設定は今の aibow には無い**(画面の文は日本語だけ)。「言語のような基本設定」に当たる今の設定は、基本設定のタブの明るさと質問を右上に出すの2つで、どちらもサーバーモードでは**サーバーの側(人ごと)**にある
- PC の側にあって画面で変えられるのは「サーバー」・「MCP」・「ワークスペース」・ツールの「確認しない」の4つ

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-20。2026-11-21、作る前にユーザーが「このまま採用」と確かめた)

### 「接続」(サーバーのタブ)

4. **「接続」がすること**:今の「確かめる」(`CheckServer`)と同じく、つながるか・ログインが要るか・証明書を確かめる。自己署名の証明書でまだ信頼していなければ、フィンガープリントを見せて「この証明書を信頼する」を待つ(0019 の決定事項 6 のまま)。
   信頼できたら、その場で `connection.json` に**つなぐ先(`serverUrl`)とフィンガープリントと `known`** を書き、トークンは書かない。お知らせは今の pending の文を使う:
   - ログインが要る aibow-server:「保存しました。aibow を起動し直すと、aibow-server(…)につなぎます。起動し直したら、ログインの画面でログインしてください」
   - ログインが要らない aibow-server:「保存しました。aibow を起動し直すと、aibow-server(…)につなぎます」
   - 前の「確かめる → 信頼 → 名前とパスワード → ログインしてつなぐ」の2段目以降が無くなる。信頼したあとは、もう一度「接続」を押さなくても保存まで進む(信頼のボタンが「接続」の続きになる)
5. **Go の口**:`ConnectServer` から名前とパスワードを外し、トークンをもらわない形にする(`ConnectRequest` は `url` と `fingerprint` だけ)。
   トークンをもらう `login` は、ログインの画面の `Login`(account.go)だけが使う。`CheckServer` は「確かめて `known` に覚える」だけのまま残し、画面の「接続」は `CheckServer` → (信頼)→ `ConnectServer` の順に呼ぶ
6. **起動し直したあと**:つなぐ先があってトークンが無いので、今のログアウトのあとと同じくログインの画面になる(`Account` の 401 → `NeedLogin`)。名前の欄には `known` の最後にログインした名前を入れておく(今のまま)。
   ログインの画面の `Login` は今のまま使える(起動し直す前の pending があるときは断る、も今のまま)
7. **サーバーモードで「接続」を押したとき**:
   - **今つないでいるのと同じつなぎ先**なら、何も保存せず「今この aibow-server(…)につないでいます」と出す(ログインし直したいときは、ログアウトしてログインの画面で。期限が切れたら起動したときにログインの画面になる)
   - **違うつなぎ先**なら、今のトークンを aibow-server で消し(今の `revoke`。つながらなければ手元だけ)、新しいつなぎ先を保存して起動し直すよう促す。起動し直すと新しいほうのログインの画面
8. **タブの見出しと文**:「aibow-server につなぐ」/「つなぎ直す」を、アプリモードでは「aibow-server につなぐ」、サーバーモードでは「つなぎ先を変える」にする。入力欄の Enter も「接続」を押したのと同じ
9. **ログインの欄が無くなったことの案内**:「サーバー」のタブの説明(`LuInfo` の title)に「ログインは、起動し直したあとのログインの画面で行います」を足す

### ログインの画面の設定

10. **入口**:デスクトップのアプリのログインの画面(`Login`。`me.setup` の案内も含めた箱の下)に「設定」のボタン(歯車)を置く。ブラウザでは出さない(`isBrowser`)。
    `SetPassword`(招待・再設定のリンク)はブラウザだけなので関係しない
11. **開く画面**:ログインの画面の代わりに、ログインの前の設定の画面を出す(タイトルバーは `WithTitleBar` のまま)。見出しは「設定(ログインの前)」、左上に「ログインの画面に戻る」。
    タブは**「サーバー」だけ**(未決事項 1・2 の答えでタブが増える)。中身は今の `ServerSettings` をそのまま使う(今のモード・つなぎ先と「接続」・アプリモードに戻す・手で書いてあれば表示だけ)。
    ふだんの設定の画面(`SettingsView`)は App の状態(設定・モデル・MCP のサーバーの一覧など)を前提にしているので、使い回さず、小さい入れ物を別に作る
12. **出さないもの**:基本設定(サーバーの側。決定事項 2)・モデル・会話・アカウント・グループ(サーバーの側)。
    ワークスペース・MCP は PC の側だが、ログインしないと使い道が無い(会話で選ぶもの)ので出さない(未決事項 2 で確かめる)
13. **ログインの画面での「アプリモードに戻す」**:今の `DisconnectServer` を呼ぶ。トークンが無いので `revoke` は何も送らず、`connection.json` から `serverUrl` とトークンを消して `known` を残す(今のまま。決定事項 3)。
    お知らせは今の「保存しました。aibow を起動し直すと、アプリモードに戻ります」
14. **戻すと決めたあとのログインの画面**:pending がある(起動し直すと切り替わる)間は、ログインの画面の箱に同じお知らせを出し、ログインのボタンを押せなくする
    (`Login` は pending があると断るので、押させてからエラーにするより先に止める)。設定を開けば「接続」でつなぎ直すこともできる(今の決定事項 17 のまま)
15. **ログインの画面で「接続」して違うつなぎ先にしたとき**:決定事項 7 と同じ(トークンは無いので消すものは無い)。起動し直すと新しいほうのログインの画面
16. **起動に失敗していても開ける**:サーバーモードでは llama.cpp を読み込まないので、ふつうは起動に失敗しない。aibow-server が止まっていてつながらないときも、ログインの画面と設定は出る(今のログインの画面と同じ)

### 戻したあとの起動のエラーの文

17. `lib` の無い PC で、`known` だけがある状態(ログインの画面からアプリモードに戻した・「接続」したが起動し直す前に戻した)で起動すると、今は「aibow-server(…)にはまだログインしていません」と出る(`config.go` の `libMissing`。0019)。
    戻すのは自分で選んだことなので、この文を「llama.cpp のフォルダが見つかりません(アプリモードで動かすのに要ります)。aibow-server を使うときは、設定の画面の『サーバー』で『接続』してください(前に信頼した aibow-server(…)を覚えています)」の形にする
