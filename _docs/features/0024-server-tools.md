## 目的

**設計資料(仕様・TODO など)を、アプリなしでブラウザのチャットで作れるようにする**(2026-10-25、ユーザー)。
今の「Chat が PC のフォルダを読んで仕様を書き、実装は Code」を、組織の人がブラウザの aibow でできる形。

aibow-server につないだデスクトップのアプリは、今もツールを手元の PC で動かせる(0013 の C)。ツールが使えないのはブラウザの会話(B)だけで、この仕様はその穴を埋める。

| 段 | 中身 | この仕様 |
|---|---|---|
| 12-1 | Web のツール:組み込みの時刻・計算と、管理者が aibow-server に書いた MCP のサーバー。確認の往復をブラウザに流す | 作る |
| 12-2 | サーバーに置いた資料のフォルダ:管理者が置き、配るプロファイルに紐づける。ブラウザの会話で読む・書く(確認つき)。コマンドと git は出さない | 作る |
| 12-3 | コマンド・隔離(サンドボックス)・逆向きのつなぎ方 | 作らない(必要になってから) |

```
ブラウザ ──HTTP──→ aibow-server [ 画面用の口 → 会話の仕組み(ツールあり)→ engine ]
                                   ├ 組み込みの時刻・計算
                                   ├ MCP のサーバー(管理者が設定に書いたもの。全員で1つ)── Web など
                                   └ 作業フォルダのツール(読む・書く)── 資料のフォルダ(管理者が置いたもの。os.Root の中だけ)
                                 確認のカード:SSE で届き、答えは画面用の口で返す
```

学ぶこと:

- **ツールをどこで動かすか**:同じツールでも、アプリの PC で動かすかサーバーの PC で動かすかで、触れるものと決める人(PC の持ち主か管理者か)が変わる
- **確認の往復をネットワークで流す**:今は Wails の中で済んでいる「ループを止めて確認のカードを出し、答えを待つ」を、SSE(知らせ)と HTTP の呼び出し(答え)に分ける
- **共有のツールと共有のフォルダの危うさ**:全員で1つの MCP のサーバー(人をまたいで残る状態・社内の URL に届く fetch・外に出る検索の語)と、全員で1つのフォルダ(同じファイルを2人が書く)
- **隔離が要らない範囲**:コマンドを出さなければ、守りは「フォルダの外に出られない」(`os.Root`)と「誰がそのフォルダを使えるか」(配るプロファイル)で足りること

## 決定事項(ユーザーと決めたこと。2026-10-25)

### 12-1 Web のツール

1. **ブラウザの会話で使えるツールは、組み込みの時刻・計算と、管理者が aibow-server の設定に書いた MCP のサーバー**(Web で調べる・fetch など)。0016 の決定事項 7 を変える
2. **実行前の確認をブラウザでも出す**。確認のカードは SSE で届き、答えは画面用の口の呼び出しで返す。管理者が「確認しない」にしたツールは聞かない
   - 画面の確認のカードは、アプリと同じ部品を使う(0016 で「確認の往復を作らない」としたのは、ツールを使わないから要らなかっただけ)
3. **ツールの扱い(使わない / 確認する / 確認しない)の既定は、管理者がサーバー全体で決める**。利用者が変えられるのは、会話ごとの「使う / 使わない」と、確認のカードの「この会話では今後聞かない」だけ

### 12-2 サーバーの資料のフォルダ

4. **管理者が aibow-server の設定に「資料のフォルダ」(名前とパス)を手で書き、配るプロファイルで1つ選ぶ**
   - そのプロファイルで作った会話は、そのフォルダが作業フォルダになる(ブラウザでは名前だけを見せ、パスは見せない。0016 の決定事項 6 の続き)
   - 誰が使えるかは、配るプロファイルの「誰に配るか」(0018)でそのまま決まる
5. **資料のフォルダでは、読む・書く両方を許す**(`list_files`・`read_file`・`write_file`・`edit_file`)。書くのは今と同じ差分の確認つき
   - 同じファイルを2人が書くときは、今の「実行の直前にもう一度読んで、確認を待つ間に変わっていたら書き戻さない」(0005 の 3-2)に任せる。誰が書いたかはログに残す
   - コマンドのツール(`run_command`)は出さない
6. **git は管理者がサーバーで手で行う**(pull / commit / push)。aibow は git に触れない。モデルにも画面にも git を出さず、資料のフォルダが git の clone かどうかも気にしない

## 決定事項(話の流れから Chat が決めて書いたこと。2026-10-25 にユーザーが確かめた)

7. **MCP のサーバーと資料のフォルダは、aibow-server の設定ファイルに手で書く**(MCP の形はアプリの `settings.json` の `mcpServers` と同じ。置き場所は `server.json` か隣のファイルで、Code が決める)。画面からは足さない(起動のしかたとパスは「その PC の設定」なので。0006 と同じ考え方)
8. **`${workdir}` を使う MCP のサーバーは、資料のフォルダを持つ会話にだけ出す**(フォルダの無い会話には出さない)。資料のフォルダごとに1つ起動する(アプリの「作業フォルダごとに1つ」と同じ)
9. **サーバーの MCP のサーバーは全員で1つを使う**。人ごとに起動しない。管理者が置くのは「人をまたいで状態が残らないもの」に限る、と usage.md に書く
10. **管理者が決める既定は、サーバーの PC のファイルに覚える**(アプリの `tools.json` にあたるもの。名前は Code が決める)。管理者はブラウザの設定の画面の「ツール」で変える。管理者でない人には、使えるツールと扱いを見せるだけ
11. **ツールの実行は、誰の・どの会話の・どのツールかをログに残す**(Info。確認しないで実行したもの・資料のフォルダに書いたものは Notice)
12. **プロファイルの決まり(使えない。0014)と配るプロファイル(0018)は、サーバーのツールにも効く**
13. **デスクトップのアプリ(C)と Cline には、サーバーのツールも資料のフォルダも出さない**。アプリは手元のツールを使い、Cline は自分のツールを送ってくる(OpenAI 互換の口は今のまま)
14. **fetch のように PC の中や社内の URL に届くサーバーを置くかは、管理者が決める**。aibow は止めない(止める仕組みは作らない)が、usage.md に危うさを書く

## 作業中に決めたこと(12-1a。2026-10-26)

ユーザーと決めたこと(未決事項から):

15. **確認を待っている間にブラウザを閉じた・読み直したら、停止と同じにする**(「停止されたため実行していません」)。送信は長い HTTP の呼び出しなので、つながりが切れると止まる(停止ボタンと同じ仕組み)。
    **知らせ(SSE)だけが切れてつなぎ直したときは、待っている確認を取り直してカードを出し直す**(`PendingConfirm`。切れている間の confirm イベントは届かないため)
16. **確認を待っている間も、生成の席(`api.Seat`)は持ったままにする。ただし aibow-server では待つのを 5 分で打ち切る**(超えたら送信を止める。止め方は停止と同じ)。
    タブを開いたまま席を外した人が、ほかの人と Cline をずっと待たせないように。デスクトップのアプリは今のまま(上限なし)

Code が決めたこと:

17. **ブラウザの会話では、会話に保存した作業フォルダを使わない**(会話の仕組みの `IgnoreWorkDir`)。ツールを渡すと、作業フォルダに書いたパス(画面の口から書ける。サーバー越しのアプリで作った会話なら、その PC のパス)で、
    サーバーの PC のファイルのツールとコマンドが出てしまうため。ブラウザからは作業フォルダを決めも消しもしない(保存した値は残す。サーバー越しのアプリでは今のまま使える)。12-2 で資料のフォルダに置き換える
18. **ブラウザの利用者は、会話の設定で「確認しない」(`allow`)を足せない**(決定事項 3)。足せるのは確認のカードの「この会話では今後聞かない」だけ。使う / 使わない(`on` / `off`)と「確認する」(`ask`)は足せる。画面の会話のツールの欄でも、ブラウザでは「確認しない」の印を出さない
19. **ツールの実行のログに、会話と利用者の名前を足す**(決定事項 11。ブラウザでは誰の実行かが分かるように)

## 作業中に決めたこと(12-1b。2026-10-26)

ユーザーと決めたこと(未決事項から):

20. **サーバーの MCP のサーバーは、最初に使われたときに起動する**(アプリと同じ。そのサーバーを使う会話で最初に送信したとき)。aibow-server を止めるまで全員で1つを使い、落ちたら次の送信で起動し直す
21. **管理者の画面は、ブラウザの設定の画面の「ツール」のタブ**(決定事項 10 の形)。組み込みと MCP のサーバーごとに、グループとツールの扱いを「使わない / 確認する / 確認しない」で決める(決めていなければ決まりの既定)。
    ツールの一覧の読み直しもここ。管理者でない人にも同じ表を、変えられない形で見せる
22. **管理者がサーバー全体で「使わない」にしたツールとグループは、禁止**(利用者が会話で「使う」にできない)。
    アプリの PC の既定の「使わない」は「既定では使わない」だが、aibow-server では利用者が自分のプロファイルを作れるので、配るプロファイルの「使えない」では止められないため

Code が決めたこと:

23. **MCP のサーバーは `server.json` の `mcpServers` に書く**(形はアプリの `settings.json` の `mcpServers` と同じ。手で書くファイルを1つにする)。
    **管理者の既定は、`server.json` の隣の `server-tools.json`**(形はアプリの `tools.json` と同じ。aibow-server が書く)
24. **`${workdir}` を使うサーバーは、ブラウザには出さない**(決定事項 8。資料のフォルダは 12-2)
25. 管理者だけが呼べるもの(既定を変える・一覧を読み直す)は、口でも断り(403)、メソッドでも確かめる(サーバーの PC の事情と同じ二重の守り)。
    「管理者」は、サーバーの PC の事情と同じく、管理者とサーバーの PC の上から開いた画面(0018 の決定事項 8)。既定のファイルの場所(サーバーの PC のパス)は管理者にだけ見せる
