## 目的

利用者が増えても(数十〜100人くらいを想像している。今すぐ要る数ではない)、**共有する相手を選ぶ・利用者を管理する**画面が使えるようにする。
いちばん急ぐのは、**「指定した人」に切り替えた瞬間に名前順の先頭の人が自動で選ばれ、選んだつもりのない人に共有される**問題をなくすこと。

対象の画面:

- 会話の設定の「共有」(`ConversationSettingsView.tsx` の `ShareField`)
- プロファイルの「配る」(`ProfileSettings.tsx` の `ShareForm`)
- 設定の画面の「利用者」のタブ(`UserSettings.tsx`。ブラウザで管理者がログインしたときだけ)
- 会話の一覧の「共有された会話」(`ConversationList.tsx`)

学ぶこと:

- **選ぶ部品を1つにする**:同じ「人を選ぶ」が2か所に別々にあると、直すときに片方を忘れる。部品にして使い回す
- **下書きと確定**:チェック1つごとに保存すると、途中の状態(20人のうち5人だけに共有、など)が相手に見える。選んでから確定する形にすると、相手に見える状態は確定したものだけになる
- **グループと認可**:共有の相手に「人」のほかに「グループ」が入る。誰に見えるかの判定(0018 で `store` の SQL の条件の1か所に置いた)にグループを足すと、条件がどう変わるか
- **書き込みを減らす記録**:最後に使った日を、使うたびではなく1日1回だけ書く(セッションの期限を延ばすのと同じ考え方。`auth/sessions.go` の `extendEvery`)

## 決定事項(話の流れから Chat が決めて書いたこと。2026-10-31 にユーザーが確かめた)

### 人を選ぶ部品(会話の共有・プロファイルの配る)

6. **選ぶ部品を1つ作り、会話の「共有」とプロファイルの「配る」の両方で使う**。チェックボックスを全員分並べるのをやめ、「選んだ相手のチップ + 名前で探して足す」形にする
   ```
   共有  [ 指定した人 ▼ ]
     選んだ相手(3): [営業 グループ ×] [佐藤 花子 ×] [tanaka ×]
     [ 名前・グループで探す…   ]   ← 打つと候補が出る。Enter / クリックで足す
        最近選んだ相手: 高橋・伊藤・開発 グループ
     [ 共有する(5人) ]  [ やめる ]
   ```
7. **「指定した人」に切り替えても、だれも選ばない**(今の `names.slice(0, 1)` をやめる)。だれも選んでいなければ確定のボタンを押せない
8. **選んでから確定する**(チェック1つごとに保存しない)。確定のボタンは「共有する(n人)」/「配る(n人)」で、グループは人に広げた人数を数える(自分は数えない)。
   「やめる」で今の共有の状態に戻す
9. **確定の確かめの文に、相手の名前を出す**(多ければ「佐藤・鈴木 ほか3人」。グループはグループの名前)。非公開から共有にするときの「ツールの結果も見えます」(0018 の決定事項 12)はそのまま
10. **閉じている(編集していない)ときも、今の共有を1行で出す**(「5人に共有中:営業 グループ・佐藤 花子 ほか1人」)
11. **相手を全員外して確定すると非公開(配らない)になる**ことを、確定の前に「非公開になります」と出す(今は黙って戻る)
12. **候補の先頭に「最近選んだ相手」を出す**。覚えるのは画面(ブラウザ・アプリの手元の保存。DB は変えない)。最近の 5 件くらい
13. **候補は、全員の名前とグループを一度に取って画面で絞る**(サーバーで探す口は作らない。100人なら足りる)。表示名とログインの名前の両方で引く

### 利用者のタブ(管理者)

14. **利用者のタブを「一覧 + 詳細」にする**
    ```
    [ 名前で探す… ]  [すべて | 招待中 | 管理者 | API キーあり | 30日使っていない]        [+ 利用者を作る]
    名前                 状態      最後に使った日   作った日      会話
    佐藤 花子(sato)      管理者    今日            2026-10-20    42
    tanaka               招待中    -               2026-10-30     0
    ```
    - 上に検索欄(表示名とログインの名前)と絞り込み。列の見出しで並べ替え
    - 状態はアイコンではなく文字の印(管理者・招待中 = パスワードがまだ無い・ログインなし = `local`)
    - 行のボタン(パスワード・API キー・消す)はなくし、**行を押すと詳細**を出す:表示名・グループ・パスワードのリンク・API キー・消す・その人の会話(新しい順に 20 件 + もっと見る)
    - 招待中の人のリンクの期限が切れていたら、詳細に「リンクを出し直す」
15. **消すときは、確かめを今より一段重くする**(名前を打たせる、など)。その人の会話・プロファイル・共有も消えるため。形は Code が案を示す
16. **管理者が見る人の会話の一覧に、件数の上限を付ける**(20 件 + もっと見る。今は全件)

### 共有された会話(会話の一覧の下)

17. **「自分に共有」と「全員に共有」を分ける**(自分あて = 指定した人・グループで共有されたもの。こちらを上に)。持ち主で絞る・タイトルで探す。初めは新しい 20 件 + もっと見る

### 表示名

18. **表示名は空でもよい**(空ならログインの名前を出す)。見せるときは「表示名(ログインの名前)」、狭いところは表示名だけ。同じ表示名の人がいてもよい(ログインの名前で見分ける)
19. **表示名は管理者が利用者のタブで決め、本人も設定の画面で変えられる**。コマンドにも足す(`aibow-server user` の形は Code が決める)。長さは 64 文字まで
20. 「管理者が読みました」のログ(0018 の決定事項 1)などのログは、今までどおりログインの名前で書く(表示名は変わるため)

### 最後に使った日

21. **`users` に最後に使った時刻を持つ**。セッション(ブラウザ)・API キー・アプリ用のトークン・ログインのどれで使っても書く。**前に書いてから1日以上たったときだけ書く**(使うたびに書かない)
22. 利用者のタブに「最後に使った日」として出す(今日・昨日・n 日前・日付)。一度も使っていなければ「-」。「30日使っていない」の絞り込みはこれで決める

### グループ

23. **グループは管理者が作り、名前を付け、利用者を入れる**(利用者が自分で作る名簿は作らない)。1人が複数のグループに入れる。グループの中にグループは入れない
24. **グループの管理は、利用者のタブの中に「グループ」の切り替えを足す**(人の一覧とグループの一覧を切り替える)。利用者の詳細からも、入っているグループを変えられる。見た目は Code が案を示す
25. **会話の共有・プロファイルの配るで、相手にグループを選べる**。人とグループを混ぜてよい
26. **グループに共有すると、そのときのメンバーに広げるのではなく、「グループ」として覚える**。あとからグループに入った人にも見え、抜けた人には見えなくなる(部署の異動に合わせて共有が付いていく)。
    確定の人数(決定事項 8)は確定したときのメンバーで数える
27. **誰に見えるかの判定は、今と同じ `store` の SQL の条件の1か所に足す**(会話は `conversationShared`、プロファイルは `profileVisible` / `profileUsed`。「指定した人に入っている、または指定したグループのメンバー」)
28. **グループを消すと、そのグループへの共有と配るも消える**。そのせいで相手がだれもいなくなった会話・プロファイルは非公開(配らない)になる。消すときの確かめに「n 件の会話と n 件のプロファイルの共有から外れます」と出す
29. グループの名前はログインした人ならだれでも見える(共有の相手に選ぶため。今の利用者の名前の一覧と同じ)。メンバーの一覧も同じく見える

## 決定事項(グループ長。2026-10-31 にユーザーと決めた。形は Chat の案のとおり)

30. **グループ長を作る**。管理者が、グループのメンバーの中から長を決める。1つのグループに何人いてもよい。長がグループから外れたら長でもなくなる
31. **長にできるのは、自分が長のグループのメンバーを足す・外すことだけ**。グループを作る・名前を変える・消す・長を決める・外すは管理者に残す。
    長が自分をグループから外すこともできる(そのとき長でもなくなる)
32. **長には、設定の画面に「自分が長のグループ」だけを扱う欄を出す**(管理者だけの「利用者」のタブとは別)。足す相手は人を選ぶ部品(決定事項 6)で選ぶ。
    ブラウザだけかアプリ(serverUrl)でも出すかは、利用者のタブに合わせてブラウザだけを初めの形にする
33. **長がメンバーを変えると、グループに共有された会話・配られたプロファイルが見える人も変わる**(決定事項 26 のため)。
    - 長が人を足すときの確かめに「この人は、グループに共有された n 件の会話と n 件のプロファイルを読めるようになります」と出す
    - 会話・プロファイルをグループに共有するときの確かめに「グループの長と管理者は、メンバーを変えられます」と出す
    - 長がメンバーを変えたら、aibow-server のログ(Notice)に「誰が・どのグループに・誰を足した / 外した」を残す(管理者が読んだ記録と同じ考え方)
34. **長かどうかの判定も `store` の1か所に置く**(メンバーを変えるメソッドは「管理者か、そのグループの長」の条件で行を選ぶ。プロファイルの `profileEditable` と同じ形)
