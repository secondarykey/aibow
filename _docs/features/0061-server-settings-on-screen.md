## 目的

aibow-server の**並列数(`parallel`)・作業領域の大きさ(`ctx`)・資料のフォルダ(`folders`)**を、server.json を手で開かずに、管理(盾)の画面から見て変えられるようにする。

ユーザーはまだ形にしっくりきていない部分があり、「一旦は実装があれば OK。作ってから直すところも出ると思う」(2026-11-23)。
まず動く形を作り、使ってみて直す前提で進める。

学ぶこと:

- **起動したときに決まる値と、動いている間に変えられる値の違い**:並列数と作業領域は、モデルを読み込むときの作業領域(KV キャッシュ)の形・順番待ちの席の数・
  画面や Cline に見せる「1本あたりの作業領域」をまとめて決めるので、起動し直すまで変わらない。資料のフォルダは名前 → パスの表を引くだけなので、その場で差し替えられる
- **設定の強さの順と「画面で書く」の両立**:引数 > 設定ファイル > 環境変数 > 既定 の順のまま、画面は「設定ファイルの値」を書き換える。引数や環境変数で値を渡しているときは、
  画面で書いても効かないので、変えられないようにして理由を出す

## 今の作り(2026-11-23、Chat がコードを読んで確かめた)

- `parallel`・`ctx` は `_cmd/aibow-server/config.go` の `resolve` で、`-parallel`/`-ctx` > server.json > `AIBOW_SERVER_PARALLEL`/`AIBOW_SERVER_CTX` > 既定(1 / 32768)の順で、起動したときに1回だけ決まる
- 並列数は `engine.Config.Seqs`(`engine.New` のときに固定。モデルを読み込むたびにこの数で作業領域を作る)・`srv.SetSeats(c.Parallel)`(順番待ちの席)・
  `api.New` と `startBrowser` に渡す `nCtx`(1本あたりの作業領域)の3か所に入る。**どれも起動し直さないと変わらない**
- 資料のフォルダは server.json の `folders` にだけ書ける(引数・環境変数は無い)。`startBrowser` → `ui.Service` → `Conversations.SetFolders` で、起動のときに1回だけ渡す(コメントも「起動のときに1回」)。
  `cs.folders` は map をそのまま持っていて、鍵(mutex)は無い。会話のツールを作るときに、配るプロファイルの `Rules.Folder`(名前)で引く。名前が表に無ければ、黙って「資料のフォルダなし」になる
- 画面には、資料のフォルダは名前だけが見える(配るプロファイルで選ぶ。`Service.Folders`)。作業領域の大きさ・設定ファイルの場所は、管理の画面の「モデル」のタブに表示だけある(`api.Settings`。変えるのは server.json と起動し直し。0015 の 21)
- `config/server.go` の決まりは「server.json は手で書き、aibow-server は書かない。読むのは起動したときだけ」。aibow-server が書くのは隣の `server-models.json`・`server-tools.json`

## 決定事項

### ユーザーと決めたこと(2026-11-23)

1. **画面に出すのは、並列数・作業領域の大きさ・資料のフォルダ**。並列数は作業領域を等分するので、作業領域と組で扱う。
   待ち受け・ログイン・MCP のサーバーなど、server.json のほかの項目は今回は出さない(起動し直しの扱いが重いため)
2. **並列数と作業領域は、保存して「次に起動したときに切り替わります」と出す**。その場でモデルを読み直して切り替える形にはしない(席の数・1本あたりの作業領域を動かせるように作り直すことになり、大きいため)
3. **画面で変えた値は、起動に使った server.json に書き戻す**(既定の `%APPDATA%\aibow\server.json` でも、`-config` で指定したファイルでも)。別のファイルは作らない。
   **「server.json は aibow-server が書かない」の決まりは、この3つの項目に限って変える**。
   変えられないようにするのは、`-parallel`・`-ctx` の引数や、環境変数で値を直接渡していて、server.json に書いても効かないときだけ
   (ユーザーの言葉では「引数にしたファイルを書き換えられない理由はない。止めるのは `-parallel` のように値を直接渡しているときだけ」)
4. **資料のフォルダは、その場で効かせる**(起動し直さなくてよい)。配布プロファイルが使っているフォルダは消せないようにする

### 話の流れから Chat が決めて書いたこと(2026-11-23。2026-11-24 にユーザーが「書いてあるとおりでよい」と確かめた)

5. **権限は 0046 と同じ**:ログインが要る形では「ログインした管理者だけ」、`login: false` のときは今までどおり全部できる(`Caller.ManagesPC` と同じ判定)。
   資料のフォルダは、サーバーの PC の任意のフォルダをモデルに読み書きさせられる設定なので、管理者の外に開かない
6. **変えられないときの判定は「その値がどこから来たか」で行う**:`resolve` が、`parallel`・`ctx` それぞれの出どころ(引数 / 設定ファイル / 環境変数 / 既定)を覚えておく。
   - 引数から来たとき:変えられない。画面に「起動の引数 -parallel で決めています(変えるには引数を外して起動し直してください)」の形で出す
   - 環境変数から来たとき:変えられない。画面に「環境変数 AIBOW_SERVER_PARALLEL で決めています」の形で出す
     (server.json に書くと環境変数より強くなって黙って上書きしてしまうため。ユーザーの「値を直接渡しているとき」に含めた)
   - 設定ファイル・既定から来たとき:変えられる
   - 資料のフォルダは server.json にしか書けないので、いつでも変えられる
7. **server.json が無いとき**:aibow-server が探した場所(`%APPDATA%\aibow\server.json`。`-config` を書いたのに無いときは今までどおり起動しない)に、画面で変えた項目だけを書いて作る。
   次に起動したときから、そのファイルが設定ファイルとして読まれる(起動のログの「設定ファイル: …」が変わる)
8. **書き戻し方**:
   - 書く直前にファイルを読み直し、画面で変えた鍵(`parallel`・`ctx`・`folders`)だけを差し替え、ほかの鍵の値はそのまま残す(手で書いた値を画面が消さない)。
     読み直したファイルが壊れている(JSON として読めない・知らない欄がある)ときは書かずに断り、直してから保存するよう画面に出す
   - 一時ファイルに書いてから置き換える(書いている途中で落ちても server.json が半分にならないように)
   - 書く前の内容は隣の `server.json.bak` に1つだけ残す(手で書いた形に戻したいときのため)
   - 書いたら Notice のログに1行(0053 と同じく、変えた項目を画面と同じ言葉で並べる。例「サーバーの設定を保存しました(管理者 alice): 並列数 1 → 2・作業領域 32768 → 65536(次の起動から)」「資料のフォルダを足しました: 社内規程」)
9. **並列数と作業領域の画面**:
   - 「今動いている値」と「保存した値(次の起動の値)」が違うときは、両方を出し、「aibow-server を起動し直すと切り替わります」と出す。画面から起動し直すボタンは付けない
   - 入力の確かめ:どちらも 1 以上。1本あたりの作業領域(作業領域 ÷ 並列数)も画面に出す(0023 の決定事項 11 の「1つの会話が使えるのはそこまで」が分かるように)
   - 保存は確定式(0053)。変えて「保存」を押したときだけ書く
10. **資料のフォルダの画面**:名前とパスの一覧。できることは「足す」「パスを変える」「消す」。
    - 名前は変えられない(配布プロファイルは名前で選んでいるため。変えたいときは足してから選び直し、古いほうを消す)
    - 足す・パスを変えるときは、パスがサーバーの PC の絶対パスで、フォルダとして在ることを確かめる。同じ名前は足せない
    - 消すときに、そのフォルダを選んでいる配布プロファイルがあれば断り、プロファイルの名前を出す(「配布プロファイル 〇〇 が使っています。プロファイルで別のフォルダを選んでから消してください」)
    - その場で効かせるため、`Conversations.SetFolders` を起動のあとにも呼べるようにし、`cs.folders` を鍵で守る。
      パスを変えたら、そのフォルダを使っている会話の次のツールの実行から新しいパスになる(実行中のツールは古いパスのまま終わる)
    - パスはブラウザに返してよいのは管理者にだけ(今の「ブラウザには名前だけを見せる」は、管理者でない人にはそのまま)
11. **置く場所は管理(盾)の画面**。並列数・作業領域は「モデル」のタブの、今は表示だけの作業領域の欄を変えられるようにする形を基本にする。資料のフォルダの置き場所(どのタブか)は未決事項 1
12. **ドキュメントを直す**:`config/server.go` の冒頭のコメント(「aibow-server は書かない」)、[usage.md](../usage.md) の server.json の説明(画面で変えると書き戻すこと・`.bak`・引数と環境変数が強いこと)、
    [_docs/api.md](../api.md) の画面用の API に足したメソッド

## 作ったときに決めたこと(2026-11-24、Code。見てもらって直す)

1. **書き戻した server.json の形(未決事項 2)**:鍵の並びを保つ書き方にした(アプリの settings.json から鍵を消す `RemoveSettingsKey` と同じやり方。手間が変わらなかったため)。
   変えた鍵はその場所で値だけを差し替え、無かった鍵は最後に足す。字下げは2つの空白にそろう(値の中も)。資料のフォルダを全部消したら `folders` の鍵ごと消す。`config/serverwrite.go`
2. **`.bak`(未決事項 3)**:書くたびに上書きで1つだけ(仕様の最初の形のまま)。ファイルが無かったときは作らない
3. **出どころの判定**:`resolve` が `parallel`・`ctx` それぞれの出どころ(引数 / 設定ファイル / 環境変数 / 既定)を覚え、引数・環境変数なら変えられない理由の文を aibow-server が作って画面に渡す(`lockReason`)。
   「次の起動の値」は画面を開くたびに server.json を読み直して出す(手で書き換えたときも分かるように)。server.json に書いていないときの値(環境変数か既定)も起動のときに覚えておく
4. **資料のフォルダのパスを変えたときに効く時**:会話の仕組みはツールの呼び出しのたびにツールを作り直している(`lookupTool` → `toolsFor`)ので、返事の途中でも次のツールの実行から新しいパスになる(決定事項 10 のとおり)
5. **「使っているプロファイル」の数え方**:決まりで資料のフォルダを選んでいるプロファイル全部(配布をやめたもの・停止中のものも)。配り直したときに、黙って「資料のフォルダなし」にならないように(`store.SQLite.ProfilesUsingFolder`)
6. **フォルダの名前**:前後の空白は外す。パスは前後の空白を外して整え(`filepath.Clean`)、サーバーの PC の絶対パスで、フォルダとしてあることを確かめる。同じパスに変えるのは何もしない
7. **ログインなしで使うとき(`login: false`)**:API は管理者と同じく呼べるが、「資料のフォルダ」のタブは(「配布プロファイル」のタブと同じく)ログインした管理者だけに出すので、画面からは見えない(配布の相手がいない形なので、使い道も無い)。並列数・作業領域は「モデル」のタブなので見える
8. **API の名前**:`ServerSettings`・`SaveServerSettings`・`AddServerFolder`・`SetServerFolderPath`・`RemoveServerFolder`(`ui/web.go` の `adminServerMethods`。管理者でなければ 403)

## 完了の条件

1. 管理者が管理(盾)の画面で並列数・作業領域を変えて保存すると、server.json(`-config` で指定したファイルなら、そのファイル)に書かれ、ほかの鍵は消えずに残る。起動し直すと、その値で起動する(起動のログの「シーケンス N 本で…」で確かめる)
2. `-parallel` で起動したとき、または `AIBOW_SERVER_PARALLEL` を設定して server.json に `parallel` が無いときは、画面の並列数が変えられず、理由が出る(`ctx` も同じ)
3. 資料のフォルダを画面で足すと、起動し直さずに配布プロファイルで選べ、そのプロファイルの会話のツールがそのフォルダを読める。パスを変えると、次のツールの実行から新しいパスになる
4. 配布プロファイルが選んでいる資料のフォルダは消せず、プロファイルの名前が出る
5. 管理者でない人(ログインが要る形)は、画面にも API にも触れない(API を直接呼ぶと 403)
6. server.json が無い状態で画面から保存すると、探した場所に作られ、次の起動で読まれる
7. 書き戻しのテスト(ほかの鍵が残る・壊れたファイルには書かない・一時ファイルから置き換える)と、出どころの判定のテストがある
