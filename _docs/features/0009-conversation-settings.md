## 目的

今の設定の画面(一覧の下の歯車)は、アプリ全体の設定と「開いている会話の設定」(新しい会話の画面では、これから作る会話の設定)を同じ画面で変えている。
これを分け、会話ごとに設定を変える画面を作る。最後は、会話の中でツールを1つずつ絞る・信頼する(確認しない)ところまで、この画面で決められるようにする。

## 進め方(ユーザーと決めたこと)

- **段階に分けて作る**。まず「設定の画面 → 会話の設定」の受け渡し(新しい会話は既定の写しから始まり、会話ごとに変える)を作って確かめ、そのあと上の画面(設定の画面)から順に足していく
- ツールごとの扱いは、最後は「確認しない」まで会話の設定の画面で選べるようにする。ただし1段目ではやらない

## 決定事項

### 1段目(この段)

1. **会話の設定の歯車は、入力欄の下のメーター(会話の上限)の右に置く**。押すと開いている会話の設定の画面を開く
   - 最初は会話の一覧の各行(削除の左)に置いていた(ユーザーの指定)が、一覧を畳んでいると開けず不便だったので移した(2026-10-15、ユーザーの指示)
   - 会話を開いているときだけ出す(新しい会話の画面には出さない。これから作る会話の設定は、設定の画面の「新しい会話の既定」で決める)
2. **会話の設定の画面**(`ConversationSettingsView.tsx`)は、設定の画面と同じく、チャットの代わりに会話の場所に出す別の画面
   - 中身: その会話の設定(システムプロンプト・compact・temperature・presence penalty・思考)、「この設定を新しい会話の既定にする」、ツール(下の 5)、モデルに渡した文字列(開いている会話のものなので、設定の画面から移す)
   - 閉じるのは、「会話に戻る」・一覧で会話を選ぶ・「+ 新規」・一覧の下の歯車(設定の画面に切り替わる)
3. **設定の画面の「この会話の設定」は「新しい会話の既定」にする**(ユーザーと決めた)。開いている会話に関係なく、新しい会話の既定を直接変える
   - 変えたらすぐ保存する(会話の設定と同じく、少し待ってまとめて送る)
   - 新しい会話の画面で開いていたら、これから作る会話の設定(既定の写し)にも同じ変更を入れる
   - 「この設定を新しい会話の既定にする」は会話の設定の画面に移す(設定の画面では意味が無くなるため)
4. 会話の設定と既定の保存は、Go の今ある口を使う(会話の設定は `UpdateConversationSettings`、既定は `SetDefaultSettings`)
5. **会話の設定の画面に、この会話でのツールの状態を出す**(2026-10-15、ユーザーの指示。グループごとの使う / 使わないは今でも会話で選べるため)
   - グループ(組み込み / MCP のサーバー)のチェックは「この会話で使うか」。入力欄の上の「この会話のツール」と同じ設定(`builtin_off` / `mcp_servers`)で、ここからも変えられる
   - ツールごとのチェックで、**この会話で使うかを選べる**(会話の上書き `tool_policies`)。
     **PC の既定(設定の画面の「ツール」)の「使わない」は「使ってはいけない」ではなく「既定では使わない」の意味**なので、会話で「使う」にできないといけない(2026-10-15、ユーザーの指摘)。
     そのため、会話の上書きに「使う」(`on`)を足した。`on` は使うかだけを決め、確認するかは PC の既定・決まりの既定のまま(`tools.json` には書けない)。
     既定と同じにしたら上書きを消す(既定をあとで変えたときに付いていくように)
   - この会話で使っていないグループのツールは押せない(選んでも使われないため)
   - どこで決まったか・使えない理由を添える:「この会話で使う」「この会話で使わない」(既定と違う)・「既定で使わない」(`tools.json`)・「作業フォルダが要る」
   - 確認する / 確認しないは出さない(確認を画面で扱う段で足す)
   - 扱いは Go が決めて返す(`Conversations.ToolStates`。`toolPolicy` と同じ `policyOf` を使う)。画面で同じ判断を書き直さない(扱いを決める場所を1つにする、0006 の方針)
   - MCP のサーバーのツールは、起動していなくても、最後に起動したときに覚えた一覧(`tools.json` の `known`)から出す。一覧が無ければ「(ツールの一覧はまだありません)」
   - グループは、使っていてもいなくても畳んで出し、▶ で開ける。設定の画面の「ツール」も同じ(2026-10-15、ユーザーの指示。前は使うグループを開いたままで畳めなかった)

6. **会話の上限・返事の上限を会話ごとの設定にする**(2026-10-15、ユーザーと決めた。案B: 会話ごとに作業領域の大きさそのものを変える)
   - 今の設定の画面の値は「アプリ全体の設定」ではなく**新しい会話の既定**として扱う。会話を作るときに会話の値として写す。
     **既定を変えても、今ある会話は何も変わらない**(ほかの会話ごとの設定と同じ)
   - 会話の設定に無いもの(GPU の層数・最後に使ったモデル)は、今までどおりアプリの設定を使う。GPU の層数を会話ごとにするとモデルの読み直しになるので、プロファイル化のときに考える
   - 作業領域(`n_ctx` = 会話の上限 + 返事の上限)は1つだけ。**送信(と今すぐ要約)の前に、その会話の大きさと違えば作り直す**。会話を開いただけでは作り直さない(一覧を見て回るだけで作り直しが続かないように)。
     作り直したらトーストとログで知らせる。確保できなければ元の大きさに戻し、送信を止めて理由を出す
   - 会話の設定の画面で上限を変えるときは「適用」で反映し、そのときに作り直して VRAM に入るかを確かめる(入らなければ保存しない)。生成中・読み込み中は押せない
   - この機能より前に作った会話(上限を持っていない)は、起動したときに、そのときの既定の値を写して保存する
   - モデルの情報の「作業領域」は、開いている会話の大きさを出す(今の作業領域と違えば、次の送信で作り直すことが分かるようにする)。モデルの情報は、モデルの選択にマウスを乗せたときの吹き出しに出す
   - 環境変数 `AIBOW_HISTORY_TOKENS` / `AIBOW_MAX_TOKENS` は、新しい会話の既定の初期値(DB に値が無いとき)
   - 会話ごとに作業領域が違うと今と変わること: 大きさの違う会話に切り替えた最初の送信は、作り直しの分だけ遅く、KV キャッシュの再利用(同じシステムプロンプト・ツールの説明の部分)も効かない。VRAM が足りないときは、設定を変えたときではなく送信のときに分かることがある

7. **settings.json に足したばかりの MCP のサーバーは、新しい会話で最初から使わない**(2026-10-15、ユーザーの指示。2つ足したら、最初から使うになっていた)
   - 「ツール」のグループのチェック(`tools.json` の `notDefault`)は外したものだけを覚えていたので、足したサーバーは「最初から使う」になっていた
   - `tools.json` に aibow がすでに見たサーバー(`seen`)を持たせ、見ていないサーバーを起動したときに `notDefault` に入れる。お知らせとログで伝える
   - `seen` の無い前の `tools.json` では、今あるサーバーは全部見たことにする(それまでの扱いを変えない)。なので、この変更の前に足したサーバーは、設定の画面の「ツール」で一度チェックを外す
