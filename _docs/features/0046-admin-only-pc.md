# 0046: サーバーの PC の事情を変える操作を、ログインした管理者だけにする

- 決めた日: 2026-11-20(Chat でユーザーと決めた。下の「決定事項(ユーザーと決めたこと)」の外は、話の流れから Chat が決めて書いた)
- 前提: 0017(10-2 で「127.0.0.1 からだけ」にした)、0018(決定事項 8「127.0.0.1 から、または管理者」・決定事項 16「管理者は一人もいなくてもよい」)、
  0020(既定はログイン必須。`login: false` は 127.0.0.1 だけで待ち受けるときだけ)、0024(ツールの扱いの既定)、0032(管理(盾)の画面の出し分け)、
  0033(全員の使用量)、0044(信頼するプロキシ・`login: false` で外の元の相手は 403)

## 目的

今は、サーバーの PC の事情を変える操作(管理(盾)の「モデル」の読み込む / 降ろす・GPU の層数・置き場所・使えるモデル、「ツール」の扱いの既定)を、
**「サーバーの PC の上(127.0.0.1・::1)から来た人」か「管理者」** に許している(`api.pcSide`・`ui.Caller.ManagesPC`)。

「127.0.0.1 から」は、0017 で管理者がまだいなかったときの仮の決まりの名残り。いまは管理者がいて、利用者の管理(`/_aibow/admin/`)はもう「ログインした管理者だけ」になっている。
同じ PC の上でも、利用者の管理はできないのにモデルは降ろせる、という線の引き方には理由が無いので、**両方を「ログインした管理者だけ」にそろえる**。

学ぶこと:

- **認可を「どこから来たか」でなく「誰か」で決める**:アドレスは、リバースプロキシ・同じ PC のほかのプログラム・ヘッダーの付け忘れ(0044 の未決事項 1)で簡単に「サーバーの PC の上」に見えてしまう。
  ログインした人の印(cookie・API キー・アプリのトークン)は、偽るのにパスワードかキーが要る。権限を人に付けると、アドレスの見え方の穴が権限の穴にならない
- **同じ PC の上でも、人はひとりとは限らない**:サーバーの PC の画面を、管理者でない人がたまたま開くこともある(0044 では「サーバーの PC にほかの人がログインして使う形は考えない」としていたが、この変更でその前提に頼らなくてよくなる)

## 決定事項(ユーザーと決めたこと。2026-11-20)

1. **サーバーの PC の事情を変える操作は、ログインが要る形(既定)では「ログインした管理者だけ」**。127.0.0.1 から来たことは、もう権限にしない
   - 理由:利用者の管理と同じ線にする。ローカルで利用者の管理ができない理由が無いのなら、どちらも管理者だけでよい(ユーザーの判断)

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-20。2026-11-21、作る前にユーザーが「このまま採用」と確かめた)

### 対象の操作

2. 対象は、今 `pcSide`・`adminOnly`(`ui/web.go`)で「127.0.0.1 か管理者」にしているもの全部:
   - aibow 専用の口:`POST /models/unload`・`POST /_aibow/gpu-layers`・`POST /_aibow/places/add`・`POST /_aibow/places/remove`
   - 画面用の口のメソッド:`UnloadModel`・`SetModelGPULayers`・`ModelPlaces`・`AddModelPlace`・`RemoveModelPlace`・`SetModelEnabled`(`pcMethods`)と、
     `SetToolPolicy`・`SetGroupPolicy`・`LoadToolList`(`adminToolMethods`)
   - 画面に見せる中身:モデルの一覧の `manage`(GPU の層数・置き場所・使えないモデルも出す。`ui/serverhost.go` の `managesPC`)
   - 全員の使用量(`usageViewer`)は、ログインが要る形ではもう「管理者だけ」なので変わらない
   - `GET /_aibow/settings`・`GET /_aibow/places` は読むだけなので対象にしない(0017 の未決事項の並びには `/aibow/settings` があったが、今の口は GET だけ。下の未決事項 3)

### ログインが要らない形(`login: false`)

3. **`login: false` のときは、今までどおり全部できる**(利用者は local だけ。管理者を作れないので、断ると誰もモデルを降ろせなくなる)。
   - `login: false` は 127.0.0.1 だけで待ち受けるときしか選べず(0017・0020)、0044 の決定事項 12 で、信頼するプロキシ越しの外の元の相手は 403 になる。
     なので「`login: false` なら通す」と書けば、今の「127.0.0.1 なら通す」と同じ人だけが通る
   - 判定は「127.0.0.1 から来たか」ではなく「`login: false` の形か」で書く(どこから来たかを見るのは 0044 の決定事項 12 の1か所だけにする)
   - server.db の利用者 local の管理者の印(`users.admin`)は変えない(グループ・配るプロファイルの「管理者か」の判定に影響させない)。画面用の口の `Caller` に「ログインなしの形」の印を持たせるなど、形は Code が決める

### 呼ぶ道ごとの扱い

4. **画面用の口(ブラウザ)**:ログインが要る形では `Caller.Admin` だけを見る(`Caller.Local` は使わなくなる。消すかは Code が決める)。ログインなしの形は決定事項 3
5. **aibow 専用の口(`pcSide`)**:ログインが要る形では、API キーかアプリのトークンの持ち主が管理者のときだけ(`auth.IsAdmin`。今の `s.admin`)。
   ログインなしの形(API キーが要らない形。`KeysRequired` が偽)は通す。`IsLocal` は見ない
6. **デスクトップのアプリ**:アプリモード(手元の aibow.db)は変わらない(その PC の人が使い、この判定を通らない)。
   サーバーモード(serverUrl)は管理の画面を開かない(0032 の決定事項 9)ので、画面は変わらない。aibow 専用の口を管理者のトークンで呼べば通る(今と同じ)

### 盾(管理の画面)の表示

7. **盾を出すのは「ブラウザで、ログインした管理者」か「ログインなしの形」**(今の `canAdmin(manage)` の `manage` が、Go の新しい判定をそのまま返すので、画面の式は変えなくてよい見込み)。
   サーバーの PC の上で、管理者でない人がログインして開いた画面には、盾が出なくなる
   - 0032 の決定事項 4「管理者と、サーバーの PC から開いた画面」は「管理者と、ログインなしの形」に読み替える
   - 盾の中のタブの出し分け(利用者・グループ・配るプロファイルは `me.login && me.admin`、使用量はログインなしでも出す)は変えない

### 断るときの文と記録

8. 断る文から「aibow-server を動かしている PC からか、」を外す(例:「この操作(モデルを降ろす・GPU の層数・モデルの置き場所)は、管理者だけができます」)。
   aibow 専用の口のエラーの `code` は `local_only` から `admin_only` に変える(この code を見ているのは aibow の画面とテストだけで、外のクライアントは見ていない見込み。Code が grep で確かめる)
9. ログの Warn に、断った相手の名前(ログインしていれば)とアドレスを出す(今の `RemoteHost` に名前を足す)

### 0044(信頼するプロキシ)と B11 との関係

10. **0044 は外さない**。この変更で「プロキシ越しの外の人が 127.0.0.1 に見えると、PC の事情を変える操作ができる」穴(0042 の未決事項 1・確認表の B11)は、ログインが要る形では権限の穴でなくなる。
    それでも元の相手は、次の3つでまだ要る:
    - ログインを続けて間違えたときの制限(アドレスごと。プロキシ越しで1人が全員を止めない)
    - ログの相手のアドレス(誰が何をしたか)
    - `login: false` で外の元の相手を 403 にする(0044 の決定事項 12。決定事項 3 はこれに頼る)
11. 0044 の書きぶりを、この変更に合わせて直す(中身の動きは変えない):
    - 目的の「サーバーの PC の上からだけ許す操作が誰にでもできる」は、0046 より前の話と書き添える
    - 決定事項 2 の理由「もともとサーバーの PC の上からだけ許す操作までできる、いちばん信頼している相手」は、0046 のあとは「同じ PC のプロキシを何も書かずに使えるようにするため」だけになる、と書き添える
    - 未決事項 1(ヘッダーの付け忘れ)は、「ログインが要る形では権限の穴でなく、ログインの制限とログが粗くなるだけ。`login: false` をプロキシの後ろで使うときだけ、外の人がログインなしで入れる穴が残る」と書き直す
    - 完了の条件 2 の「管理者でない人には断られ」は、0046 のあとは**サーバーの PC の上から開いても**断られる(確かめるのは「ログの相手のアドレスがほかの PC になる」のほうが要点)
12. 確認表(プロジェクトの `aibow-checks/checklist-unverified-11.md`)の B11 は、0046 を作ったあとは「ほかの PC から、プロキシ越しでもそうでなくても、管理者でない人には盾が出ず、口を直接呼んでも 403」を確かめる行に変える(Chat が確認表を直す。Code はしない)

### 管理者が一人もいないとき

13. 0018 の決定事項 16「管理者は一人もいなくてもよい(127.0.0.1 からはいつも変えられる)」の理由が無くなる。止めはしない(今までどおり起動する)が、
    ログインが要る形で管理者が一人もいなければ、起動のときに注意を出す(下の未決事項 1 で文と強さを決める)。戻し方は今のコマンド(`aibow-server user admin <名前>`)のまま
