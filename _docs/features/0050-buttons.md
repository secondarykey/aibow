## 目的

画面のボタンは、作ったときごとに言葉を選んできたので、同じ操作が場所によって違う言葉・違う見た目になっている(洗い出しは 2026-11-21、ボタン約 170 個)。

- 消す操作が「削除」「消す」「捨てる」「この人を消す」の4通り。最初のボタンも「×」・ゴミ箱付きの赤い枠・赤い枠だけ・ふつうの色とばらばら
- プロファイルの「消す」は、ふつうの色で、確かめずに消える
- 赤にする CSS が画面ごとに書かれていて(`style.css` の `.conversation button.danger`・`.share-confirm button.danger`・`.user-field button.danger, .user-remove button.danger`)、MCP・ワークスペースの確認の「消す」は赤くならない
- 「×」が「閉じる」「一覧から外す」「会話を削除」の3つの意味で使われている
- 「しまう」「降ろす」「最初に選ぶ」「写す」など、和語の動詞で、何をするのか分かりにくいものがある

学ぶこと:

- **言葉と見た目の決まりを先に持つ**:部品ごとに決めると、作るたびにずれる。決まりを ui.md に書き、共通の部品と CSS に寄せる
- **CSS の効く範囲**:親の class で絞った書き方(`.conversation button.danger`)は、ほかの場所に置いたときに効かない。意味を表す class(`button.danger`)は絞らずに1か所で書く

## 決定事項(ユーザーと決めたこと)

1. **ボタンの文字は名詞(漢語)にする**。一般的なアプリの言い方にそろえる。対象が分かりにくいときだけ「〜を削除」のように目的語を付ける
2. **同じ操作は、どこでも同じ言葉**(下の「言葉の表」)
3. **「降ろす」は「アンロード」**(Ollama と同じ言い方)
4. **「最初に選ぶ」ボタンをやめ、プロファイルの画面の上に「既定のプロファイル」の選択肢を置く**
5. **ボタンだけでなく、説明(マウスを乗せた文・title)・見出し・確かめる文・トースト・エラーの文の中の言葉もそろえる**(ボタンと説明で言葉が違うと迷うため)
6. **削除はどこでも同じ形**(下の「削除の形」)。プロファイルの削除にも確かめる段を付ける
7. **「×」は「閉じる」と「一覧から外す」だけ**。会話の一覧の削除はゴミ箱のアイコンにする
8. **赤くする CSS を1か所にする**(`button.danger`・`button.danger-outline` をどの画面でも効くように)

## 言葉の表

| 操作 | 言葉 | 今の言葉(主な場所) |
|---|---|---|
| 消す | **削除** | 削除(会話の一覧)・消す(グループ・MCP・ワークスペース・利用者・プロファイル)・捨てる(読み込んだファイル)・このグループを消す・この人を消す |
| worktree を捨てる | **破棄**(取り込んでいない変更ごと捨てるので、削除と分ける) | worktree を捨てる・捨てる(`WorktreeDiff.tsx`) |
| やめる | **キャンセル** | やめる(確かめるところ全部)・閉じる(プロファイルを写す) |
| 作る | **作成**(会話の「新規」はそのまま) | 作る(グループ・利用者)・利用者を作る・フォルダから作る・フォルダから新しく作る・新しいプロファイル |
| 足す | **追加** | 足す(MCP・モデルの置き場所・グループのメンバー)・N 個を足す |
| 保存 | 設定の画面でまとめて書くのは **保存**、その場の1項目に効かせるのは **適用**(今の使い分けのまま) | 保存・適用 |
| パスワードを変える | **パスワードを変更** | `AccountSettings.tsx` |
| 写す | **複製**(「写して続ける」→「複製して続ける」・「写して配る」→「複製して配布」) | 写す・写して続ける・写して配る |
| 配る | **配布**(「配るのをやめる」→「配布を停止」・「配られたプロファイル」→「配布されたプロファイル」) | `SharePicker.tsx`・`ProfileSettings.tsx` |
| しまう / 戻す | **アーカイブ** / **アーカイブ解除**(札も「しまってある」→「アーカイブ済み」) | `ProfileSettings.tsx` |
| 読み込む / 降ろす | **読み込み** / **アンロード**(トースト「…を降ろしました」→「…をアンロードしました」) | `ModelSettings.tsx`・`useModels.ts`・`ModelBar.tsx` |
| 決める(パスワード) | **設定** | `Login.tsx` |
| 読み取る(JSON) | **読み取り** | `McpEditor.tsx` |
| 取り込む(worktree) | **取り込み**(「取り込む(N ファイル)」→「取り込み(N ファイル)」) | `WorktreeDiff.tsx` |
| 試しにつなぐ(MCP) | **接続テスト** | `McpEditor.tsx` |
| 一覧から外す | アイコンの「×」のまま。説明は「〜から外す」(物そのものは消えない) | メンバー・共有の相手・置き場所・フォルダ |
| 送り直す・作り直す | **再送信**・**再生成**(0048 の D8 のエラーの横のボタンも「再生成」) | `ChatView.tsx` |

表に無い言葉も、決定事項 1 の決まりで直す(例:「リンクを出す」→「リンクを発行」、「読み込み直す」→「再読み込み」)。
「新規」「接続」「ログイン」「ログアウト」「拒否」「実行」「停止」「コピー」はすでに名詞なのでそのまま。

## 削除の形

1. **最初のボタン**:ゴミ箱のアイコン(`LuTrash2`)+「削除」、赤い枠(`danger-outline`)。一覧の行の中など狭い所は、ゴミ箱のアイコンだけ(説明に「削除」)
2. **必ず確かめる**:「〜を削除しますか?」(消えるものがあれば一言添える)+ **「削除」(赤く塗る `danger`)**・**「キャンセル」**
3. 今の「この人を消す」の名前を打たせる確認(`UserSettings.tsx`)のような、重い削除のための追加の確認はそのまま残す
4. worktree の「破棄」も同じ形(アイコンはゴミ箱、言葉は「破棄」)

## 決定事項(話の流れから Chat が決めて書いたこと)

2026-11-21、着手の前にユーザーがこのとおりでよいと確かめた。

- **既定のプロファイルの選択肢**:プロファイルの画面(設定の「会話」のタブ)の上、プロファイルの一覧の前に「既定のプロファイル」のセレクトを置く。中身は選べるプロファイル(自分のもの・配布されたもの。アーカイブ済みは除く)。
  変えたら `ChatService.SetDefaultProfile` を呼ぶ。一覧の「最初に選ぶ」の札は「既定」にする。管理の画面の「配るプロファイル」には置かない(既定は人ごとの設定なので)。形は Code が画面で案を出してよい
- **共通の部品**:削除の形(最初のボタン → 確かめる)は、`components/` に1つの部品(例:`DeleteButton`)にまとめ、今の各画面の確かめる処理を置き換える。部品にするかは Code が決めてよいが、見た目と言葉は上の形にそろえる
- **主のボタン**:その場所でいちばん押す操作だけを `primary` の色にする(1つの場所に1つ)
- **0049 との重なり**:確認のカード(`ToolCard.tsx` の `Confirm`)のボタンの並びは 0049 で変える。言葉はこの仕様の決まり(拒否・実行)に合わせる
- **ドキュメント**:`_docs/ui.md`・`_docs/usage.md`・README などで画面のボタンの名前を書いているところも、新しい言葉にそろえる(古い仕様は直さない)

## やらないこと

- ログの文(0048 で扱う)。ただし、ログが画面の操作の名前を書いているところ(「プロファイル … をしまう」など)は新しい言葉にそろえる
