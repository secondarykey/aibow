## 目的

リリース版(`wails3 build` の exe)はコンソールを持たないので、ログがどこにも残らなかった。
ファイルに書くことを含め、ログの仕組みを作る。あわせて、aibow をライブラリとして使う人が自分のログとまとめて扱えるようにする。

## 決定事項(ユーザーと決めたこと)

1. **ログの土台は `github.com/wenteasy/log`**(ユーザーの指定)。ただし aibow を使う人には wenteasy/log を意識させない。
   wenteasy/log を import するのは `aibow/log` の中だけで、見せるのは `slog.Level` と `*slog.Logger` だけ
2. **aibow のコードは `aibow/log` からログを出す**(標準の `log`・`slog`・wenteasy/log を直接使わない。`_cmd/aibow` も同じ)
3. **形は shinte/ikkyoku の `log` に揃える**。出す関数は自前(`runtime.Callers` で呼び出し元を取る。wenteasy/log の関数を包まない)、
   `Init(Options) (io.Closer, error)` で出口を組む、`Options.Root` で出すレベル、`CatchCrash` で異常終了を残す
4. **`SetLogger(*slog.Logger)` を残す**(ikkyoku には無い)。aibow はライブラリとしても使われるので、使う人が aibow のログだけを別の出し先・別のレベルにできるようにする。
   決めなければ `slog.Default()` に出る
5. **`wails3 dev` はターミナル、exe はファイル**。exe は `%APPDATA%\aibow\logs\aibow_<日付>.log`(日ごと)
   - 2026-10-16 追記(ユーザーの指示): **dev もターミナルとファイルの両方**に書く(不具合をあとから調べられるように)。ファイルは同じフォルダの `aibow-dev_<日付>.log`
     (exe と同時に動かすことがあるので頭を分ける。異常終了は `aibow-dev_crash.log`)。dev も 10 日分を残して古いものは消す
6. **exe は古いログを消して 10 日分を残す**(今日を含む)
7. **exe は NOTICE 以上だけを書く**。dev は INFO 以上。
   INFO は開発中・学習で観察するもの(生成の統計・ツールの実行・compact など)、NOTICE はレベルを上げても常に残したいもの
   (起動した版・ログと会話の保存先・計算装置・読み込んだモデル・利用者が変えた設定・確認せずに実行したツール・つながった MCP のサーバー)
8. **異常終了の内容もファイルに残す**(`aibow_crash.log`。次の起動で改名して「前回は異常終了しました」を伝える)
9. 使う側の作り方は、wenteasy/log の README「使う側のやり方(自分の log パッケージを作る)」を正にする(各セッションで形がばらつかないように。v0.3.2〜)

## 決定事項(作りながら Code が決めたこと)

- 置き場所は会話の DB・設定ファイルと同じ `%APPDATA%\aibow` の下(TODO.md に書いてあった案)。`AIBOW_LOG_DIR` で変えられる
  (試しに起動するときに、ユーザーのフォルダに書かないため。`_docs/testing.md`)。dev でも `AIBOW_LOG_DIR` を指定したときだけファイルに書く(消さない)。
  → 2026-10-16 に、dev もいつもファイルに書く(`aibow-dev_<日付>.log`・10 日分)ように変えた(決定事項 5 の追記)
- 日付はファイルの更新時刻ではなく、名前(`aibow_20261014.log`)から読む(コピーや展開で更新時刻が変わるため)。名前の形が違うファイルは消さない
- ログが書けなくても起動は止めない。理由は画面のお知らせに出す(`startLog` は画面に出すお知らせを返し、`main` が画面とログの両方に出す。二重に書かない)
- Wails には `application.Options.Logger` に `slog.Default()` を渡す。渡さないと Wails は `slog.Default()` を使わず、dev は自分の書式で標準エラー出力、
  **exe では自分のログを捨てる**(v3.0.0-beta.26 の `application.go` で確かめた)
- WebView2 の行(`[WebView2] …`)は Wails の中で標準の `log.Printf` で書かれる。`slog.SetDefault` のあとは標準の `log` も slog の出口に流れるが、
  レベルを持たない(Info 扱い)ので、`Init` が `slog.SetLogLoggerLevel(Root)` で出すレベルに合わせ、exe でも捨てない
- 「※」で始めていた注意は `Warn`、失敗は `Error` にした(レベルで表す)
- `mcp/client` の `Options.Logf`(ログの出し先を関数で受け取る)はやめ、`aibow/log` に一本化した。テストは `log.SetLogger` でログを集める
- 異常終了のうち、画面から呼ばれたメソッドの中の panic は Wails が recover して Logger に Error で書くので、ログファイルに入る。
  `CatchCrash`(`debug.SetCrashOutput`)が拾うのは、aibow の goroutine の panic とランタイムの致命的なエラー

## 構成

| 場所 | 役割 |
|---|---|
| `log/log.go` | 出す関数(Trace〜Error と `…f`)・段階(`Level*`)・`SetLogger` / `Logger` |
| `log/setup.go` | `Init(Options)`(`Dir`・`KeepDays`・`Root`・`Console`)・`FilePath`・古いファイルの片付け |
| `log/crash.go` | `CatchCrash`(異常終了の記録) |
| `log/AGENTS.md` | 崩さないこと(エージェント向け) |
| `_cmd/aibow/main.go` | `startLog`(dev / exe で組み分ける。`logKeepDays = 10`)・Wails に `Logger` を渡す |

## やり残し(TODO.md の「ログの続き」)

着手するときは、相談してからこの文書に書き足す。

1. **パッケージごとのレベルの設定**:「`mcp/client` だけ Debug」のような絞り方(ikkyoku は `ikkyoku-log.json` と wenteasy/log の `PackageLevelHandler`)。
   画面から全体のレベルを変える(ikkyoku の「ログの細かさ」)かどうかも、ここで決める
2. **llama.cpp のログをファイルに入れる**:`AIBOW_LLAMA_LOG=1` のログは C の側が標準エラー出力に書くので、exe では残らない。
   yzma の `llama.LogSet(cb)` に自分のコールバックを渡せば `aibow/log` に流せる(`purego.NewCallback` で作る)。
   ⚠️ purego(yzma が内部で使っている)を aibow から直接 import することになるので、外部パッケージを足す確認が要る
3. **llama.cpp の C の異常終了(GGML_ASSERT など)は残らない**:Go のランタイムを通らず、C の標準エラー出力に書かれて終わる(`_docs/known-issues.md`)
4. **MCP のサーバーのエラー出力(stderr)が exe に残らない**:`mcp/client` が Info で出しているので、NOTICE 以上の exe では捨てられる。
   起動に失敗したときの最後の行はエラーの文に入るので残る。Warn にする・数を絞って残す、などを考える。
   自作の MCP サーバー(aibow-mcp)は、自分でもファイル(`aibow-mcp_<日付>.log`)に書くようにした(2026-10-15。0007 の決定事項 11)。既製のサーバーのものは残らないまま
5. **dev のターミナルが Wails の `[AssetFileServerFS] Handling request` で埋まる**(画面のファイルを読むたびに Info で十数行。exe は NOTICE なので出ない)。1 と一緒に考える
6. **画面からログを見る手段が無い**:「ログのフォルダを開く」、binder のようなログビューア、起動できないときのお知らせにログの場所を添える、など
7. **MCP のサーバー側・クライアント/サーバー構成のログ**は別に考える(TODO.md の元の項目で、ユーザーと決めた)。
   MCP のサーバー側は、aibow-mcp がアプリにならって `aibow-mcp_<日付>.log` に書くようにした(2026-10-15。`Options.Prefix` を足した。0007 の決定事項 11)。残りはクライアント/サーバー構成のログ

## 確かめたこと

- `go test ./log/`:出す関数とレベルの足切り・記録される位置が呼んだ側になること・`SetLogger` / `slog.Default()` に出ること・`Init` がファイルに書くこと・
  フォルダを作れなくても止まらないこと・古いファイルを消して 10 日分を残すこと(名前の形が違うものは消さない)・`Root` より下を出さず標準の `log` の行は捨てないこと・
  本当に panic させた子プロセスの内容が `aibow_crash.log` に残ること
- exe を一時フォルダに向けて(`AIBOW_LOG_DIR` など。ユーザーのフォルダに触れない)起動し、ファイルに NOTICE 以上だけが残ること・Wails 本体のログと WebView2 の行が入ること・
  11 日前のファイルが消えて 10 日目が残ること・一時的なビルドで panic させて記録が残り、次の起動で改名されて知らされることを確かめた
