## 目的

今はツールを実行する前に確認する(「確認する」)。書き換えるツール・コマンド・MCP のツールは毎回聞かれ、1つの頼みごとで何回も確認が出る
(Blender の MCP で4回。TODO.md)。信頼したツールは確認を省けるようにする。
組み込みのツールを自作の MCP サーバーに移すと(ステップ5)、読むだけのツールまで毎回確認されるので、その前にやる。

## 決定事項

### 1段目(この段)

1. **「確認しない」(`allow`)を2か所で選べるようにする**(ユーザーと決めた)
   - 設定の画面の「ツール」(PC の既定。`tools.json`): ツールごとと、グループ(組み込み / MCP のサーバー)ごとまとめて
   - 会話の設定の画面の「ツール」(この会話だけ。会話の `tool_policies`): ツールごと
2. **扱いは値の名前で持つ**(ユーザーの提案。真偽値の組み合わせにせず、あとで動きを足すときは値を1つ足す)。今の値:

   | 値 | 意味 | 置ける場所 |
   |---|---|---|
   | `off` | 使わない(モデルに見せない) | 会話・PC(ツールごと) |
   | `ask` | 使う。実行する前に確認する | 会話・PC |
   | `allow` | 使う。確認しない | 会話・PC |
   | `on` | 使う。確認するかは PC の既定のまま(PC の既定の `off` を打ち消すだけ。0009) | 会話だけ |
   | (無し) | 決めていない。次の層を見る | — |

   決め方は今までどおり、会話の上書き → PC の既定(ツールごと → グループごと)→ 決まりの既定(`Conversations.policyOf` の1か所)
3. **確認のカードからあとで足す操作も、この値で表す**(ボタンは次の段)
   - 「この会話では今後聞かない」= 会話の上書きを `allow`
   - 「今後許可しない」= 会話の上書きを `off`(モデルから隠す。ユーザーと決めた。隠すので会話の上限の節約になり、モデルも呼ばなくなる。次の送信からプロンプトの先頭が変わるので KV キャッシュは効かない)
   - 確認の答え(`Confirmation`)に「これから先の扱い」(`Remember`。`ToolPolicy` の値。空ならこの1回だけ)を持たせ、答えたときに会話の上書きに書く
   - 送信の途中(ツールのループの中)で会話の上書きが変わったら、次のツールの呼び出しから効く(ツールを呼ぶたびに会話の設定を読み直す)。
     「今後許可しない」にしたツールは、その送信のプロンプトにはまだ載っているが、呼ばれたら「ツール … はありません」を返す
4. 画面の形
   - ツールの行に「確認しない / 確認する」を切り替える小さな枠を置く(使うツールだけ)。「確認しない」は橙で出す(今の `tools.json` の印と同じ色)
   - グループの見出しにも同じ枠を置き、グループごとまとめて切り替える(PC の既定だけ)
   - 確認の扱いは Go が決めて返す(`ToolStates` / `ToolDefaults`)。画面で同じ判断を書き直さない
5. 会話の上書きを1つだけ書き換える口を Go に置く(`Conversations.SetToolPolicy`)。確認の答えから使う(画面の保存の待ち時間と関係なく、すぐ効くように)
