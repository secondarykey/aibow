## 目的

aibow の新しい会話のシステムプロンプトは「あなたは親切なアシスタントです。日本語で簡潔に答えてください。」と、作業フォルダの説明(`# Environment`)だけで、
**エージェントとしての決まり(どこまで続けるか・最後に確かめるか)が書かれていない**。

0040 の試し(2026-11-06。課題 C を 8 回)で、会話の上限が尽きる回は 4 → 0 になり、`go test` が通ったのは 7/8 になった。
残った失敗は上限ではなく**振る舞い**だった:

- テストのファイル(`search_test.go`)のほうを書き換えて「直した」と答えた(1回)
- 「もう書いてある」と答えて、直さなかった(1回)
- `search_files` を同じ形で続けて呼び、同じエラーの繰り返しで止まった(1回)

Cline はシステムプロンプトに「最後に必ず確かめる」「終わるまでツールを呼び続ける」と書いてあり、4B でも自分でテストを実行した(0012 の 6-3)。
**作業フォルダのある会話に、短い「作業の決まり」を足し、残った振る舞いの失敗を減らす**。あわせて、直したあとに確かめる道具として、読むだけの Git のツールを足す(段2)。

学ぶこと:

- **エージェントの振る舞いはシステムプロンプトで決まる**:同じモデルでも、決まりの数行で「どこで止まるか」「何を確かめるか」が変わる。Claude Code・Cline がシステムプロンプトに何を書いているか
- **小さなモデルに効く書き方**:長い説明より、守れたか外から確かめられる短い決まり(「直したら go test を動かす」)。決まりを足すたびに、1行ずつ試して効いたかを見る
- **決まりの副作用**:決まりを足すと、別の頼みごと(質問だけ)でも余計なことをする(0037 の「予定の1行」で探し回る回が増えた)。足したら、効かせたくない場面も試す
