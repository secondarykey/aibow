## 目的

今の組み込みは時刻・計算・`list_files`・`read_file`・`write_file`・`edit_file`・`run_command`(2026-11-02、ユーザーと話した。backlog の「コーディングエージェント向けの組み込みのツール」)。
コードを探すには、`read_file` で丸ごと読むか、`run_command` で確認を挟むしかない(cmd.exe には grep が無い)。小さなモデルは長い作業で手順を見失いやすい。
**ファイルの中を探す・名前で探す・作業の予定を書く、の3つを組み込みにする**。

学ぶこと:

- **会話の上限を使わずに探す**:ファイルを丸ごと読む代わりに、一致した行だけを返す。Claude Code の Grep / Glob がなぜあるのか
- **ツールの数とプロンプトの大きさ**:ツールを1つ足すたびに、説明がシステムプロンプトに入る。新しいツールにするか、今のツールに引数を足すかの決め方
- **予定を「状態」として持つ**:TodoWrite のように、モデルが書いた予定を会話の仕組みが覚え、compact で古い発言を捨てても残す

## 今の作り(2026-11-02、Chat がコードを読んで確かめた)

- フォルダのツールは `tool.FilesIn(folders)` が作る(`list.go`・`read.go`・`write.go`。共通は `files.go` の `folderSet`)。フォルダが複数なら `folder` の引数(`withFolder`)、1つなら出さない
- `list_files` は浅い順に 500 件か 8,000 文字で切り、`.git`・`node_modules` を飛ばし、隠しフォルダには入らない(`list.go`)
- `read_file` は 200 行か 8,000 文字で切る。テキストかどうかは `readText`(NUL・UTF-8 でない・10MB 超はエラー)
- 環境の説明(`environment`)は、`run_command` を使うときに `Shell for run_command: cmd.exe (use dir, type, findstr; ls, cat and grep are not available)` と書く
- aibow-server の資料のフォルダでは、list/read/write/edit を出し、`run_command` は出さない(0024)

## 決定事項(ユーザーと決めたこと。2026-11-02)

1. **今回作るのは3つ**:ファイルの中を探す(`search_files`。grep に当たる)・名前で探す(glob)・作業の予定(`update_plan`。TodoWrite に当たる)
2. **名前で探すのは、`list_files` に `pattern` の引数を足す形**。ツールの数を増やさず、小さなモデルのプロンプトを増やさないため
3. **git(状態・差分)はあとで**。worktree の構想(「コーディングエージェントとして洗練する」)と一緒に考える

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-02 にユーザーが確かめた)

### search_files

4. **引数**:`pattern`(必須。Go の `regexp`。RE2 の書き方)・`path`(省略可。探すフォルダかファイル)・`glob`(省略可。`*.go`・`**/*_test.go` のようにファイルを絞る。書き方は決定事項 9 と同じ)・`ignore_case`(省略可)・`folder`(0035。フォルダが複数のときだけ)
5. **結果**:`パス:行番号: 行` を1行ずつ(パスは作業フォルダからの相対・`/` 区切り)。100 件か 8,000 文字の早いほうで切り、最後に「一致は全部で N 件(M ファイル)。path か glob で絞ってください」。
   一致が無ければ「見つかりませんでした」(エラーにしない)。長い行は 300 文字で切る(read_file の 1,000 文字より短く。一覧として読むものなので)。前後の行は出さない(要るなら read_file の offset で読む)
6. **たどり方は list_files と同じ**:`.git`・`node_modules` を飛ばし、隠しフォルダは path に指定したときだけ入る。浅い順・名前の順。
   NUL を含む・UTF-8 でない・1MB を超えるファイルは黙って飛ばす(読めないファイルの一覧で結果が埋まらないように。飛ばした数は最後に書く)
7. **読むだけ・os.Root の中なので確認は要らない**(決まりの既定は list_files・read_file と同じ「確認しない」)
8. **環境の説明**:search_files があるときは、シェルの行の `findstr` の案内を「ファイルの中を探すときは search_files を使う」に変える(4B が `run_command` で findstr を呼んで確認を挟むのを防ぐ)

### list_files の pattern

9. **`pattern`(省略可)を足す**:`*.go`(どの深さでも名前が合うもの)・`**/*.go`・`cmd/**/main.go`・`*_test.go` のような形。`/` を含まない pattern は名前だけと比べ、含むものは作業フォルダからの相対パスと比べる。
   `**` は標準の `path.Match` に無いので自分で書く(`/` で区切って1段ずつ合わせ、`**` は0段以上)。中括弧(`{a,b}`)は作らない
10. pattern を付けたときはファイルだけを返し(フォルダは返さない)、上限と並べ方は今の list_files と同じ。0 件なら「合うファイルはありません」

### update_plan

11. **引数は予定の全部**:`items`(配列。項目ごとに `text` と `status`(`pending` / `in_progress` / `done`))。毎回まるごと書き直す形(1つだけ変える指示は、小さなモデルが番号を取り違えやすいため)。
    `in_progress` は1つまで(2つ以上なら、エラーで「1つにしてください」)
12. **結果は短く**:「予定を覚えました(N 件中 M 件済み)」だけ。書いた予定はモデルが自分の呼び出しとして履歴に持っているので、結果で繰り返さない
13. **予定は会話の仕組みが覚える**(最後の `update_plan` の呼び出しの引数がその会話の今の予定)。保存の形を変えずに、履歴の呼び出しから読む。
    **compact で `update_plan` の呼び出しを含む発言を捨てた・要約したときは、最後の予定を要約の後ろ(truncate なら残した発言の前)に、システムの文として足す**(「Current plan: …」。英語)。予定を残すための仕組みで、毎回の送信で足すのではない(KV キャッシュの使い回しを崩さないため)
14. **`update_plan` は作業フォルダがある会話だけで出す**(コーディングの作業のためのもので、ふつうの会話のプロンプトを増やさない)
15. **画面**:返事の吹き出しの中で、`update_plan` のツールのカードを予定のチェックリストとして出す(ほかのツールのような「引数と結果」ではなく)。見た目は未決事項
16. aibow の中の MCP サーバー越し(0007)でも同じに動く。aibow-mcp でも出す(ほかのクライアントからは、結果の文だけが見える)

### 共通

17. **どこで使えるか**:`search_files` と `list_files` の pattern は、アプリ・aibow-mcp・aibow-server の資料のフォルダ(0024)のどれでも。`update_plan` はフォルダのある会話ならどこでも(資料のフォルダの会話でも)
18. **ツールの説明は英語**(ほかのツールと同じ)。4B で試して、呼び方を間違えるなら説明を直す(0035 の `folder` と同じ進め方)

## 作業中に決めたこと(Code。ユーザーの確認待ち)

- glob:Windows の `\` は `/` に直す(4B が `cmd\**\main.go` と書いても合うように。`path.Match` の `\` によるエスケープは使えなくなる)。頭の `./`・`/` は省く。大文字と小文字は区別する(`path.Match` のまま)
- glob の `**` は段の全体のときだけ。`a**b` のように段の一部なら `path.Match` の `*` と同じ
- `list_files` の pattern で 0 件のときは「(pattern *.ts に合うファイルはありません)」。上限で切ったときの文は pattern が無いときと同じ
- `search_files` の結果の文は日本語(ほかのフォルダのツールの添え書きに合わせた):0 件は「(見つかりませんでした)」、
  切ったときは「(一致は全部で N 件(M ファイル)あり、100 件までを並べました。path か glob で絞ってください)」、
  飛ばしたときは「(バイナリ・UTF-8 でない・1 MB を超えるファイル K 件は、探さずに飛ばしました)」
- 行の頭の空白(字下げ)は削らない(edit_file の old_string にそのまま写せるように)。300 文字で切った行は最後に `…` を付ける
- `path` にファイルを名指ししたときは `glob` を見ない(選んだファイルなので)
- 時間切れ(既定の 10 秒)のときは、途中までの結果を返さず「時間内に探しきれませんでした。path か glob で、探す範囲を絞ってください」のエラーにする(全部の件数が書けないため)
- 引数 `ignore_case` は JSON Schema の `boolean`(`tool.Args` に `Bool` を足した)
