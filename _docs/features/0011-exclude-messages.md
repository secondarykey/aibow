# 0011: 選んだやり取りをモデルに渡さない

- 状態: ✅ 完了(2026-10-15。大きいほうの案(モデルに渡さない)と、小さいほうの案(作り直す・送り直す)の両方)
- ロードマップ: ロードマップの外(ステップ5の前にやる、と決めたもの)
- 決めた日: 2026-10-14(大きいほうの案にする)・2026-10-15(外す単位など。Code のセッションで、ユーザーと決めた)
- 前提: 0001(会話の保存)・0002(compact。要約と薄い表示)・0004(ツールを使う送信の発言の並び)

## 目的

mermaid の描画に失敗した返事と「直して」の往復のように、要らなくなったやり取りを、ユーザーが選んでモデルに渡さないようにする。
2-2 の compact を使ってみて欲しくなったもの(`_docs/tuning.md`)。自動で古い部分を収める compact とは別。

学ぶこと: モデルに渡す履歴はアプリが毎回組み立てている(モデルは覚えていない)ので、何を渡すかはアプリが自由に選べる。
その代わり、途中を変えると、そこから後ろの KV キャッシュは使えなくなる。

## 決定事項

1. **大きいほうの案**: 吹き出しを選んで「モデルに渡さない」にする。画面からは消さず、薄く残す(2026-10-14)
2. **外す単位は吹き出しごと**: ユーザーの発言1つ、または返事1つ(1回の送信の返事。ツールの呼び出しと結果も含む。次のユーザーの発言の前まで)。
   - mermaid の例「質問 → 壊れた図 → 直して → 直った図」は、「壊れた図」と「直して」を外すと「質問 → 直った図」になる(組ごとに外すと、どちらの組を外しても足りなかった)
   - 返事はツールの呼び出しと結果を一緒に外す(片方だけ残ると、呼び出しと結果の組が壊れる)
3. **操作の場所**: 吹き出しの下の行(発言は「時刻 コピー」、返事は「コピー 時刻 詳細」)に切り替えのボタンを置く。押し直せば戻せる
4. **表示**: 外した吹き出しは薄く出し、点線の枠にする(要約に入った・truncate で外れた発言の薄い表示と見分けるため)
5. **保存の場所**: 発言の表(`messages`)に列 `excluded` を足す(マイグレーション 版4)。会話の設定には入れない
6. **モデルに渡す履歴から外す**: 送信・メーター・今すぐ要約で履歴を読んだところで外す(`Conversations.forModel`)。外したあとの並びで組を数え直す
   (上の例なら「質問」の組に「直った図」が続く形になる)。truncate・summary もこの並びで行う
7. **要約との関係**: 外した発言は、これから作る要約にも入れない。すでに要約に入っているものは、外しても要約の中に残る。
   要約より前の発言を戻しても、要約には入らない(要約より前はモデルに渡さないため)
8. **生成中の会話では切り替えられない**(生成中は削除できないのと同じ。途中で履歴が変わらないように)
9. 作り直す・送り直す(小さいほうの案)は、最初は入れなかった。あとで入れることにした(下の「作り直す・送り直す」。2026-10-15)

### 作り直す・送り直す(小さいほうの案。2026-10-15、ユーザーの指示)

効くのは**条件を変えてやり直す**とき(ツールをオンにして作り直す、4B でだめだった質問を 9B に切り替えて作り直す、など)。
同じ条件では、モデルの癖で同じ間違いをしやすい(ユーザーの感想)。失敗した往復がそもそも残らないので、モデルが「できない」をまねすることもない。

10. **最後の返事を作り直す**: 最後のユーザーの発言の後ろ(返事とツールの結果)を消し、今のモデル・設定でもう一度返事を作る(`Conversations.Regenerate`)
11. **最後の発言を直して送り直す**: 最後のユーザーの発言とその返事を消し、直した文で送る(`Conversations.Resend`)
12. 作り直す前の返事は**消す**(モデルに渡さないにして残す 0011 の形ではない。TODO の「失敗した往復がそもそも残らない」)
13. 消すのは、収まるか(会話の上限)を確かめてから。送れないときに、前のやり取りだけが消えないように
14. 送信と同じ流れ(作業領域・MCP のサーバーの起動・送る前の要約・ツールのループ・`done`)を使う(`Send` と入り口だけ違う)
15. 対象は最後のやり取りだけ。最後の発言を「モデルに渡さない」にしているときは作り直せない(渡さない発言への返事になるため)
16. 画面: 最後の返事の下の行に「作り直す」(更新のアイコン)、最後の発言の下の行に「直す」(鉛筆のアイコン。押すと吹き出しの中で直せる。「送り直す」「やめる」)。生成中・読み込み中は押せない。
    押したら表示から最後のやり取りを外して返事を流し、エラーがあれば会話を開き直して元の表示に戻す(Go は消していない)
17. 前の返事でツールが行ったこと(ファイルの書き換え・コマンド)は、作り直しても元に戻らない

## 気をつけること(わかっていること)

- 外した発言より後ろは、KV キャッシュが再利用できない(プロンプトの途中が変わるため)。統計行の「再利用」で見える
- 外すと「タグを混在させない」のような教えも消えるので、次でまた同じ間違いをしうる(残したい教えはシステムプロンプトに書く、など)

## やらないこと

- 外した発言を要約からも取り除く(要約を作り直すことになる)
