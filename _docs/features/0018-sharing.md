# 0018: 共有(管理者・会話の公開範囲・共有の作業)

- 状態: ✅ 完了(2026-10-23。11-0〜11-3。確かめ方と見ていないことは「11-3 で確かめたこと」)
- ロードマップ: ロードマップ2 ステップ 11
- 決めた日: 2026-10-23(Chat でユーザーと決めた)
- 前提: 0013(検討メモ。共有で変わること・守らせられる場所)、0014(プロファイルと決まり)、0016(ブラウザでは PC の事情を見せない)、0017(利用者・ログイン・API キー・持ち主・保存の口・生成中の印)

## 目的

**組織の中で、会話と「作業の型」を分け合えるようにする**。
ステップ10で入れた「自分のものだけ」に、「管理者」という役割と「共有された相手」を足す。

```
管理者 ── 利用者を管理する・サーバーの PC の事情を変える・共有の作業(プロファイル)を配る・全員の会話を読める(読めることは全員に見える)
利用者 ── 自分の会話を「非公開 / 指定した人 / 全員」に共有する・共有された会話を読む・写して自分の会話として続ける
```

学ぶこと:

- **認可**:ステップ10は認証(この人は誰か)と「自分のものだけ」。ステップ11で、読み出しが「持ち主か・共有されているか・管理者か」の判定になる。判定をどこに1か所で置くか
- **共有の作業 = プロファイル + 誰が使えるか**(0013):Claude の Projects に近いもの。決まり(固定・使えない)を、配る側が決めることの意味
- **守らせられる場所**(0013):ブラウザ(B)はサーバーで判定するので全部守れる。アプリ(C)はループとツールが手元なので、配ったプロファイルのツールの禁止は「アプリが守る約束」にとどまる
- **見られることを知らせる**:管理者が読めることを隠さず、画面に出し、読んだ記録を残す(組織の道具の監査と、利用者の安心の両立)

## 決定事項(ユーザーと決めたこと。2026-10-23)

1. **管理者はほかの人の会話を読める**
   - 読めることを、全員の画面(ブラウザとアプリ)に常に出す。出し方は Code が案を示す(未決事項)
   - 管理者がほかの人の会話を開いたら、ログ(Notice)に「誰が・誰の・どの会話を」読んだかを残す
   - 管理者も、ほかの人の会話には書き込めない(読むだけ。下の 2 と同じ)
   - 理由:0013 で「管理者は全部の会話を見られる」がユーザーの最初の考え。アプリ(C)ではツールの結果(手元のファイルの中身・コマンドの出力)も会話に入るので、読まれうることを利用者が知っていることが大事
2. **共有された会話は読むだけ。続けたいときは「写して自分の会話にする」**
   - 共有の範囲は会話ごとに「非公開(既定)/ 指定した人 / 全員」
   - 写すと、写した人が持ち主の新しい会話になる。発言・要約・「モデルに渡さない」の印(0011)も写す
   - 同じ会話に複数の人が書き込む形(共同で使う)は作らない。持ち主のプロファイル・作業フォルダ(アプリの手元)・生成中の印(0017)が人をまたいで複雑になるため
3. **共有の作業(プロファイルを配る)は管理者だけが作り、全員か指定した人に配る**
   - 配ったプロファイルの決まり(固定・使えない。0014)は、配った管理者が決める
   - グループ(チーム)は作らない。配る相手は名前で選ぶ
4. **ステップ11を、ロードマップの外の「画面から aibow-server に切り替える(アプリのログイン)」より先にする**
5. **ロードマップの外の「aibow-server の中央の制御」のうち、次の2つをこのステップに入れる**(2026-10-23、ユーザーと決めた。管理者ができるので、ここが入れどき)
   - **サーバー全体で使えるモデルを管理者が決める**:配るプロファイルの「使えるモデル」(0014)の外枠になる。9B を読み直すたびに全員の KV キャッシュが消える、のような使い方をサーバーの側で止められるようにする
   - **モデルの ID からサーバーの PC のパスを外す**(今は `file:D:\…\gemma-4-E4B-it-Q4_K_M.gguf` の形。`/v1/models` で Cline にも、共有した会話の設定にも出る)
   - 中央の制御の残り(作業領域や返事の上限の上限・順番待ちの優先度・使われなければ自動で降ろす)は入れない(下の「やらないこと」)

## 決定事項(話の流れから Chat が決めて書いたこと。2026-10-23 にユーザーが確かめた)

6. **管理者は aibow-server のコマンドで決める**(例: `aibow-server user admin <名前>` / 外す形。形は Code が決める)。
   最初の管理者を画面から決める道は作らない(サーバーの PC でコマンドを打てる人が決める。0017 の決定事項 4 の続き)
7. **利用者の管理を画面にも出す**(管理者だけ。ブラウザの設定の画面)。作る・パスワードと API キーの作り直し・消す。
   パスワードと API キーは、作ったときに一度だけ画面に出す(今のコマンドと同じ考え方)。コマンドは残す
8. **サーバーの PC の事情を変える口は「127.0.0.1 から、または管理者」**(0017 の 10-2 で「ステップ11の管理者で決め直す」としたもの)。
   管理者は、ブラウザの設定の画面のモデルのタブで、読み込む / 降ろす・GPU の層数・置き場所を変えられる(0016 の決定事項 6 の「ブラウザでは見せない」を、管理者だけ外す)
9. **配ったプロファイルは、受け取った人には読むだけ**。新しい会話で選べるが、値は変えられない。変えたい人は「写して自分のプロファイルにする」
10. **配ったプロファイルを管理者が変えたら、受け取った人の今ある会話にも決まりが効く**(0014 の「あとから決めても今ある会話に効く」と同じ)
11. **会話の一覧に「共有されたもの」を分けて出す**(見た目は Code が案を示す)
12. **共有した会話を開くと、ツールの結果もそのまま見える**(持ち主が共有すると決めたので)。共有するときの確認の文に、そのことを書く
13. **使えるモデルは、管理者がブラウザの設定の画面のモデルのタブで選ぶ**。覚えるのはサーバーの PC(`server-models.json` と同じ考え方。置き場所は Code が決める)。初めは全部使える(今の動きのまま)
    - 使えないモデルは、一覧(`/v1/models`・画面)に出さず、リクエストで頼まれても読み込まない(OpenAI 互換の口は今の `model_not_found` と同じ 404 で断る)
    - 会話やプロファイルのモデルが使えなくなったときは、送信のときに理由と対処(会話の設定でモデルを選び直す)を書いた注意で断る。勝手にほかのモデルに替えない
    - 管理者のプロファイルを配るときは、使えるモデルの中からしか選べない
14. **モデルの ID からパスを外すときは、保存済みの会話・プロファイルのモデルと、`server-models.json` の層の数のキーを引き継ぐ**(読み替えるか、DB の版を上げて書き換えるか。形は Code が案を示す。未決事項)

## 決定事項(11-0 を始めるときにユーザーと決めたこと。2026-10-23)

15. **モデルの ID は `file:<ファイル名>`**(例 `file:Qwen_Qwen3.5-4B-Q4_K_M.gguf`。`ollama:<名前>` は今のまま)。
    同じ名前のファイルが2か所にあれば、一覧の先(models フォルダ → Ollama → 足した置き場所)だけを出し、後ろは Warn のログで知らせる。
    古い ID(`file:<パス>`)は探すときにファイル名に読み替える(DB は書き換えない)。`server-models.json` の層の数のキーは、読み込むときに書き換える(上の 14)
16. **管理者は一人もいなくてもよい**。127.0.0.1 からはいつもサーバーの PC の事情を変えられ、管理者はコマンドでいつでも戻せるので止めない。
    外して一人もいなくなったら、ログで知らせる
17. **使えるモデルは「使えないモデル」の一覧を覚える**(`server-models.json`)。置き場所に新しく増えたモデルは、管理者が止めるまで使える
18. **使えるモデルを選ぶ画面は、モデルのタブの一覧の行に「使える」のスイッチ**。使えないモデルの行は薄くし、読み込むのボタンを出さない。
    管理者でない人には、使えないモデルは出さない

## 決定事項(11-1 を始めるときにユーザーと決めたこと。2026-10-23)

19. **配られたプロファイルを写すときは、決まり(固定・使えない)も写す**。写した人のプロファイルになるので、決まりも写した人が変えられる
    (利用者は自分のプロファイルをいつでも作れるので、写しで決まりを守らせることはもともとできない。配った意図を出発点として残す)。名前は「<名前>(写し)」
20. **配ったプロファイルは「組織のもの」として、管理者なら誰でも変えられ、配る相手も変えられる**。配った管理者を消しても、そのプロファイルは消さずに配り続ける
    (作った人の名前は残す)。管理者から外れた人は、配ったプロファイルを変えられなくなる
21. **配るのをやめた(相手から外した)ときも、その人がもう作った会話には決まりが効き続ける**。新しい会話では選べなくなる(しまったプロファイルと同じ扱い)
22. **画面は、プロファイルの編集に「配る:配らない / 全員 / 指定した人」と名前のチェックを足す**。一覧には「全員に配っている」「N 人に配っている」の印。
    受け取った人には「配られたプロファイル」の欄を分けて出し(読むだけ・配った人の名前・写すボタン)、新しい会話の選択では別のまとまりにする。
    配られたものを「最初に選ばれる」にもでき、配られなくなったら自分のプロファイルに戻る

## 決定事項(11-2 を始めるときにユーザーと決めたこと。2026-10-23)

23. **「管理者が読めます」は、会話の一覧の下の自分の名前の横に、目のアイコンと一緒に常に出す**(ログインが要る形の aibow-server につないでいるとき。ブラウザとアプリの両方)。
    吹き出しに「会話(ツールの結果も)は管理者が読め、読んだことは記録に残ります」。一覧を畳んでいるときはアイコンだけ
24. **会話の共有は、会話の設定の画面の「共有:非公開 / 全員 / 指定した人」と名前のチェックで決める**。共有するときに「ツールの結果も見えます」と確かめる(決定事項 12)。
    共有した会話は一覧で名前の横に共有のアイコン。共有された会話は一覧の下の「共有された会話」の欄(開閉できる・持ち主の名前付き)。
    開くと読むだけで、入力欄の代わりに「写して続ける」。相手を選ぶため、利用者の名前の一覧はログインした人なら誰でも見られる
25. **管理者は、設定の「利用者」のタブで人を選び、その人の会話の一覧から読むだけで開く**(ふだんの一覧には混ぜない)。
    開いた会話の上に「管理者として ○○ の会話を読んでいます(記録が残ります)」の帯
26. **写した会話の名前は「<名前>(写し)」**。利用者を消すと、その人が共有した会話も消える(その人の会話は全部消える。今と同じ)。ほかの人が写した会話は写した人のものなので残る

## 決定事項(11-0 で Code が決めたこと)

- 管理者を決めるコマンドは `aibow-server user admin <名前>`、外すのは `aibow-server user unadmin <名前>`。`user list` に「管理者」と出す。
  ログインなしの形の利用者(local)も管理者にできる(ログインなしの形では、127.0.0.1 だけで待ち受けるので、もともと何でもできる)
- 「127.0.0.1 から、または管理者」(決定事項 8)は、画面用の口にも同じ線を引く:サーバーの PC の上で開いたブラウザは、管理者でなくてもモデルのタブを全部出す
  (`ui.Caller.ManagesPC`)。利用者の管理(「利用者」のタブと `/aibow/admin/`)は、ブラウザでログインした管理者だけ
- サーバーの PC の事情をアプリ(serverUrl でつないだもの)から変えるのは作らない(決定事項 8 はブラウザのモデルのタブ。口は管理者の API キーで通るので、curl などからはできる)
- 利用者の管理の画面では、自分と `local` は消せない。管理者の印は表示だけ
- 使えないモデルの会話に送ったときの「注意」は、赤いエラーではなく、要約できなかったお知らせと同じ見た目(三角のアイコン)にした(`ChatEvent.Caution`)。
  画面のアプリ(serverUrl)では、`/models/load` の 404 `model_disabled` で見分ける
- 使えなくしたのが読み込み中のモデルなら降ろす(読み込んだままだと、model を書かないリクエストがそのモデルで答えるため)
- 起動のときのモデル(`-model` など)が使えないモデルなら、止めずに使えるモデルから選ぶ(起動できないと、管理者が画面で戻せないため)。
  使えるモデルが残っていなければ、`server-models.json` の `disabled` から外すよう書いたエラーで止まる
- 一覧の外の GGUF をパスで読み込ませるのは、起動のときだけにした(以前は OpenAI 互換の口の `model` にパスを書けば、サーバーの PC の好きな GGUF を読み込めた)

## 11-3 で確かめたこと(2026-10-23)

ユーザーと決めた確かめ方:LAN のアドレスで確かめる(10-4 と同じく SSH のポート転送を使わない)・Cline は curl で同じ形のリクエストを送る。

- 用意:一時フォルダの aibow-server(`192.168.11.4:18089` だけで待ち受け・ログインあり・CPU(`AIBOW_GPU_LAYERS=0`))。利用者は alice(管理者)・bob・carol と、それぞれの API キー。
  ユーザーの DB・アプリ・設定には触れていない
- **Cline の形(curl・API キー)**:`/v1/models` の ID にサーバーの PC のパスが出ない(`file:<ファイル名>`)・キーなしは 401・管理者でない人が LAN から PC の事情を変える口を呼ぶと 403、
  管理者は通る・9b を使えなくすると `/v1/models` から消え、`model` に書くと 404 `model_not_found`・以前の形(`file:<パス>`)の ID は読み替える・一覧の外のパスは断る
- **ブラウザ(Chrome)**:alice には全部のモデルのタブと「利用者」のタブ、配っているプロファイルのモデルは使えなくできない。bob はモデルのタブが制限され、PC の事情を変える口は 403、
  配られたプロファイルは読むだけ。bob にだけ配ったものは carol に見えない。共有していない会話は、保存の口(`/aibow/store/`)からも画面用の口(`/aibow/ui/`)からも見えない
- **アプリ(serverUrl。一時ビルド・WebView2 のデータフォルダを分けた)**:bob で、一覧の「共有された会話」と「管理者が読めます」・新しい会話の選択の配られたプロファイルのまとまり。
  共有された会話を読むだけで開く → 写して続ける → 続けて送れる。配られたプロファイルの固定がその会話で効き、管理者が固定を外すと開き直したあとに効く
  (11-1・11-2 の「見ていないこと」の、アプリでの配られたもの・共有・写すと、本物のモデルでの固定)
- **管理者が読む**:aibow-server のログに「管理者 alice が bob の会話「1+2は? 数字だけ」(…)を読みました」(Notice)
- 確かめている途中で直したもの:管理者でない人が人の会話の一覧を開いたとき、「プロファイルを配れるのは管理者だけです」と出ていた(`ErrNotAdmin` の文を、どちらの操作にも合う文にした)
- 見つけたが直していないもの:HTTP の LAN のアドレスでブラウザからログインすると、すぐ外れる。以前 HTTPS で同じアドレスにログインしたときの `Secure` の cookie が残っていると起きる
  ([_docs/known-issues.md](../known-issues.md) の「HTTP の LAN のアドレスでブラウザのログインが続かない」)。確かめるときは PC の名前(`http://neo:18089`)でつないで避けた
- 見ていないこと:本物の Cline(10-4 で curl と同じ形を確かめている)・今回の版の HTTPS(cookie と口の仕組みは 10-4 から変えていない)・
  ほかの PC から実際につなぐこと(同じ PC から LAN のアドレスでつないだ)・ツールを使った会話を共有したときの見え方(テストだけ)

## 11-2 で Code が決めたこと(2026-10-23)

## 11-1 で Code が決めたこと(2026-10-23)

- 誰に見えて誰が変えられるかは、保存先(SQLite)の条件の1か所で決める(学ぶことの「認可」。`store` の `profileVisible`・`profileUsed`・`profileEditable`)。
  会話の仕組みと画面は、保存先が入れた `ReadOnly`・`Withdrawn`・`OwnerName` を見るだけ
- 配る相手は名前で受け渡す(管理者の画面は利用者の名前の一覧を持っているため)。自分は相手にしない(配らなくても見える)
- 名前の重なりは、自分のもの同士・配られたもの同士の中だけ断る(皆が「既定」を持っているので、配った「既定」と重なっても画面のまとまりで見分けられる)
