# 0048: エラー・ログ・画面の文を、使う人から見た言葉に直す

- 状態: ⬜ 未着手(仕様。Code はこれを発注書として作る)
- ロードマップ: ロードマップの外(文言の直し)
- 決めた日: 2026-11-20(Chat でユーザーと決めた。洗い出しと書き直し案を見せて、ユーザーが「書いてください」とおすすめの案で決めた。
  きっかけはユーザーの指摘:「エラー文・ログ・画面の言葉の多くが内部の事情側から書かれていて、使う人に寄り添っていない」。
  例は -base のエラー(「Windows のパスになっています…」と内部で起きたことが先に来る)と、
  「同じ PC のリバースプロキシは、元の相手を X-Forwarded-For に書くようにしてください…」(「プロキシ使わない人には何言ってるかわかりません」))
- 前提: 0042(base)、0044(信頼するプロキシ)、0019(画面からつなぐ・証明書)、AGENTS.md の「ユーザーとのやり取り」(フィンガープリント・アプリモード / サーバーモード)

## 目的

aibow の文は、書いた人(作る側)が「中で何が起きたか」を説明する向きで書かれていることが多い。
読む人が知りたいのは「自分は何をすればいいか」で、中の事情はそのあとでよい。また、関係しない人にまで出る文は、読んでも意味が分からない。

洗い出し(2026-11-20。Go と画面の日本語 約 2,100 行)では、**画面のラベル・ボタン・確認の文はおおむね使う人の言葉**になっていて、
問題は **aibow-server の起動のログ・エラー**と、**サーバーモードの接続まわりのエラー**に集まっていた。

学ぶこと:

- **読み手を決めて書く**:同じ「エラー」でも、読み手が画面の前の人・サーバーを立てた人・API を書く人・モデル(ツールの結果)で、書くべきことが違う
- **出す条件も文のうち**:正しい文でも、関係しない人に出せば雑音になる。起動のときに見分けられないことは、ログではなくドキュメントに書く
- **学習用の詳細の置き場所**:トークン数・戻り値などは仕組みを観察するために残す(AGENTS.md)。ただし Info / Debug のログや「詳細」に置き、エラーの頭には置かない

## 決定事項(ユーザーと決めたこと)

1. **書き方の方針**(下の「書き方の決まり」)で、画面に出るエラー・トースト・Notice / Warn のログを直す
2. **直す範囲**:画面のエラー・トースト・お知らせ、Notice / Warn / Error のログ、コマンド(`aibow-server` の引数の説明・`user`・`cert`)の出力。
   **直さない**:Info / Debug のログ(学習用)、ツールの説明と結果(読み手はモデル)、API を直接呼ぶ人向けの断り(「このパスはありません: POST …」など)、`_cmd/dev` の出力
3. **X-Forwarded-For の案内は起動のログから外す**(`_cmd/aibow-server/main.go` の `logAddresses`。base を付けて 127.0.0.1 で待ち受けると毎回出ていた)。
   起動のときにはプロキシを使っているか見分けられない(0044 の未決事項 1)ので、usage.md の「リバースプロキシの後ろに置く」に任せる(すでに書いてある)
4. **「信頼するプロキシ: この PC の上(X-Forwarded-For で元の相手を見ます)」は、trustedProxies を書いたときだけ Notice で出す**。書いていなければ Info にする(今は毎回、全員に出ている)
5. **言い換え表**(下)のとおりに直す

## 書き方の決まり

1. **先に「使う人が何をすればいいか」(無ければ「何が起きたか」を使う人から見て)。中の事情(なぜそうなったか)は後ろか括弧に**
   - 例(0042 の base):✕「base が Windows のパスになっています: … Git Bash は引数の /aibow をパスに書き換えるので、-base aibow と…書いてください」
     → ○「-base は先頭の / を付けずに `-base aibow` と書いてください(Git Bash が /aibow を Windows のパス "…" に書き換えて渡したため)」
2. **その人に関係あるときだけ出す**。条件でしぼれないものは、起動のログではなくドキュメントに書く
3. **中の呼び名・造語を使わない**(言い換え表)。決めた用語(アプリモード・サーバーモード・フィンガープリント)にそろえる
4. **開発する人向けの詳細**(HTTP のメソッドとパス・Go の型名・戻り値・`[DONE]` などの印)は、文の頭に置かない。括弧の後ろかログへ。Go の型名(`%T`)は画面に出さない
5. **学習用の詳細**は、Info / Debug のログ・「詳細」・マウスを乗せた説明に置く(そのままでよい)

この決まりは AGENTS.md の「コードの書き方」(エラーのメッセージ)と「ユーザーとのやり取り」(用語)に足す。これから書く文も同じ決まりで書くため。
