## 目的

今は、モデルが作業フォルダ(ワークスペースのフォルダ)を**直接書き換えている**。守りは書き換えるたびの確認のカードだけ。
これを、**会話ごとに Git の worktree を作ってそこで書き換えさせ、最後に本体との差分を見て、取り込む / 捨てる**形にできるようにする(Claude Code と同じ形)。

ユーザーの作業のイメージ(2026-11-03):コーディングエージェントに動作確認までさせるのではなく、**コードを書くことに集中させる**。動作の確認はユーザーがする。
ただ、コンパイルエラーが無い程度は確かめられるとよい。worktree は「書いたものを本体に入れる前に、まとめて見る」ための場所。

学ぶこと:

- **アプリとモデルの役割の分け方**:Git の操作(作る・差分を取る・取り込む・消す)はアプリが決まった手順で行い、モデルには普通の作業フォルダとして見せるだけ。プロンプトは1文字も増えない(0037 の試しで分かった「会話の上限の残りが尽きる」を悪くしない)
- **worktree の仕組み**:1つのリポジトリ(`.git` のオブジェクト)を分け合ったまま、別のフォルダに別のブランチを取り出す。作るときのコミットから始まるので、本体のコミットしていない変更と、Git に入っていないもの(`node_modules` など)は入らない
- **差分を「取り込む」ときに何が起きるか**:パッチを当てる(`git apply`)とマージの違い。当たらないとき(本体の同じ行が変わっているとき)にどうなるか

## 決定事項(話の流れから Chat が決めて書いたこと。2026-11-03 にユーザーが確かめた)

### パッケージ

- 新しいパッケージ `git/`(`git` パッケージ)に、アプリが行う Git の操作をまとめる。worktree はその中の1つ(`worktree.go`):作る・本体の状態を見る・差分を取る・本体に当てる・消す
  (`git/worktree` のように分けるのは、操作が増えてから考える。2026-11-03、ユーザーと話した)
- `os/exec` で `git -C <フォルダ> …` を呼ぶだけ。ルートの `aibow`・`tool`・Wails を import しない(aibow-server から使うときにそのまま使える。`tool` が LLM を知らないのと同じ分け方)
- **`git` はアプリが使う Git の操作、`tool` はモデルに見せるツール**、と分ける。段3で読むだけの Git のツール(`git_status`・`git_diff`)を作るなら、`tool` の中に作り、中で `git` を呼ぶ(`tool` → `git` の向き。`git` は `tool` を知らない)
- 子プロセスの止め方は `internal/proc` を使う。呼んだ git のコマンドは `log.Infof` で残す(仕組みが観察できるように)

### 段1:worktree を作る

- 作る時は**最初に書き換えるツールを実行する前**(切り替えを入れた会話で、読むだけなら作らない)。
  切り替えられるのは worktree を作る前まで。作ったあとは切り替えを「worktree で作業中」の表示にする
- 作り方:`git -C <メイン> worktree add -b aibow/<短い ID> <メイン>/.aibow/worktrees/<短い ID> HEAD`。作ったときのコミット(`base`)を覚える
  - 短い ID は会話の ID(UUID)の先頭 8 文字(重なれば延ばす)。Windows のパスの長さを抑えるため
    → 2026-11-04 に「<worktree の名前>-<末尾 4 文字>」に変えた(下の「あとから変えたこと」)
- 作るときに、本体にコミットしていない変更があれば「本体のコミットしていない変更 n 件は worktree に入りません」、あわせて「Git に入っていないもの(`node_modules` など)はありません」と画面に出す(会話の中の、モデルに渡さない発言として。0035 の「この PC にはこのワークスペースがありません」と同じ扱い)
- 作ったあとは、その会話のメインのフォルダのパスを worktree に置き換える。ファイルのツール・`run_command`・`${workdir}` の MCP・環境の説明がすべて worktree を指す。
  フォルダの名前(モデルが呼ぶ名前)は変えない。**モデルには worktree だと伝えない**(プロンプトを変えない)
- `workspaces.json` の形(案):ワークスペースに `worktrees: [{conversation, path, branch, base}]` を足す
- **worktree の会話では、`write_file`・`edit_file` の扱いの既定を「確認しない」にする**(取り込む前に差分で見られるため。0010 の層の「決まりの既定」を worktree のときだけ変える。会話・PC で `ask` にしていればそちらが勝つ)。
  `run_command` は今までどおり確認する(コマンドは worktree の外にも書けるため)
- 会話を消したら、worktree とブランチも消す(取り込んでいない差分があれば、消す前に確認する)。
  会話をサーバーに置いているときなど、この PC に結び付けの無い会話を消すときは何もしない

### 段2:差分を見て、取り込む / 捨てる

- 差分は `base` との比較。新しいファイル・消したファイルも含める(案:worktree の中で `git add -A` してから `git diff --cached --binary <base>`。worktree の索引はアプリのものなので、ステージしてかまわない)
- 入力欄の上(worktree の表示のそば)に「差分(n ファイル)」を出し、押すと差分の画面を開く。ファイルの一覧(足した / 変えた / 消した)と、選んだファイルの差分
- **取り込む**:選んだファイルの差分をパッチにして、本体で `git apply`(`--3way` は付けない)。
  - 当たらないとき(本体の同じところが変わっているとき)は何も変えずに失敗し、どのファイルが当たらないかを出す。ユーザーが本体の変更を片付けてから取り込み直すか、そのファイルを外して取り込む
  - 取り込んだあとも worktree は残す(会話を続けられるように)。取り込んだファイルは一覧で「取り込み済み」と分かるようにする
- **捨てる**:`git worktree remove --force` とブランチの削除(`git branch -D aibow/<短い ID>`)。結び付けを消し、会話は直接のフォルダに戻る(切り替えは外れた状態)
- 当てる方法を `git apply`(`--3way` なし)にした理由(2026-11-03、Chat が git 2.43 で試して確かめた):
  - `git apply` は**全部当たるか、何も変えないか**のどちらか。本体の作業ツリーだけを変え、索引(ステージ)には触れない。本体のコミットしていない変更があっても、別の行なら当たる
  - `--3way` は本体の索引を変え(当てたファイルがステージされる)、本体にコミットしていない変更があると「does not match index」で直接当てる形に落ち、**新しいファイルを作らずに一部だけ当たった**。ユーザーの手に残す、と合わない
  - ユーザーの Windows の git の版では確かめていない(未確認)

2. **`run_command` でも作る**:作る時は「最初に書き換えるツールを実行する前」なので、`write_file`・`edit_file` に加えて `run_command` の前にも作る(コマンドもファイルを書き換えうる。作る前に本体で動かすと本体が変わる)。

3. **作るときの知らせの出し方**:決定事項 9・段1 の「会話の中の、モデルに渡さない発言として」は、そのツールのカードの中のお知らせにした(`ToolResult.Notice`。結果と一緒に保存され、再起動しても出る。モデルに渡す結果の文には入れない)。
   ツールの呼び出しと結果の間に別の発言を挟むと、履歴の形(呼び出し → 結果)と「モデルに渡さない」の扱い(0011)が崩れるため
4. **取り込み済みの分け方**:覚えておかず、差分の画面を開くたびに本体を見て決める(本体のハッシュが worktree と同じか、差分を本体に逆向きに当てられるか)。取り込んだあとに本体で書き換えれば、取り込み済みでなくなる。
   逆向きの確かめは、実際の画面で試して足した(本体の同じファイルの別の行にコミットしていない変更があると、中身の比べ方だけでは付かなかった。[tuning.md](../tuning.md))
5. **作ったあとの守り**:作ったあとは、切り替えを外せない(捨てるのは差分の画面)・会話のワークスペースを変えられない。worktree で作業している会話が残っているワークスペースは消せない(結び付けが消えると、フォルダとブランチが片付けられずに残るため)
6. **会話を消す前の確認**:会話の一覧の「削除しますか?」を、取り込んでいないファイルがあれば「取り込んでいない差分(n ファイル)も消えます。削除しますか?」にした(ほかに確認の画面は増やさない)
7. **フォルダが1つの環境の説明**:worktree でも「"<名前>" refers to the working directory itself.」の名前は本体のフォルダの名前のまま(パスの最後の名前を使っていたので、そのままだと worktree の短い ID になってしまうため)。「Working directory:」のパスは worktree になる
