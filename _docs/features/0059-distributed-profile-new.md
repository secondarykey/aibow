- 状態: 🔧 作業中(段1・段2 済み。段3 の画面の確認が残り)
- ロードマップ: ロードマップの外(使い勝手の直し。0018 の 11-1・0032 の段3 の続き)
- 決めた日: 2026-11-23(Chat でユーザーと決めた。Chat がコード(`profile.go`・`store/profiles.go`・`ui/profiles.go`・`ProfileSettings.tsx`・`SharePicker.tsx`)を読んで、今の作りを確かめた)
- 前提: 0018(プロファイルを配る)、0031(配る相手にグループ)、0032 の段3(複製して配布)、0056(編集の欄の「既定にする」「アーカイブ」「削除」)

## 目的

管理の画面の「配るプロファイル」で、配布プロファイルを**最初から作って編集できる**ようにする。
今は、管理者の個人プロファイルを「複製して配布」するしか作り方がなく、配布を外すと管理者の個人プロファイルに戻る。
配布プロファイルと管理者の個人プロファイルを行き来させず、**配布プロファイルは配布プロファイルとして生まれ、停止・削除される**形にそろえる。

学ぶこと:

- **持ち物を混ぜない**:同じ表(profiles)に入っていても、「自分のもの」と「配るもの」は使い方も変えられる人も違う。行き来できると、どちらの一覧にあるのか・誰が変えられるのかが分かりにくくなる
- **止めると消すを分ける**:会話はプロファイルの決まりを引き続ける(外部キー)。使われているものは消さずに止め、使われていないものだけ消す(0014 の 11 のアーカイブと同じ考え方)

## 今の作り(2026-11-23、Chat がコードを読んで確かめた)

- 管理の画面(`ProfileSettings` の `mode="distributed"`)の一覧の下に「**複製して配布**」(`ShareCopyForm` → Go の `ShareCopy`)。自分のプロファイルを選び、配る相手を確定すると、写してそのまま配る
- 編集の欄の操作の行に「**アーカイブ**」「**削除**」(`ProfileEditor`。own と distributed で同じ部品)。その下に配る範囲(`ShareForm` = `SharePicker` + `PROFILE_WORDS`)
- **アーカイブは、もう配布プロファイルの停止として効いている**。配ったプロファイルは1行を全員で共有しているので、管理者がアーカイブすると `archived` が全員に効く:
  - 受け取った人の新しい会話の画面から消える(`NewChat.tsx` の `usable`)。Go も選べないと断る(`usableProfile`)
  - 受け取った人の既定だったときは、その人の既定が自動で別のものに移る(`markedProfile`)
  - 今ある会話は決まりを引き続ける。「アーカイブ解除」で戻る
  - ただし、ボタンの言葉は「アーカイブ」で、配布の停止だと読み取りにくい
- アーカイブ・削除は、**管理者自身の既定**なら断られる(`isDefault` は ctx の利用者の既定だけを見る)。受け取った人の既定かどうかは見ていない(見なくても上のとおり移るので困らない)
- **削除は、誰か1人でもそのプロファイルから作った会話があると失敗する**(`store.DeleteProfile` は全員の会話を数える。外部キーでもある)。
  ところが画面の「会話 N」(`ProfileInfo.Uses`)は**管理者自身の会話**しか数えていない(`Profiles` は `ListConversations` = 自分の会話)。そのため、受け取った人が使っていると、ボタンは押せるのに押すとエラーになる
- 配る範囲を「配布しない」にする(または指定した人を全員外す)と「**配布を停止**」になり、`share = ''` に戻って**作った人の個人プロファイルになる**(`ShareForm` の notes の文)。今回なくす動き

## 決定事項

### ユーザーと決めたこと

1. 管理の画面の配布プロファイルの一覧に「**新規**」を置き、そこで最初から作って編集する
2. 「**複製して配布**」(管理者の個人プロファイルから写して配る道)は**なくす**
3. 配布をやめたときに**管理者の個人プロファイルに戻す動きはやめる**。配布プロファイルを個人プロファイルにする道も、個人プロファイルを配布プロファイルにする道も無くす
4. **削除とは別に「停止」**を置く。停止は今の「アーカイブ」を使う(新しい列は足さない)。止めると受け取った人の新しい会話では選べなくなり、今ある会話は続けられる。再開できる
5. **削除は、確認のうえそのまま消す**。ただし**誰か1人でもそのプロファイルから作った会話があれば削除できない**(ボタンを押せなくし、停止を案内する。2026-11-23 にユーザーが選んだ)
6. **すでに配布中のもの**(「複製して配布」で作ったもの)は、そのまま残す。移行はしない

### 話の流れから Chat が決めて書いたこと(2026-11-24、ユーザーに確認して、このまま進めることにした)

7. **「新規」の流れ**:一覧の「新規」を押すと、一覧の下に作る欄を出す(今の `ShareCopyForm` の場所)。欄は **名前**・**モデル**・**配布(範囲と相手)** の3つ。配布の確定のボタン(`SharePicker` の確定)で、作ると配るを一度に行い、作ったものを選んで編集の欄を開く。「キャンセル」で閉じる
   - 配布の相手を決めずに作ることはしない(相手の無い配布プロファイルは、管理者の個人プロファイルと同じ見え方になってしまうため)
   - 名前の初期値は「新しいプロファイル」(配布プロファイル同士で重なれば「新しいプロファイル 2」…。`freeName` を配布プロファイルで数える形に)。重なりの確かめは今の `checkName`(配ったもの同士で比べる)
   - モデルは、使えるモデル(`usableModel` が通るもの)から選ぶ。初期値は使えるモデルの先頭
8. **新規の初期値**:モデル以外の値は、**管理者の今の既定のプロファイルの値**を写す(自分の画面の「作成」が選んでいるものの値を写すのと同じ考え方)。決まり(固定・使えないもの)と資料のフォルダは**空**。
   値はこのあと編集の欄で変えるので、「どこから写したか」の関係は持たない。
   (別の案:アプリの組み込みの既定の値から始める。今はプロファイルの外に「組み込みの既定」が無いので、写す案にした)
9. **Go の入口**:`ShareCopy` を消し、`ShareNew(ctx, name, model string, share string, with, groups []string) (Profile, error)` を足す(aibow の `Conversations` と `ui.Service` の両方)。
   中身は今の `ShareCopy` と同じ順(値を作る → `validate` → `checkName` → `store.CreateProfile` → `store.SetProfileShare`、配れなければ作ったものを消す)。`ui.Service` 側で `usableModel(model)` を確かめ、ログは「プロファイル「%s」を作成して、全員に配布しました(%s)」など
   - 値を作るところは、`ShareCopy` の「写して配る」の部分を `createShared(ctx, p Profile, share, with, groups)` のような内側の関数に分けて使ってよい
10. **個人と配布を行き来させない**(決定事項 3):`Conversations.SetProfileShare` で
    - `share == ""` は断る(「配布をやめるときは、停止か削除を使ってください」)
    - 今 `share == ""` のプロファイル(個人プロファイル)を配ろうとしたら断る(「個人プロファイルは配布できません。管理の画面の「新規」で作ってください」)
    - 範囲を「全員」⇔「指定した人」に変える・相手を変えるのは今のまま
    - `store.SetProfileShare` は今のまま(`''` も受け付ける)にする。断るのは aibow の層だけ(store のテストが `''` を使っているため。認可の1か所は store のまま)
11. **配布の欄(`ShareForm`)から「配布しない」を無くす**:`SharePicker` に `noneAllowed?: boolean`(既定 true)を足し、false のときは
    - 範囲の select に「配布しない」を出さない
    - 「指定した人」で相手を全員外したときは、確定のボタンを押せなくする(今の `becomesNone` の代わりに「1人以上選んでください。配布をやめるときは、停止か削除を使ってください」)
    - 新規の欄・`ShareForm` の両方で false にする。会話の共有(`SHARE_WORDS`)は今のまま
    - `PROFILE_WORDS` の `commitNone`・`willNone`・`becomesNone` と、`ShareForm` の「作った人の自分のプロファイルに戻り…」の notes は消す
12. **停止の見せ方(管理の画面)**:distributed のときだけ、ボタンの言葉を「アーカイブ」→「**停止**」、「アーカイブ解除」→「**再開**」にする。一覧の札も「アーカイブ済み」→「**停止中**」。
    説明(title)は「受け取った人の新しい会話で選べなくする(今ある会話は続けられ、決まりも効き続ける)」「受け取った人の新しい会話で、また選べるようにする」。
    Go の関数(`SetProfileArchived`)と列(`archived`)はそのまま使う。ログだけ、配布プロファイルなら「配布を停止しました」「配布を再開しました」
    - 自分の画面(own)の個人プロファイルの「アーカイブ」は今のまま
13. **停止の見せ方(受け取った人)**:「配布されたプロファイル」の欄の札は「アーカイブ済み」でなく「**停止中**」(`read_only` か `share` があるもの)。title は「管理者が配布を停止した。新しい会話では選べない。今ある会話は続けられる」。
    「既定にする」は今のまま押せない(説明「停止中は既定にできない」)。「複製」は今のまま押せる
14. **管理者自身の既定でも、配布プロファイルは停止・削除できる**:管理者が配布プロファイルを自分の既定にしていても、`SetProfileArchived`・`DeleteProfile` は断らない(`p.Share != ""` のときは `isDefault` を見ない)。
    止めた・消したあとは、受け取った人と同じく `markedProfile` が既定を移す。管理の画面のボタンの disabled も、distributed のときは `info.default` を見ない
    - 個人プロファイル(own)は今のまま(既定はアーカイブ・削除できない。プロファイルが必ず1つ以上あるように)
15. **削除できるかは、全員の会話で数える**(決定事項 5):
    - `ProfileInfo` に `UsesAll int `json:"uses_all"`` を足す。管理者に見える配布プロファイル(`share != ""` で編集できるもの)だけ、全員の会話の数を入れる(ほかは 0)。
      数えるのは store に `ProfileUseCounts(ctx) (map[uuid.UUID]int, error)` のような関数を足して行う(管理者でなければ空を返す。`SELECT profile_id, COUNT(*) FROM conversations GROUP BY profile_id`)
    - 管理の画面の一覧の行の「会話 N」と、削除のボタンの disabled・title は `uses_all` を使う。title は「このプロファイルから作った会話が全員で N 個あるので削除できない(停止はできる)」
    - 自分の画面は今のまま(`uses` = 自分の会話の数)
    - `store.DeleteProfile` の「全員の会話を数えて `ErrProfileInUse`」は今のまま(画面と Go の両方で止める)
16. **削除の確認の文**(distributed):「配布プロファイル「<名前>」を削除しますか? 受け取った人の一覧からも消えます。元に戻せません」。own は今のまま
17. **「複製して配布」を消すもの**:`ShareCopyForm`・`copying` の状態・Go の `ShareCopy`(aibow・ui の両方)・bindings(`chatservice.ts` は Wails の生成なので作り直す)・関係するテスト。`CopyProfile`(受け取った人が自分のものにする「複製」)は残す
18. **ヒントの文**:配布プロファイルが無いときの「配布しているプロファイルはありません」は、「配布しているプロファイルはありません。「新規」で作ります」にする

### 作業中に Code が決めたこと(2026-11-24)

    印は残したまま、自分のしまっていないプロファイルを使う(見えなくなったときと同じ)。再開すると印のものに戻る。

    停止 / 再開「プロファイル「<名前>」の配布を停止しました / 配布を再開しました(…)」。どれも Notice(ほかの人に効く変更)。個人プロファイルのアーカイブは今までどおり「プロファイル「<名前>」をアーカイブしました」

    範囲を選ぶと人を選ぶ欄と確定のボタンが出る。確定のボタンは今までどおり「全員に配布」「配布(N人)」

23. 自分の画面の「作成」の名前の初期値(`freeName`)は、自分のプロファイル同士で数える(今までどおり)。管理の画面の「新規」は配布プロファイル同士で数える

## やらないこと

- 既にある配布プロファイルの移行・作り直し(決定事項 6)
- 管理者の個人プロファイルの値を、あとから配布プロファイルに写す道(「プロファイルに保存」を配布プロファイルに向けるなど)。必要になったら別に相談する
- 停止・削除を受け取った人に知らせる(通知)
- 受け取った人の会話がある配布プロファイルを、会話ごと消す・決まりを会話に写して消す(決定事項 5 で選ばなかった案)
- 新しい列(「停止」専用のフラグ)を足すこと。`archived` を使う
