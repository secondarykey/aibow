# 使い方と設定

画面の使い方、設定と環境変数、各ステップで観察してほしいことです。準備と起動は [setup.md](setup.md)。

## 画面の使い方

**会話の一覧(左)**
- 上のハンバーガーで開閉します。閉じるとアイコンだけの細い列になります。
- 一覧の一番上の「+ 新規」で、入力欄が真ん中にある新しい会話の画面になります(起動したときもこの画面です)。最初に送ったときに会話ができます。
- 会話の切り替え・削除ができます。タイトルは最初の発言の先頭から自動で付き、一覧でダブルクリックすると変えられます。
- 一覧の右の境目をドラッグすると一覧の幅を変えられます(ダブルクリックで元の幅。幅は次の起動でも同じ)。
- ウィンドウの幅が 720px 以下のときは、一覧を開くと会話の上に重ねて出ます。後ろの影・Esc・会話を選ぶ・「+ 新規」・「設定」で閉じます。
  720px 以下に狭めたときに一覧が開いていたら、自動で閉じます。

**発言と返事**
- 発言の下には「時刻 コピー」、返事の最後には「コピー 時刻 詳細」が出ます。
  時刻は「3分前」のように今からどれくらい前かで出し(5日以上前は「2025/10/12 14:05」)、マウスを乗せると実際の時刻を秒まで出します。
- 返事のコピーは答えの文だけ(思考は含めない)です。「詳細」を押すと、統計行(モデル名・速さ・トークン数)が開きます。
- モデルがツールを使うと、答えより前の部分(各回の思考とツールのカード)が「思考の過程(10秒)・ツール 2回」の枠にまとめて畳まれます。
  秒数は送信から答えを書き始めるまでの時間です。開くと、思考とカード(ツールの名前と、実行中・成功・エラー)が使った順に並び、カードを開くと引数と結果が読めます。
- 生成中は、返事の吹き出しの右下に赤い停止のアイコンが出ます。
- 生成中でも、上にスクロールすれば過去の発言を読めます(一番下にいるときだけ、届いた文を追いかけて下へ送ります)。
- 生成中に別の会話を開いて読むことはできますが、送信は生成が終わるまでできません(エンジンが1つのため)。

**返事の表示**
- 返事と要約の文は Markdown として表示します(太字・見出し・箇条書き・表・コードなど)。リンクはふだんのブラウザで開きます。
- コードブロックは、言語が書かれていれば色が付きます。右上のアイコンで、そのコードだけをコピーできます。
- 言語が `mermaid` のコードブロックは図になります。図の上のアイコンで、コードとの切り替え・保存・コピーができます。
  保存は SVG、コピーはコードの文字がふだんの動きで、横の ▾ から PNG で保存・PNG をコピーも選べます。

## モデルの切り替え

入力欄の下のドロップダウンで選ぶと、aibow が今のモデルを VRAM から降ろして、新しいモデルを読み込みます(数秒〜十数秒)。
モデルはアプリ全体で1つです(VRAM に1つしか載らないため)。会話を切り替えてもモデルは変わりません。
会話はそのまま続けられるので、同じ質問を 4B と 9B で比べる、といった使い方ができます。
回答の最後の「詳細」を開くと、統計行の先頭に、どのモデルの返事かが表示されます(発言ごとに保存されています)。
最後に使ったモデルは保存され、次の起動で読み込まれます。

aibow を起動したまま `ollama pull` した場合は、aibow のウィンドウに戻ると一覧に出てきます(ウィンドウにフォーカスが戻るたびに一覧を作り直しています)。

## 会話の保存

会話は SQLite のファイル `%APPDATA%\aibow\aibow.db` に保存され、アプリを閉じても残ります。
保存先は `AIBOW_DB` で変えられます。試しに動かすときに、普段の会話と混ぜたくない場合などに使います。

次に起動したときは、閉じたときと同じ様子で開きます:ウィンドウの位置と大きさ(最大化していたら最大化)・会話の一覧を開いていたか・一覧の幅・最後に開いていた会話。
ウィンドウの位置と大きさは `%APPDATA%\aibow\window.json`(`AIBOW_WINDOW`)、ほかは画面(WebView2)の中に覚えます。
覚えた位置がどの画面(モニター)にも入っていなければ(モニターを外したときなど)、真ん中に開きます。

## 長い会話(compact)

モデルに渡すのは、これまでの会話を全部並べた1本の文字列です。会話が長くなると「会話の上限」に入りきらなくなるので、
会話ごとに選んだ方式で収めます(会話の設定の画面の「会話が長くなったら(compact)」。新しい会話の既定は設定の画面)。どの方式でも、保存した発言は消えません。

| 方式 | 何をするか |
|---|---|
| 要約する(summary、新しい会話の既定) | 最近の発言を会話の上限のおよそ半分まで残し、それより古い発言をモデル自身に要約させる。要約は前回の要約と一緒に作り直して積み重ねる |
| 古い発言を捨てる(truncate) | 古い発言から順に(ユーザーの発言と返事の組ごとに)、モデルに渡すのをやめる |
| 何もしない(none) | 上限を超えたら、生成する前に止まって知らせる |

- **メーター**: 入力欄の下の右端の `5,210 / 8,192` は、次の送信でモデルに渡す文字列のトークン数 / 会話の上限です。
  90% を超えると橙、上限を超えると赤になります。トークン数は保存せず、そのときのモデルで数え直します(モデルが変わると同じ文章でも変わる)
- **薄い表示**: 要約に入った発言や、truncate で外れた発言(モデルに渡していない発言)は薄く表示されます
- **選んだやり取りをモデルに渡さない**: 発言の下(「時刻 コピー」の左)と返事の下(「コピー 時刻 詳細」の右)の目のアイコンを押すと、その吹き出しを次の送信からモデルに渡しません。
  返事はツールの呼び出しと結果も一緒です。吹き出しは消えず、薄い点線の枠で残ります。もう一度押すと戻せます。
  描画に失敗した図と「直して」の往復のように、要らなくなったやり取りを外すときに使います(「質問 → 壊れた図 → 直して → 直った図」なら、真ん中の2つを外す)。
  すでに要約に入った発言は、外しても要約の中に残ります。生成中の会話では変えられません
- **作り直す・直して送り直す**: 最後の返事の下の更新のアイコンで、その返事を消して、今のモデル・設定でもう一度作ります。最後の発言の下の鉛筆のアイコンで、発言を直して送り直せます(発言と返事は消えます)。
  ツールをオンにしてから・9B に切り替えてから作り直す、のように条件を変えてやり直すときに使います(同じ条件では、同じ間違いをしやすい)。
  前の返事でツールが行ったこと(ファイルの書き換えなど)は元に戻りません
- **区切り**: 要約した位置に「― ここまでを要約しました ―」が出ます。クリックすると、モデルに渡している要約の文と、要約前後のトークン数・かかった秒数が読めます
- **今すぐ要約**: summary の会話では、メーターのトークン数(「n / 8,192」の n)を押すと、上限を超えていなくても要約できます。要約するものが無いときは、右上のお知らせで理由が出ます
- 要約を作っている間は、返事の吹き出しに要約の文が流れます。停止のアイコン(マウスを乗せると「要約を停止」)で要約だけを止めると、その回は truncate で返事を生成します。
  要約に失敗したとき(答えが出なかった、途中で切れた、エラー)も同じで、理由が吹き出しに出ます

## ツール呼び出し

モデルが「ツールを使いたい」と書いたら aibow が実行し、結果を渡して続きを書かせます(エージェントループ)。
どのツールを使うかは、設定の画面の「ツール」で決めます(使わないツールは説明もプロンプトに入りません)。今ある組み込みのツール(aibow の中で動くツール)は次のとおりです。会話ごとに、入力欄の上の「この会話のツール」で外すこともできます。

| ツール | 内容 |
|---|---|
| `get_current_time` | 現在の日時・曜日・タイムゾーン(タイムゾーンは省略すると PC のもの) |
| `calculate` | 四則演算と括弧の式を正確に計算する(`7/2` は `3.5`) |
| `list_files` | 作業フォルダの中のファイルを、下のフォルダまでたどって浅い順に並べる(500 件・8,000 文字まで。`.git` と `node_modules` は飛ばし、隠しフォルダは名前だけ) |
| `read_file` | 作業フォルダの中のファイルを、行番号付きで読む(1回 200 行・8,000 文字まで。続きはモデルが `offset` を指定して読む) |
| `write_file` | 作業フォルダの中にファイルを作るか、丸ごと上書きする(**実行前に確認**) |
| `edit_file` | 作業フォルダの中のファイルの一部を置き換える。置き換える文字列がファイルの中に1か所だけのときだけ(**実行前に確認**) |
| `run_command` | 作業フォルダでコマンドを実行し、出力と終了コードを返す。Windows は cmd.exe、それ以外は `/bin/sh`。120 秒まで、入力はできない(**実行前に確認**) |

### 作業フォルダ

入力欄の上のフォルダのアイコンを押すと、フォルダを選ぶダイアログが出ます。選ぶと、その会話でだけファイルのツールが使えるようになります(× で外せます)。

- 作業フォルダは会話ごとの設定です。**新しい会話には引き継がれません**(前の会話のフォルダを、別の会話で触らせないため)。会話ごとに選んでください
- ツールは作業フォルダの外を開けません(`../` や外を指すリンクもエラーになります)
- 作業フォルダを決めた会話では、システムプロンプトの後ろに「# Environment」(作業フォルダと OS)が自動で入ります
- 読めるのは UTF-8 のテキストだけです(Shift_JIS のファイルやバイナリはエラーになります)

### 実行する前の確認

`write_file` / `edit_file` / `run_command` は、実行する前にカードで確認を求めます。差分(+ は追加、- は削除)かコマンドを見て「実行する」か「拒否」を押します。
コマンドは何でもできる(ファイルを消す・作業フォルダの外を触る)ので、よく読んでから押してください。

- 拒否するときは理由を一言書けます(空でもよい)。理由はモデルに「ユーザーが実行を拒否しました。理由: …」として渡り、モデルは別のやり方を考えます。
  理由を書かないと、小さいモデルは同じ書き換えをもう一度試すことがあります
- 確認を待っている間も停止のアイコンで止められます
- 確認を待っている間に別の会話を見に行っても、待ち続けます(会話の一覧に橙の点滅)。戻るとカードがそのまま出ます
- 答えた結果(実行した / 拒否した)は保存され、再起動しても見えます

### MCP のサーバー

MCP(Model Context Protocol)のサーバーのツールも使えます。サーバーは設定ファイル `settings.json`(`%APPDATA%\aibow\settings.json`)の `mcpServers` に書きます。
書き方は、ほかのツール(Claude Desktop など)の `mcpServers` と同じです。たとえば公式の filesystem サーバー(Node.js が要ります)は次のようにします。

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "${workdir}"]
    }
  }
}
```

- `${workdir}` は会話の作業フォルダに置き換わります。`${workdir}` を使うサーバーは作業フォルダごとに起動し、作業フォルダを決めていない会話では使いません
- サーバーは、その会話で最初に送信したときに起動します(`npx` の初回はダウンロードで時間がかかります)。アプリを閉じると止まります
- 設定ファイルを変えたら、アプリを起動し直してください。書き間違いは起動したときにお知らせに出ます
- 起動できなかったときは、お知らせに理由が出ます(サーバーがエラー出力に書いた最後の行も添えます)
- ツール1回の実行の上限は 60 秒です。長く動くツールのあるサーバーは、サーバーごとに `"callTimeout": 130` のように秒数を書くと延ばせます(aibow-mcp の `run_command` は 120 秒まで動くので、それより長くします)
- 起動してつながるまでの上限は 60 秒です。初回の `npx` / `uv` はダウンロードや環境の組み立てで超えることがあるので、サーバーごとに `"startupTimeout": 180` のように秒数を書くと延ばせます
- ほかのアプリ(Claude の拡張など)と同じフォルダのサーバーを `uv run --directory …` で起動するときは、`"env": { "UV_PROJECT_ENVIRONMENT": "…" }` で aibow 用の環境を別のフォルダに作らせてください。同じ環境を使うと、uv が環境を作り直そうとして、ほかのアプリが使っているファイルとぶつかり、起動できません(「アクセスが拒否されました」「別のプロセスが使用中です」)
- どこか(イントラの中など)で動いているサーバーには、`url` でつなげます。API キーなどは `headers` に書きます(OAuth のログインが要るサーバーには、まだつなげません)

  ```json
  "intra-tools": {
    "url": "http://tools.intra.example:3000/mcp",
    "headers": { "Authorization": "Bearer xxxx" }
  }
  ```

  url のサーバーには作業フォルダ(`${workdir}`)を渡せません。`headers` の API キーは `settings.json` にそのまま書かれるので、ファイルの扱いに気をつけてください
- **会話ごとに使うツールを選びます**。入力欄の上、作業フォルダの隣のレンチのアイコン(この会話のツール)を押すと、組み込みのツールと MCP のサーバーの一覧が開きます。新しい会話では、設定の画面の「ツール」でチェックしているものが最初から選ばれていて、会話ごとに外したり、チェックしていないものを足したりできます。ツールの説明は毎回プロンプトに入り、全部を載せると会話の上限を食い尽くすので、ふだん使わないサーバーは「ツール」でチェックを外しておき、要る会話でだけ選びます
- 設定の画面の「ツール」で、ツールを使う / 使わないを決められます(この PC の既定。全部の会話に効き、`tools.json` に保存します)。組み込みのツール(aibow の中で動くツール)と MCP のサーバーがグループに分かれていて、グループのチェックは「新しい会話で最初から使う」の意味です(外しても、会話では選べます)。settings.json に足したばかりの MCP のサーバーは、チェックが外れた状態から始まります(起動したときにお知らせが出ます)。グループの中のツールのチェックは、既定で使う / 使わないです(全部の会話の既定。会話の設定の画面で、会話ごとに使うにも使わないにもできます)。
  ツールの行とグループの見出しの「確認しない」を押すと、そのツール(グループのツール全部)を実行する前に確認しなくなります(橙で出ます。マウスを乗せると出る薄い枠を押すと「確認しない」になります)。ツールごとに決めたものは、グループごとより優先します使わないツールは説明もプロンプトに入らないので、会話の上限の節約になります。MCP のツールの一覧は、サーバーを一時的に起動して受け取ります(読み直すボタンで受け取り直せます)
- MCP のツールは、**全部、実行する前に確認**します。カードにはサーバーの名前と、サーバーに渡す引数が出ます
- MCP のツールの名前には、サーバーの名前が前に付きます(`filesystem__read_file` のように。組み込みの `read_file` と区別するため)。カードには、サーバーの名前を枠で、ツールの名前をその後ろに出します
- 仕組みは [mcp.md](mcp.md)

- 組み込みのツールは、aibow の中で動く MCP のサーバー(aibow-mcp と同じもの)を通して実行しています。見た目と使い方は変わりません。ログには `MCP 組み込み` の行で、送受信したメッセージが出ます

- 返事の中では、答えより前の部分(各回の思考とツールのカード)が「思考の過程(N秒)・ツール N回」の枠に畳まれます
- 1回の送信でツールを実行するのは 20 回まで、1回の実行は 10 秒まで(`run_command` は 120 秒まで)です。停止のアイコンで、ツールの実行中でも止められます(コマンドは、そこから起動された子プロセスもまとめて止めます)
- ツールのエラーや書式の崩れは「エラー: …」としてモデルに返し、モデル自身に直させます

### aibow のツールをほかのアプリから使う(aibow-mcp)

aibow のツール(時刻・計算・ファイルの読み書き・コマンド)を、MCP のサーバー `aibow-mcp` としてほかのアプリ(Claude Code など)から使えます。
画面のアプリとは別の exe です。リポジトリのフォルダで次のようにビルドします(`go install ./_cmd/aibow-mcp` なら Go の bin フォルダに入ります)。

```bash
go build -o aibow-mcp.exe ./_cmd/aibow-mcp
```

```
aibow-mcp [作業フォルダ]
```

- `aibow-mcp -version` でバージョンを表示します(アプリと同じバージョン。`go run` で動かしたものは `0.5.2+dev` のように次のバージョンに `+dev` が付きます)

- 作業フォルダを渡すと、その中のファイルを扱うツールとコマンドのツールも出します(フォルダの外には出られません)。渡さなければ時刻と計算だけです
- Claude Code なら `claude mcp add -s local aibow -- <aibow-mcp.exe の場所> <作業フォルダ>` で足せます(`-s local` はそのフォルダだけで使う登録。消すときは同じフォルダで `claude mcp remove -s local aibow`)。
  作業フォルダは絶対パスで書いてください(書き忘れると、時刻と計算の2つしか出ません)。ほかのアプリでも、`mcpServers` に `command` と `args` を書けば使えます
- Claude Code は自前のファイルの書き換えやコマンドのツールを持っていて、ふつうはそちらを使います。aibow のツールを試すときは
  `claude --disallowedTools "Write,Edit,Bash,PowerShell,NotebookEdit"` で起動すると、その起動の間だけ自前のツールを使わなくなります(Windows には Bash とは別に PowerShell のツールがあります)
- ツールの名前・説明・引数は aibow の組み込みと同じです
- **書き換えるツール(`write_file`・`edit_file`・`run_command`)は、実行する前にサーバーが差分を見せて確かめます**。aibow では今と同じ差分のカードが出ます(`settings.json` に書いたサーバーなので、その前に引数のカードも出ます。2回)。
  ほかのアプリでは、そのアプリの確認の画面に差分の文が出ます。確認(elicitation)に対応していないアプリからは、書き換えるツールは使えません(「書き換えません」のエラーが返ります)
- `run_command` は 120 秒まで動くので、aibow の `settings.json` では `"callTimeout": 130` のように延ばしてください(確認を待つ時間は数えません)
- ログは `%APPDATA%\aibow\logs\aibow-mcp_<日付>.log`(アプリと同じフォルダ。`AIBOW_LOG_DIR` で変えられます)と標準エラー出力に出ます。ツールの実行も残り、各行の終わりの `pid=…` で、どのサーバー(作業フォルダごとに1つ)の行か分かります
- 仕組みは [mcp.md](mcp.md) の「自作の MCP サーバー」

## 設定の変更

設定は2つの画面に分かれています。どちらも、チャットの代わりに会話の場所に開きます。
「会話に戻る」を押すか、一覧で会話を選ぶ・「+ 新規」を押すと閉じます。入力欄に打ちかけていた文は、戻ったときにそのまま残っています。

**会話の設定**: 会話を開いているとき、入力欄の下の右端(メーターの右)にある歯車のアイコンを押すと、その会話だけの設定の画面が開きます。

- システムプロンプト・会話が長くなったら(compact)・temperature・presence penalty・思考する: 会話ごとに保存され、次の送信から効きます
- **会話の上限**(モデルに渡す、これまでの会話のトークン数の上限)と**返事の上限**(1回の返事で生成するトークン数の上限): 「適用」で反映します。
  作業領域(コンテキスト)は、この2つの合計の大きさで確保します(パネルに計算した値が出ます)。
  作業領域は1つだけなので、大きさの違う会話に送信するときに作り直します(モデルは読み直しません。トーストで知らせます)。
  「適用」のときにもその大きさで作り直してみて、VRAM に入らなければ保存せずに理由を出します
- 「この設定を新しい会話の既定にする」で、この会話の設定をこれから作る会話の初期値にします
- ツール: この会話で使うグループ(組み込み / MCP のサーバー)を選べます(入力欄の上の「この会話のツール」と同じ)。ツールの行の「確認しない」で、この会話だけ確認せずに実行するにもできます。
  実行前の確認のカードの「この会話では今後聞かない」(実行して、この会話では確認しない)・「今後許可しない」(拒否して、この会話ではそのツールを使わない)でも変わり、ここに出ますグループの中のツールのチェックで、この会話で使うかを選べます。設定の画面の「ツール」で外したツール(「既定で使わない」と出ます)も、この会話では使うにできます。既定と違うものには「この会話で使う」「この会話で使わない」、作業フォルダを決めないと使えないものには「作業フォルダが要る」が付きます
- モデルに渡した文字列(この会話で最後に送信したときのもの)

**設定の画面**: 会話の一覧の右下にある歯車のアイコンで開きます(左下にはアプリの名前とバージョンが出ます)。

- **新しい会話の既定**(会話の設定と同じ項目。会話の上限・返事の上限も): 新しい会話は、この設定の写しから始まります。変えても今ある会話には効きません
- **アプリの設定**(会話によらず1つだけのもの): GPU に載せる層の数。変えるとモデルを読み込み直します

環境変数でも変えられます。bash では `名前=値 コマンド` と書くと、そのコマンドにだけ渡せます(`export 名前=値` ならそのターミナルの中でずっと有効)。

| 環境変数 | 既定値 | 内容 |
|---|---|---|
| `AIBOW_MODEL` | 最後に使ったモデル → 一覧の先頭 | 起動時に読み込むモデル。`ollama:qwen3.5:4b` のような Ollama の名前か、GGUF ファイルのパス |
| `AIBOW_MODELS_DIR` | `models` | GGUF ファイルを探すフォルダ(相対パスはカレントフォルダが基準) |
| `OLLAMA_MODELS` | `%USERPROFILE%\.ollama\models` | Ollama の保存フォルダ(Ollama 自身と同じ変数) |
| `AIBOW_LIB` | `lib` | llama.cpp の DLL があるフォルダ(相対パスはカレントフォルダが基準) |
| `AIBOW_DB` | `%APPDATA%\aibow\aibow.db` | 会話を保存する SQLite のファイル。フォルダが無ければ作る |
| `AIBOW_SETTINGS` | `%APPDATA%\aibow\settings.json` | 設定ファイル(手で書く設定。今は MCP のサーバーの `mcpServers` だけ)。無ければ MCP を使わない |
| `AIBOW_LOG_DIR` | `%APPDATA%\aibow\logs` | ログファイル(`aibow_<日付>.log`。日ごと)を書くフォルダ。exe は Notice 以上(起動した版・使ったモデル・変えた設定・注意・エラーなど)だけを書き、起動時に古いファイルを消して今日を含めて 10 日分を残す。異常終了したときは同じフォルダの `aibow_crash_<日時>.log` に内容が残る(次の起動で画面に知らせる)。MCP のサーバー `aibow-mcp` も同じフォルダの `aibow-mcp_<日付>.log` に書く(Info 以上・10 日分)。フォルダが無ければ作る。`wails3 build` で作った exe は既定でここに書く。`wails3 dev` はターミナルに出し、この変数を指定したときだけファイルにも書く |
| `AIBOW_TOOLS` | `%APPDATA%\aibow\tools.json` | ツールの扱いの、この PC の既定(設定の画面で変えたものを aibow が書く) |
| `AIBOW_WINDOW` | `%APPDATA%\aibow\window.json` | ウィンドウの位置・大きさ・最大化(閉じるときに aibow が書き、次の起動でそこに開く)。消すと初めの大きさ(720×820)で真ん中に開く |
| `AIBOW_HISTORY_TOKENS` | `8192` | 新しい会話の既定の会話の上限(モデルに渡す、これまでの会話のトークン数の上限)。超えたら会話ごとの compact の方式で収める |
| `AIBOW_MAX_TOKENS` | `8192` | 新しい会話の既定の返事の上限(1回の返事で生成するトークン数の上限。思考 + 答えの合計) |
| `AIBOW_GPU_LAYERS` | `999` | GPU に載せる層の数。VRAM に入りきらないモデルは減らす(残りは CPU で計算) |
| `AIBOW_PRESENCE_PENALTY` | `1.5` | すでに生成した言葉を選ばれにくくする強さ。思考の堂々巡りを抑える。`0` で無効 |
| `AIBOW_LLAMA_LOG` | なし | `1` にすると llama.cpp 自身の詳しいログ(どの層をどこに置いたか、読めない理由など)を出す。起動時に数千行出る |

作業領域(コンテキスト長)は「会話の上限 + 返事の上限」から計算します(会話ごと。起動したときは新しい会話の既定の大きさで確保します)。増やすと長い会話ができますが、VRAM を使います(Qwen3.5 4B で 1 トークンあたり約 32KB)。
以前の `AIBOW_CTX`(コンテキスト長)は使わなくなりました。設定されていると、起動時にログと画面のお知らせで伝えます。

`AIBOW_HISTORY_TOKENS` / `AIBOW_MAX_TOKENS` / `AIBOW_GPU_LAYERS` / `AIBOW_PRESENCE_PENALTY` は、DB にまだ値が無いときの初期値です。
画面で一度変えると、DB に保存した値が優先されます(`AIBOW_PRESENCE_PENALTY` は新しい会話の既定の初期値になります)。
以前の版で保存したコンテキスト長があれば、`会話の上限 = コンテキスト長 − 返事の上限`(最低 2048)として引き継ぎます。

```bash
AIBOW_MODEL=ollama:qwen3.5:4b wails3 dev
```

## 観察してほしいこと

- **MCP**(ステップ4で足したもの)
  `settings.json` に MCP サーバーを書いて、そのツールを使う頼みごとをしてみてください。ログ(`wails3 dev` で起動したとき)に、aibow とサーバーの
  JSON-RPC のやり取りがそのまま出ます(`→` が aibow から、`←` がサーバーから)。`tools/list` でツールの定義を受け取り、`tools/call` で実行しているだけで、
  その定義は組み込みのツールと同じ形(名前・説明・引数の JSON Schema)です。モデルから見ると、どちらも同じツールです。
  最初の `server/discover` が「Method not found」などで断られ、`initialize` で話し直していれば、そのサーバーは古い版の MCP で話しています。
  ツールの説明は毎回プロンプトに入るので、ツールの多いサーバー(Blender は 26 個)を足すと、メーターがそれだけで大きく進むことも分かります。
- **ミニコーディングエージェント**(ステップ3で足したもの)
  作業フォルダに小さなプロジェクトを選び、「テストを実行して、失敗していたら直して、もう一度確かめて」と頼んでみてください。
  モデルは `run_command` でテストを動かし、失敗の出力を読み、`read_file` で読んでから `edit_file` で直し、もう一度テストを動かします。
  コーディングエージェントの中身は、ツール呼び出しのループで「読む → 直す → 動かす → 結果を見て直す」を回しているだけだと分かります。
  確認のカードで「拒否」して理由を書くと、モデルが別のやり方を考えるのも見えます(理由が空だと、同じことをもう一度試しがちです)。
  ファイルの中身やコマンドの出力でメーターがどれくらい速く伸びるか、会話の設定の画面の「モデルに渡した文字列」に「# Environment」が入っていることも見てみてください。
- **ツール呼び出し**
  「今何時?」「1234 × 5678 は?」「今日の日付を調べて、大晦日まであと何日か計算して」と聞いてみてください。
  会話の設定の画面の「モデルに渡した文字列」を見ると、ツールの正体が分かります。システムプロンプトの先頭にツールの説明(JSON)があり、
  モデルは返事の中に `<tool_call><function=calculate>…` と書いて止まっただけで、計算したのは aibow です。
  結果が `<tool_response>` に包まれて足され、もう一度生成させています(これを繰り返すのが「エージェント」)。
  「思考する」をオフにするとツールを呼ばずにそれらしく答えてしまうことがあり、設定の画面の「ツール」で組み込みのツールを使わないにすると計算を間違えたり考え込んだりする違いも見えます。
- **長い会話(compact)**
  会話の上限を小さく(例えば 2048)して、同じ長い会話を truncate と summary で比べてみてください。
  truncate では外した発言の内容をモデルが完全に忘れます。summary では内容は残りますが、要約を作る分だけ待ち時間とトークンを使い、
  要約の質しだいで細部が落ちます。どちらも、モデルに渡す文字列の先頭が変わるので、KV キャッシュの再利用がほとんど効かなくなることも統計行で分かります。
  メーターの値が、compact の前後で下がるのも見えます。
- **会話を覚えているのはアプリ**
  モデルは何も覚えていません。aibow が発言を DB に保存し、送信のたびに並べ直して読ませています(会話の上限を超えたら compact で収めたもの)。
  会話を切り替えても、モデルを入れ替えても、続きを話せるのはそのためです。

- **会話の設定の画面の「モデルに渡した文字列」**
  会話が `<|im_start|>user …<|im_end|>` という書式の1本の文字列になっていて、最後が `<|im_start|>assistant` で終わっています。
  モデルはこの「続き」を書いているだけです。送信のたびに会話全部が入っていることも分かります
  (会話の上限を超えて compact したあとは、要約が system の後ろに入り、古い発言が外れた形になります)。
  過去の返事の思考は保存されていて画面で開けますが、この文字列には入っていません(Qwen3.5 の公式テンプレートと同じ)。
  ただし、ツールを呼んでいる途中の返事の思考だけは入ります(何のために呼んだかを覚えたまま続きを書かせるため)。
- **「思考する」のオン/オフ**
  オフにすると、文字列の最後に空の `<think></think>` が入ります。モデルは「考え終わった」と思い込んで、すぐ答え始めます。
- **統計行**(回答の最後の「詳細」を押すと開く。ふだんは畳んである)
  `モデル名 ・ 初回応答 ○s ・ プロンプト ○ tok(再利用 ○)○s ・ 生成 ○ tok ・ ○ tok/s` の形式で出ます。
  プロンプトを読む速さと、1トークンずつ生成する速さが大きく違うことが分かります。
  ツールを使った返事では、全部の回の合計になり、「3回生成 ・ ツール 2回」のように生成とツールの回数が付きます。
  「再利用」は KV キャッシュ(前回読み終えた部分の計算結果)を使い回せたトークン数です。
  Qwen3.5 は一部の層が途中まで巻き戻せない仕組みのため、新しい質問ではたいてい 0 になります。
  ツールの結果を渡して続きを書かせるときは、前回の続きに足すだけなので、ほぼ全部を再利用できます。
- **モデルの切り替え**
  読み込み時間、生成速度、答えの質がモデルの大きさでどう変わるか。設定の画面で GPU に載せる層の数を減らすと、どれくらい遅くなるか。
  会話の上限・返事の上限を変えたときは、モデルの読み込み時間が変わらない(重みは読み直さず、作業領域だけ作り直している)ことも分かります。
- **ログ**(`wails3 dev` で起動したときはターミナル、exe は `%APPDATA%\aibow\logs\aibow_<日付>.log`)
  起動時の計算装置とモデル一覧、1回ごとのトークン数・速度・終了理由、compact したこと(方式・前後のトークン数・秒数)、ツールの実行(名前・引数・結果の長さ・秒数)、MCP サーバーの起動・やり取り・エラー出力が出ます。
